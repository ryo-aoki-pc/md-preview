# md-preview の設計

`mdpreview` の設計の判断と理由。導入は [導入と更新](../install.md)、操作は [使い方](../usage.md)、開発で守ることは [AGENTS.md](../../AGENTS.md) にある。

## 描画の流れ

描画は、Markdown を HTML にする段、消毒とフィルターの段、ブラウザに表示する段に分ける。プレビューと HTML への書き出しは、同じ [internal/pipeline](../../internal/pipeline/pipeline.go) の `Renderer.Render` を通す。表示先によって消毒や構文の扱いが変わることを避けるため。

1. CR と front matter を処理し、`::include{file=…}` を展開する
1. GitLab の gem `gitlab-glfm-markdown` のコードを WebAssembly にした [描画エンジン](../../engine/engine.go) で HTML にする
1. HTML を木として読み、コードの言語・JSON の表など、GitLab で消毒より前に置かれるフィルターを通す
1. [消毒の規則](../../internal/sanitize/sanitize.go)で、許可していない要素・属性・リンクを除く
1. 数式・図・目次・脚注などを処理し、最後にコードを配色する
1. HTML と、見出し・取り込みの記録・GitLab との違いの知らせを返す

HTML の木は `golang.org/x/net/html` で扱い、[internal/htmltree](../../internal/htmltree/tree.go) が取り消しと深さを検査する。入れ子は 512 段までとし、超えると `入れ子が深すぎるため、描画できません。` を返す。消毒前後の処理は [internal/filters](../../internal/filters/)、最後の配色は [internal/highlight](../../internal/highlight/highlight.go) が受け持つ。Chroma の字句を GitLab と同じ短いクラスに対応づけ、包みと行の span も GitLab と同じ形にする。

エンジンの出力だけでは消毒が済んでいない。HTML を文字列の置き換えで直さず、木に対して許可リストを適用する。フィルターの順序も GitLab に合わせ、消毒の後ろで足す属性をそれぞれ検査する。コードの配色が作る要素と属性は、その段で値を制限する。

描画の関数は、include の読み込みとメディアの存在確認を、呼ぶ側から渡す関数に任せる。Markdown の処理とファイルを読む権限を分けるため。[session.FileContext](../../internal/session/files.go) は、同じパス検査を通したルート内のファイルだけを、この関数へ渡す。

## GitLab に合わせる範囲と確かめ方

構文解析と整形は、似た解析器で作り直す代わりに GitLab の gem のコードを使う。`glfm.rs`・`formatter.rs` の写しは変更せず、WebAssembly から呼ぶ入口を付ける。`.wasm` は実行ファイルに埋め込み、`engine` パッケージが wazero で動かす。gem に渡すオプションの元になる GitLab のソースも保存し、試験で値を比べる。固定した版とハッシュは [engine.lock.json](../../engine/engine.lock.json) にある。

その後ろの Ruby のフィルターは Go で実装する。GitLab の利用者・プロジェクト・権限や外部の図サービスが必要な処理は、[internal/pipeline](../../internal/pipeline/pipeline.go) に省く理由を記す。対応する処理が無い場所を、見た目だけで解決したことにはしない。

PlantUML は外部の図サービスを使わず、PATH の絶対パスの項目にある手元の `plantuml` を使う。[フィルター](../../internal/filters/pre.go)は GitLab と同じく消毒の前にコードブロックを img に変え、原文と sha256 の ID を集める。コマンドが無い場合と `--no-plantuml`、原文が 256 KiB を超える図は、原文のまま残す。

[描画する部品](../../internal/plantuml/plantuml.go)は原文を標準入力にだけ渡し、`SANDBOX` と Java の headless を指定して一時フォルダーで起こす。`SANDBOX` は、環境変数 `PLANTUML_SECURITY_PROFILE` と、`JAVA_TOOL_OPTIONS` の最後に足す同じ名前の Java のプロパティの両方で指定する（PlantUML はプロパティを先に読むので、利用者の `JAVA_TOOL_OPTIONS` に別の値があっても `SANDBOX` になる）。原文は、PlantUML のサーバー（GitLab が図を送る先）と同じく、先頭が `@start` でなければ `@startuml` と `@enduml` で包む。構文に誤りのある図は、PlantUML が誤りを描いた SVG を返すので、GitLab と同じくその図を見せる。SVG でない出力（原文に `@@@format png` の行があるときなど）は失敗として扱う。描画は直列で、同じ ID の待ちは共有し、成功した SVG だけをメモリーに覚える。時間切れ・中止・終了では子のプロセスを木ごと止める。プレビューは token・Host・Sec-Fetch-Site を検査した経路から SVG を sandbox 付きで返し、ページでは img として表示する。SVG を DOM に入れず、失敗時は原文のコードブロックへ戻す。

[見本との比較](../../internal/pipeline/fixtures_test.go)は、合成の Markdown を GitLab が描いた HTML と、手元の最終 HTML を木にして比べる。属性の順、遅延画像、脚注の乱数、絵文字の囲み、コードの配色の字句は、試験で列挙した差だけを正規化する。それ以外の既知の差は、[known_differences.json](../../internal/pipeline/testdata/known_differences.json) に、文書・木の場所・理由・両側の値を固定する。参照のリンクを一律に文字へ戻すような、違いを隠す正規化はしない。

見本を作る [開発用スクリプト](../../tools/make-fixtures.mjs)と、保存済みの見本を読む試験を分けている。試験のたびに GitLab に接続せず、同じ入力と出力で比べるため。合わせた範囲と GitLab との差は [README](../../README.md#消毒とフィルター) にある。

## サーバーとファイルを読む範囲

プレビューは [HTTP サーバー](../../internal/server/server.go)を手元に起こす。127.0.0.1 だけで待ち受け、URL に毎回 16 バイトの乱数を 32 桁の 16 進で入れる。ループバックへの待ち受けだけに頼らず、`Host` と `Sec-Fetch-Site` も検査し、CORS の許可を返さない。別のサイトから手元の文書へアクセスさせないための境界にする。

サーバーは接続を自分で受けて `net/http.ReadRequest` で読む。パスの自動整理・接続の再利用・Expect の自動応答を通さず、token は定数時間で比べる。`Host` が複数ある要求と、行頭の空白で折り返したヘッダーは 400 で拒む。

ファイルを開く入口は [internal/resolve](../../internal/resolve/resolve.go) の `Resolve` に集める。URL のパスを戻し、`..`・バックスラッシュ・`.git`、Windows のドライブやデバイス名として扱われる書き方を拒む。さらに実パスを求めて、ルートの外へ出るリンクも拒む。文字列の上でルートの下に見えるだけでは、配信を認めない。

数式と図のライブラリも、同じサーバーから配る。配信対象は [page/lib/lock.json](../../page/lib/lock.json) にあるファイルに限り、`node_modules` をそのまま公開しない。ページに入れる [copy-code.js](../../page/copy-code.js) などのスクリプトも同じサーバーから配る。ページの CSP は `script-src 'self'` とし、文書が任意のスクリプトを読み込む入口を作らない。

## リンク切れの点検

[internal/links](../../internal/links/links.go) は、消毒とフィルターを通した本文の `a[href]` を、外へ通信せずに点検する。文書の中の `#id` は、描画の見出しと本文の `id`・`name` に照らし、`user-content-` の付いた ID も認める。ルート内の相対ファイルは存在を調べ、別の Markdown に `#id` があれば、その文書を描いて見出しの ID に照らす。Markdown 以外は、フラグメントがあってもファイルの存在だけを調べる。同じ文書へのファイル名つきのリンクには、未保存の内容も含む今の描画の ID を使う。

外部 URL（`//` とスキームのある URL）、見出しのアンカー、目次、脚注の参照と戻り、画像そのものを開くリンク、図のリンクは点検の対象にしない。対象外の URL へ要求を送らず、「点検していないリンク」にも数えない。ファイルの検査には `internal/resolve.Resolve` と `session.FileContext` を使い、ルートの外や読み取りを許可しない場所は「点検していないリンク」にする。存在しないファイルと ID は「リンク切れ」にする。

別の文書の描画は実パスごとに 1 回だけ、32 件まで・各 10 MiB までに限り、その文書のリンクをたどって再帰しない。点検全体の期限は 10 秒にし、文書数・大きさ・期限の上限を超えた分や、読み取れない・描画できない文書は未点検にする。原文の行は公開の位置と行対応から求め、include の中は取り込みの指定行へ戻す。位置を持たないリンクは行を `null` にする。

[サーバーの口](../../internal/server/links.go)は `GET _/links?render=<描画番号>` と、省略できる `&doc=<ルートからの相対パス>`。token の下に置き、Host・Sec-Fetch-Site と `doc` のパスを検査する。`render` は 1 個の正の `uint64` の十進表記だけを受け、重複した `doc` も断る。成功はキャッシュしない JSON の `{render, broken: [{line, href, reason}], unchecked: [{line, href, reason}]}` で、該当がない配列は `[]` にする。不正な引数は 400 の `invalid`、点検前後で描画が変わった場合は 409 の `stale`、点検の失敗は 503 の `unavailable` にする。`doc` のルートがなければ 404、存在しない・許可しないパスはパス検査の状態を返す。点検は文書の購読・編集・監視の状態を変えない。

[ページ](../../page/preview.js)は `gp:render` の約 400 ms 後に点検する。続く描画では待機と前の要求を取り消し、最後の描画にまとめる。一覧と誤りの表示では点検しない。「再点検」は自動点検の待機も取り消してすぐ点検し、処理中は「点検中…」にして押せなくする。古い要求・描画番号の違う応答と 409 は表示に使わない。結果は既存の知らせと合わせ、「GitLab との違い」の「リンク切れ」「点検していないリンク」に件数と理由を出す。文字は `textContent` で入れ、行がある項目から本文へ移れる。0 件でも「再点検」は残す。失敗は「リンクを点検できませんでした。再点検してください。」と知らせる。編集・コメントモードでも読み取りだけの点検を使う。欄の行き先は、描画の `href` の `%` の符号化を `decodeURI` で戻して出す（日本語の見出しの ID も読める形になる。戻せないときはそのまま）。

リンク点検の画面の操作は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証。

## 文書の状態と取り込みの見張り

描画は [internal/session](../../internal/session/session.go) が管理し、文書の更新をまとめる。プレビューの描画は 15 秒、HTML への書き出しは 60 秒の `context` の期限で止める。描画の各段と WebAssembly の実行に取り消しを伝え、時間切れの後も描画を受け付ける。

編集中の文書と、相対リンクや一覧から開いたファイル文書は別の状態を持つ。描画の通知は文書ごとに送り、エディタのスクロールは編集中の文書のタブだけへ送る。別の文書を読んでいるタブを、編集中の文書の位置へ動かさないため。

- ファイル文書の監視は 32 件まで。最後のタブが離れて 5 秒後に監視と結果を捨て、読まれていない文書を持ち続けない
- include の展開は [internal/include](../../internal/include/include.go) で行う。32 回まで・再帰しない・展開後 16 MiB までに制限し、取り込み先からさらに読み込みを広げない
- 取り込み先の監視も、ルートの内側かを検査して文書ごとに 32 個までにする。無いファイルは安全な親の下で出現を待ち、作成されたときにも描き直す
- 編集中の文書を描き直すときは、最後に受けた本文を使う。include が変わったときに、未保存の内容をディスク上の古い本文に戻さない

見張りのパスの検査は [internal/watch の IncludePath](../../internal/watch/watch.go)、置き換え保存や削除・作成への追従は [watch.go](../../internal/watch/watch.go) に分けている。100 ミリ秒ごとに、更新時刻・大きさ・ファイルの同一性を確かめる。書かれてから 2 秒の内に見た 32 MiB までのファイルは、中身のハッシュを覚え、更新時刻の刻みが過ぎてから 1 回だけ確かめ直す。同じ更新時刻・同じ大きさでの書き換えを拾うため。

文書・include・配信するファイルの読み取りには [internal/fileopen](../../internal/fileopen/open_windows.go) を使う。Windows では、読んでいる間も名前の変更と削除を許して開く。置き換え保存を読み取り中のハンドルで妨げないため。

## 画面での編集

`--edit` を指定した単体ファイルとフォルダーのプレビューと、`hello` で `edit: 1` を知らせた Neovim の橋渡しは、[internal/edit](../../internal/edit/service.go) と [page/edit.js](../../page/edit.js) を接続する。「編集」でパイプの表と HTML の表、段落・見出し・リスト・説明リスト・引用・コードブロック・数式のブロック・図（mermaid・PlantUML）・水平線・注記・脚注の定義と、本文のいちばん外側の生の HTML のブロックの原文、表のセルと脚注の定義の中を含むタスクのチェックボックスを編集し、ブロックや最上位の表の前後、文書の先頭・末尾、空の文書へ追加できる。最上位のパイプの表全体の原文の編集と、同じ節の中のブロックの上下の移動も扱う。指定しない場合は編集の経路とページ設定を追加せず、編集のスクリプトも操作や層を追加しない。

`GET _/edit/tables?doc=&render=` は、描画の番号、文書と表の編集可否、セル、取り消し・やり直しの可否、見出しの一覧 `headings`、表ごとのブロックの移動情報 `blockMoves`、描画のもとの本文の `version` を返す。表の `start` は、描画にある信用できる `data-sourcepos` の公開の開始行。位置属性の無い生の HTML の表は、原文と対応づけたモデルの開始行を公開の行にする。どちらも確かめられない場合や、単独の CR で行の対応がずれる場合は 0 にする。応答の `insertStart` は、文書の先頭（front matter の後ろ）へ追加したときに下書きの位置をずらす開始行。`empty` は、サーバーが原文から決める、空白と空行だけの文書かどうかの真偽で、BOM は判定から除く。参照の定義やコメントだけで画面に本文が出ない文書も空とは扱わず、ページの DOM から判定しない。表ごとの `anchor` は前後への追加先となる原文の実際の範囲、`anchorReason` は追加できない理由を表し、追加できない表は `anchor` を空にする。

表情報の `convertLocked` は `{html: "<理由>", pipe: "<理由>"}`、`deleteLocked` は削除できない理由で、空文字なら事前の検査を通ったことを示す。同じ種類への変換は `convertLocked` に「すでに…」を入れて画面では無効にするが、公開関数の同じ種類への変換は無変更になる。`cellsLocked` はセルの構造を変えられない理由、`sections` は HTML の区画ごとの `{tag, explicit, first_row, rows}`（タグ名・明示した区画か・開始行・行数）、`sortLocked` は選んだ行ごとの並べ替えを断る理由の配列。行と列は 0 起点。セルの `mergeLocked` は、結合で覆って消せない内容（リンクの参照の定義・入れ子の表）の理由を表す。範囲に応じた穴・既存の結合の境界・区画をまたぐ検査は、ページと確定時の公開関数でも行う。

`deleteLocked` は文書を読み直さず、同じ行の項目の印やほかの文字、入れ子の表などの軽い検査だけを行う。削除するたびに全文を読み直して前後の解釈を比べる検査を、すべての表の情報取得時にも行うと、表の数に対して 2 乗の時間が掛かるため。最終的な削除の可否は `DeleteTable` を呼ぶときに決めるので、メニューを押した時点で理由を知らせて断ることがある。

`GET _/edit/source?doc=&render=&tag=&range=` は、要素名 `tag` と公開の範囲 `range`（HTML の `data-sourcepos`）で表以外のブロックを引き、原文 `text`・描画番号 `render`・実際の編集範囲 `range`・種類 `kind`・外側のブロックの列 `outer`・追加先 `anchor`・移動情報 `move`・リストの段の情報 `listIndent` を返す。`anchor` は取得対象から外へたどった、外側の対象を持たないブロックの `{tag, range, actual}` で、`range` は公開の範囲、`actual` は実際の範囲。そのブロックが断られている場合は `null` にする。脚注の定義も、画面では文書の最後に並び、原文の位置と対応しないため、`anchor` を `null` にする。範囲は 1 起点で終端を含む UTF-8 のバイト列の位置で、終了列 0 はその行の手前までを表す。CRLF の CR は列に含めない。

生の HTML の原文は `GET _/edit/source?render=&tag=html&prevTag=&prevRange=&nextTag=&nextRange=` で取得する。`prevTag`・`prevRange` と `nextTag`・`nextRange` は、それぞれ連なりの前後の境の組で、文書の先頭・末尾では組ごと省く。`range` は付けず、ファイル文書は `doc` を加える。[internal/server/edit.go](../../internal/server/edit.go) の `htmlBoundaries` が組を検査し、`HTMLBoundary` を `HTMLText` へ渡す。応答は `{text, render, range, kind: "html", outer: [], anchor, move}` で、`range` は検証した実際の範囲、`anchor` は連なり自身の `{tag: "html", range, actual}` にする。内側の段落などの取得では、検証できた連なりの `{tag: "html", range, kind: "html"}` を `htmlOuter` が `outer` の最後に加える。内側の対象の `anchor` は、位置を持つブロックから求めた追加先のままにする。

[internal/edit/blocks.go](../../internal/edit/blocks.go) は、描画番号ごとに HTML からブロックとチェックボックスの編集対象の一覧を作る。ブロックには公開の範囲と実際の範囲、種類、外側の関係、編集を断る理由を持つ。取得は `target`、確定は `writable` で一覧と照合し、`POST _/edit {render, range, text}` は、一覧で編集できる実際の範囲か、`htmlWritable` で検証した生の HTML の連なりの範囲と完全に一致するときだけ受ける。チェックボックスも一覧にある位置だけを受ける。Neovim のバッファへの反映も同じ検査を通る。

チェックボックスは、`task-list-item-checkbox` を持ち、`data-checkbox-sourcepos` の形が正しい input から集める。表のセル（HTML の表と、パイプの表の `| [ ] |`）と脚注の定義の中も含めるが、JSON からできた表と、入れ子の表の内側・外側は一覧に入れない。表と脚注の中では位置の検証を通らないものも登録せず、同じ位置が複数あれば `ambiguous` として断る。表の中の位置には文書順の表番号も記録する。確定時は、一覧と位置の検査に加え、その番号の表が対応と格子の検査を通って編集可能であることを確かめ、対応できない表・include で取り込んだ表などは 422 の `excluded` で断る。原文の位置が `[ ]`・`[x]`・`[X]` の中の 1 バイトであることも確かめ、違えば 422 の `range` にする。

[internal/edit/html.go](../../internal/edit/html.go) は、サーバーの HTML の最上位で、信用できる位置を持たない節点の連なりを `htmlRuns` で集める。信用できる位置を持つ最上位の要素を前後の境とし、エンジンの包み `div.markdown-code-block` は直下の `pre` の位置を使う。脚注の節 `section[data-footnotes]` は飛ばす。要素を含まない連なりと、目次の `ul.section-nav` を含む連なりは対象にしない。`<details>` 全体や位置のない `<p>`・`<br>`・`<img>`、段落などを挟まずに続く HTML と空行なしで続く文字をまとめて扱う。リスト・引用・注記などの内側の生の HTML は、最上位の連なりとしては受けない。HTML の表はセルの編集で扱う。

`headingMapping` は描画の h1〜h6 を文書順に集め、ブロックの一覧と信用できる位置で対応づける。操作できるのは、最上位の Markdown の見出しだけ。引用・リスト・注記・表・脚注・HTML のブロックの中、HTML で書いた見出し、取り込み・front matter に掛かる見出し、重複や信用できない位置を持つ対象は、理由を付けて断る。`headings` の各項目は `index`・`tag`・`range`・`id`・`level`・`text`・`reason`・`section`・`ops` を持ち、`section` は末尾の空行を除く行数と見出し数、`ops` は各操作の無効理由を返す。HTML などの位置を使えない見出しは `tag` と `range` を空にする。

節は、その見出しから次の同じか上のレベルの最上位の見出しの手前まで。見出し欄の順で見つけた境と最上位の境が違う場合、行対応が連続しない場合、取り込みの指定や取り込んだ行を含む場合は節ごとの操作を断る。節ごとのレベル変更は内側にも操作できない見出しがあれば断り、h1〜h6 の外へ変える操作も断る。移動は同じ親の中の前後の同じレベルの節とだけ入れ替える。レベルが異なる境や、範囲を確かめられない隣の節を越えて移さない。

レベル変更は ATX の `#` と、同じ個数で書かれた閉じの `#` を変え、字下げと改行を保つ。setext は内容を 1 行にまとめた ATX にし、末尾の `#` が閉じの印にならないようエスケープする。削除は前後の空行を調整し、節の移動は行の由来を保って入れ替える。どれも [internal/edit/heading_verify.go](../../internal/edit/heading_verify.go) の `verifyHeadingEdit` が `Trial` で試しに描き、期待する最上位の並び・見出しの要素名・削除範囲と、残る要素の形を比べてから書く。

`planListIndent` は、下げる場合は直前の兄弟、上げる場合は親の項目を求める。字下げの桁は描画の位置をそのまま使わず、一覧の実際の開始列から原文の印と空白を読む。下げる幅は直前の兄弟の本文の開始桁と対象の印の桁の差、上げる幅は対象と親の印の桁の差。箇条書きの印や番号の文字に、その後ろの空白 1〜4 個を加えて本文の桁を求め、空白が 5 個以上なら CommonMark の規則で 1 個として数える。印の後ろが行末の場合も 1 個として数える。`rewrite` は対象の子・続きの行も含めた範囲の空白を同じ幅だけ増減し、空行と、対象を包む引用の印および直後の空白を残す。本文の中の引用は本文と一緒にずらし、印と番号の文字は変えない。

期待する木は元の描画の対象の項目だけを移して作る。下げる場合は直前の兄弟の末尾にある同じ種類の子のリストへ追加し、無ければ `ul` か `ol` を作る。新しい `ol` の `start` は対象の原文の番号から求める。上げる場合は親のすぐ後ろへ入れ、空になった子のリストを除く。所属が変わるリストの `task-list` のクラスは直下のタスクの有無から更新する。`Trial` で書き換えた全文を描き、`listIndentSignature` で期待の木と全体を比べる。

比較では `data-sourcepos`・`data-checkbox-sourcepos`、リストの入れ子の境に描画器が足す改行と空白だけの節点、`li` 直下の `p` の包みを除く。ゆるい・きついリストのどちらへ所属するかで変わる段落の包みは比べず、その中身・ほかの段落・本文の空白・残る属性は保ち、属性を名前順にそろえる。期待した所属・項目の順・本文・リストの種類・前後の解釈が異なる場合は 422 の `render` と「所属が変わるか、本文・リストの種類・前後の解釈が変わるので、段を変えられません。」にして書かない。子のリストを始められない `2.` などが直前の項目の段落の続きになる、親の続きの段落を巻き込む、箇条書きと番号付きの種類が変わる場合などをここで断る。試しの描画に失敗した場合は「段を変えた文書を描画できません。」を返す。

事前の検査では、リストの先頭を下げる、いちばん外側を上げる、同じ段の後ろに兄弟が残る項目を上げる操作を断る。後ろに兄弟がある場合は「後ろの項目の所属が変わるので、後ろの項目から上げてください。」と返す。タブの字下げ、引用の印の後ろに空白が無い行、続きの引用の印を確かめられない行、同じ幅だけ空白を取り除けない続きの行、脚注の定義と定義を含む項目、対象と相手の間も含む取り込みの指定・取り込んだ行・front matter も 422 の `excluded` などで断る。範囲や対応を確かめられない対象は共通のブロックの誤りを返す。

書き換えは行の由来を保つ `headingRewrite` にまとめ、LF・CRLF・BOM・末尾の改行の有無を保つ。書き込みと履歴は共通の経路で 1 手、Neovim はバッファの 1 個の行の置き換えにする。`change.keep` は字下げを変えた行も対応づけ、版・行の対応と内容の照合でコメントを追従させる。

表の操作は `POST _/edit {render, table, op}` で受け、`table` は画面の文書順の 0 起点の表番号。追加した `op` の形は次のとおり。知らない項目や余分な項目、誤った型・範囲は断る。

| 操作 | `op` |
| --- | --- |
| 表全体の原文の編集 | `{type: "setTableSource", source}`。`source` は文字列 |
| 種類の変換 | `{type: "convert", to: "html"}`。`to` は `html` か `pipe` |
| 表の削除 | `{type: "deleteTable"}` |
| HTML のセルの結合 | `{type: "mergeCells", row, col, rows, cols}` |
| パイプの表の変換と結合 | `{type: "mergeCellsAsHTML", row, col, rows, cols}` |
| 結合の解除 | `{type: "unmergeCells", row, col}`。結合の左上を指定する |
| 揃えの変更 | `{type: "setAlign", row, col, rows, cols, align}`。`align` は `left`・`center`・`right`・空文字（既定） |
| 見出しセルの変更 | `{type: "setHeader", row, col, rows, cols, header}`。`header` は真偽 |
| 列の値で並べ替え | `{type: "sortRows", row, col, order: "asc"}`。`order` は `asc` か `desc` |

`row`・`col` は 0 起点、`rows`・`cols` は正の整数で各 1000 以下、範囲の格子は 10000 セル以下。パイプの表の `setAlign` は指定範囲の列全体に働く。`setHeader` は HTML の表だけで、内容・揃え・結合を保って開始・終了タグの `th` / `td` を変える。

パイプの表全体の原文は、`GET _/edit/source?doc=&render=&tag=table&range=<anchor>` で取得し、[internal/edit/table_source.go](../../internal/edit/table_source.go) の `tableText` が `{text, render, range, kind: "table", table}` を返す。`range` は表情報の `anchor` と照合し、対応と格子を確かめた最上位のパイプの表だけを受ける。HTML の表・引用やリストの中の表・取り込み・front matter・JSON からできた表・入れ子の表などは断る。行の改行を LF にした原文を入力欄に出し、表番号を付けた `setTableSource` で確定する。確定・取り消し・下書きはブロックの原文の入力欄と共有する。

`setTableSource` は、対象と `anchor` を検査して原文のバイト範囲を求める → 入力の改行をそろえ、前後の空行を除く → 置き換え先の LF・CRLF に合わせ、文書の 16 MiB の上限を検査する → 入力単独を `tableedit.Parse` し、全行が対象外でない最上位のパイプの表 1 個に収まることを確かめる → 全文へ差し込んで読み直し、同じ開始行で入力の最終行までが表になることを確かめる → 本文が変わる場合だけ `Trial` で試しに描く、の順に行う。空・段落を含む・表でなくなる・2 つに割れる・前後を巻き込む入力は 422 の `tableSource` と「表全体の原文は、前後の段落を含まないパイプの表 1 個にしてください。」で断る。空行なしで表に続く文は GFM では表の行になるため、取得と置き換えにも含む。

`verifyTableSource` は表の数、対象が最上位であること、変更後の原文と描画の格子を確かめる。対象の表だけを同じ印に替え、`tableSourceSignature` で位置属性と最上位の空白だけの文字節点を除いた全体を、ほかの属性も含めて比べる。行と列の数・中身は変えられるが、表の外の脚注などの描画も変わる場合は 422 の `verify` にして書かない。BOM・改行と表の外の原文を保ち、履歴は 1 手、Neovim はバッファの 1 個の行の置き換えにする。

変換は `tableedit.Document.ConvertTable` で生成・読み直しを行い、さらに [internal/edit/convert.go](../../internal/edit/convert.go) の `verifyConversion` が 1 回の試しの描画で、表の数、変換後の原文のモデルと描画の格子、変換前後の左上のセルの文字、チェックボックスの数を比べる。`[ ]`・`[x]`・`[X]`・`[~]` だけのセルは、種類でチェックボックスの描画が変わるので生成前に断る。内容の続く先頭の `<br>`、HTML のブロック、結合のある HTML の表からパイプの表への変換、リンクの参照の定義なども、公開関数で理由を出して断る。

削除は `tableedit.Document.DeleteTable` が、表と前後の空行を除き、前後に内容があれば空行 1 行を残す。引用の途中では `>` だけの行を先に試し、解釈が変わる場合は空の行でも確かめる。表と同じ行に項目の印やほかの文字がある形と入れ子の表は断る。`mdtable/internal/verify` の `Removal` が文書を読み直し、残りの表・葉のブロックの種類・祖先・位置・リストの形などを比べ、リストがつながるなどの変化があれば書き込まない。

結合は左上の原文・タグ・揃えを残して `rowspan` / `colspan` を変え、覆われるセルの文字を捨てる。行を全部覆って空になった `tr` は残す。1 セルだけ、穴を含む、既存の結合の途中を切る、`thead`・`tbody`・`tfoot` の区画やパイプの表の見出し行と本文をまたぐ範囲、覆われるセルにリンクの参照の定義か入れ子の表がある形は断る。解除は左上と同じタグ・有効な揃えの空のセルを覆っていた位置へ入れ、捨てた文字は復元しない。下の行の左に穴がある場合は空のセルが穴へ入るので断る。

`mergeCellsAsHTML` は変換と結合をメモリー上で済ませ、最終の本文だけを書いて 1 手の履歴にする。試しの描画では変換後・結合後の格子と左上の文字を確かめるが、結合で捨てるセルのチェックボックスの減少は許す。単なる変換のチェックボックス数の検査とは分ける。

HTML の揃えは既存の `align` と `style` の `text-align` を変更し、両方あれば両方を変える。無ければ表内の書き方に合わせ、既定へ戻すと揃えの指定だけを除く。ほかの属性・style の宣言は保つ。`style` の生成は `text-align: right` のようにコロンの後に空白を入れる。gitlab.com は `text-align:right;` のような空白のない値を消すためで、`test/fixtures/table-edit.md` と `table-edit.gitlab.html` がその違いと、変換・結合・解除・揃え・見出しセル・タスクの形を比べる見本になる。パイプの表では区切り行の `-` の数と空白を保ち、揃えの `:` だけを変える。

並べ替えはパイプの表の見出しを除く本文、HTML の表では選んだ行の区画だけが対象で、区画の先頭に続く `th` だけの行を除く。`thead`、並べ替える範囲に掛かる `rowspan > 1`、対象が 2 行未満の区画などは `sortLocked` に理由を出す。表の検索で行を隠している間は、見えていない行も動くので、ページがほかの列の操作と同じ理由で断る。セル用 Markdown の値で比べ、選んだ列を横に覆う結合ではその左上の値、セルのない位置は空を使う。行の原文・属性・改行を保って入れ替える。ファイルの末尾にある改行の無い行が途中へ移るときは、末尾へ来た行の改行をその行へ渡し、末尾は改行なしのままにする。

比べ方は Excel に近づけ、昇順は数値 → 文字 → 空、降順は文字 → 数値 → 空とし、空白だけの値も常に最後にする。数値は全角の英数をそろえ、符号・小数・指数・3 桁区切りの `,`・末尾の `%` を読み、`10%` と `0.1` は同じ値になる。十進の桁と小数点の位置で比較し、浮動小数点の丸めと巨大な指数の桁の展開を避ける。文字は英字の大小・英数とカタカナの幅をそろえ、連続する数字を数値の大きさで比べる自然な順（`項目2 < 項目10`）にする。そろえた文字が同じなら元の文字を比べ、それも等しい値の行は安定な並べ替えで元の順を保つ。

この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「表の変換・削除・結合・揃え・見出しセル・並べ替えと、版 0.16.0 の配布の検証（2026-11-13）」にある。

追加は `POST _/edit {render, insert: {anchor: "<実際の範囲>", side: "before" | "after"}, text}` で、[internal/edit/insert.go](../../internal/edit/insert.go) の `insertBlock` が扱う。`anchor` は、一覧にある、断られていない、外側の対象を持たないブロックの実際の範囲、表情報の `anchor`、`htmlWritable` で検証した生の HTML の連なりの範囲のどれかと一致するときだけ受け、対応しなければ 422 の `target` にする。連なりの検証に失敗した場合は `boundary` にする。脚注の定義の範囲を `anchor` にした場合も 422 の `target` にする。対象の最初の行で、対象より前に字下げ以外の文字があれば 422 の `boundary` にする。`text` の前後の空行を除き、空なら 422 の `invalid` と「追加する文を入力してください。」を返す。改行は追加先の LF・CRLF に合わせ、前後に空行を 1 行ずつ置く。既に空行があれば足さず、文書の先頭・末尾の側にも足さない。

文書への追加は `POST _/edit {render, insert: {document: "start" | "end"}, text}` で受ける。`insert` の `document` と `anchor`・`side` は混ぜて受けない。`documentInsertionPoint` はサーバーが持つ原文と行対応から追加点を決め、先頭は BOM と front matter の後ろ、末尾は原文の終わりにする。末尾の行が include なら展開全体の後ろとして比較する。空白と空行だけの文書は、追加する文の前後の空行を除き、BOM があれば残して文書全体を置き換える。

表の `anchor` は、`tableAnchor` が、編集可能で対応と格子を確かめた表だけに付ける。描画の最上位にあり、原文の解析でも入れ子でない表に限り、原文の連続した行を行対応で検査する。リスト・引用などの中や、入れ子の表は受けない。HTML の表では最初と最後の行に表以外の文字がなく、原文を HTML の字句でたどって、表 1 個と前後の空白だけであることも確かめる。ページが渡した範囲を、そのまま追加点に使わない。

差し込んだ本文を `Trial` で試しに描き、`insertionPreserves` で、元からあった要素の「要素名・位置・祖先の要素名の並び」が、追加した行数だけ行がずれたほかは変わらないことを確かめる。追加した行に収まる新しい要素は比べから除く。違えば 422 の `insert` と「追加した文が前後のブロックに取り込まれます。」を返して書き込まない。閉じていないコードの囲み・`>>>`・`<details>` が後ろを巻き込む場合や、リストの後ろへの項目の追加が元のリストに取り込まれる場合も断る。

文書の末尾への追加では、既存の要素の比較だけでは、追加した文が閉じない構文に取り込まれて消える場合を見つけられない。`verifyInsertion` は、追加する文を原文と重ならない乱数の印の段落へ替えた別の試しの描画も行い、印だけを含む最上位の p があることを確かめる。閉じていない `<!--`・`<details>`・コードの囲みなどで印が最上位の段落にならない場合は、422 の `insert` にして書き込まない。

位置を持たない節点も、`insertionHTMLPreserves` で前後の境ごとに分け、`htmlSignature` による形の並びを比べる。追加点の外は同じ並びと形を保ち、追加点のある並びでは、既存の節点の形と順序を保って節点が増える場合だけ受ける。文書の最後の連なりの前に閉じない `<div>` だけを足し、既存の節点を取り込む形も 422 の `insert` にする。追加先が生の HTML の中の段落などの場合は、追加先の位置を持つ対象を中に持つ節点だけ、中身が増えるため要素名で比べる。同じ並びにいるほかの位置のない節点は `htmlSignature` で形を比べ、順序も保つ。`details` の中への追加で、その後ろに並ぶ `div` を取り込む形も断る。位置を持つ要素の比較は省かない。

比較する位置は、古い描画と試しの描画のそれぞれの一覧の `correctedRanges` で補正した実際の範囲を使う。補正の表は一覧ごとに 1 回だけ作り、連なりや境の照合でも使う。上流の公開の終端（終了列 0、入れ物の中の水平線）は後ろに続く内容で変わるため、公開の範囲のままでは、次が見出しのリストの後ろへの追加などを誤って断る。一覧で範囲を決められない要素（表の中など）と、利用者が書いた位置は、公開の値のまま比べる。利用者が書いた位置は、追加による行のずれも加えない。追加の書き込みは範囲の置き換えと同じ経路を通り、ファイルは入れ替えと履歴の 1 手、Neovim は 1 個の行の置き換えで扱う。

書く前にファイルをバイトで読み直し、BOM を除いた UTF-8 の本文が描画の原文と同じことを確かめる。古い描画は `stale`、外で変わった本文は `changed` として 409 を返す。単独の CR などで行の対応がずれる文書、取り込み・front matter・取り込みの指定を含む範囲、UTF-8 の文字の途中を指す範囲は断る。範囲に入れる改行は開始行の改行コードへそろえ、範囲とチェックボックスの編集後は試しに描けることも確かめる。表の操作は `tableedit` が検査し、行列を複数個変える操作は途中でも期限と 16 MiB の文書上限を確認する。

編集全体は 1 本の mutex で直列にし、書き込みの直前にも外の変更を検査する。同じ本文なら書かない。BOM と権限を保って隣の一時ファイルから入れ替え、単体ファイルは即時に描き直し、見張りによる同じ本文の再描画を省く。ファイル文書は `Reload` で読み直す。POST の本文を受け取った後の処理はタブの切断で中断せず、60 秒の期限を設ける。応答は JSON、no-store とし、端末の絶対パスや内部の失敗の詳細を含めない。

取り消し・やり直しは文書の実パスごとに持つ。1 手は共通する先頭と末尾の長さ、変更前後の中ほど、前後の全文の SHA-256 で表し、`Apply` 1 回を 1 手にする。文書ごとに 200 手、文書 32 件、全差分 32 MiB までとし、古い履歴から捨てる。今のファイルの指紋が履歴と合う場合だけ元へ戻し、外で変わっていればその文書の履歴を捨てる。新しい編集はやり直しの履歴を消す。

[internal/edit/change.go](../../internal/edit/change.go) は、編集前後の本文の版と、変わらなかった行の対応を作る。版は起動ごとの乱数を鍵に、文書の鍵と BOM を除いた本文から HMAC-SHA-256 を計算し、先頭 16 バイトを 32 桁の 16 進で返す。表情報の `version` は、外でファイルが変わっていても現在の描画のもとの本文から計算する。端末のパスと token は返さない。変更した編集の応答は `change: {before, after, keep}` を持ち、`keep` は `[旧の行, 新の行, 行数]` の配列で行は 1 始まり。変更なしと拒否には `change` を付けない。

ブロックの範囲・パイプの表全体の原文・チェックボックスの編集は、書き換えた原文の範囲の外で、改行も含めて同じ先頭・末尾の行を対応づける（同じ行が続く文書で、書き換えた行と残った行を取り違えない）。ほかの表の操作と追加は同じ先頭・末尾の行を、見出しの操作・ブロックの上下の移動・リストの項目の段の上げ下げは組み立てと一緒に運んだ行の由来を使う。履歴はその対応を保持し、取り消しでは旧と新を逆にして返す。`publicKeep` は、描画のもとの行対応から include 展開後の公開の行へ変換し、front matter を除く。取り込みの指定を変えた区間の後ろは返さない。単独の CR で対応がずれる場合と、描画が編集前の本文に追い付いていない場合は、公開の行を決められないので応答に `change` を付けない。空の `keep` は、全部の行が変わったことを表す。

Neovim の橋渡しでは版を 1 のままにし、`hello` の数値の `edit: 1` にだけ、`ready` の最後に `edit: 1` を付けて応じる。編集の設定は `{scope: "current", undo: false}` にし、`doc` に正の安全な整数の `buf` がある編集中の文書だけを編集できる。古い Lua へは今までと同じ行を返し、編集の設定や経路を追加しない。`buf` の省略は許すが、誤った型・範囲の値や `null` は `doc` の誤りにする。

バッファの編集では `doc` の `text` だけを使い、ファイルを読まず、書かない。表・範囲・追加・チェックボックスの変更と描画の再検査はファイルと共有する。変更前後の本文から末尾の `\n` を 1 個だけ除き、`\n` で分けた行の先頭と末尾の一致を除いて、1 個の置き換え `{start, end, lines}` にする。行は 0 始まりで `end` は含まず、CR は行の中に残す。末尾の改行の有無だけの違いを含めて行が同じなら送らない。

アプリは `edit` に、要求ごとに増える `id`、`jump` と同じ `path`（無名なら `null`）、描画のもとの `buf`・`rev`、1 個だけの `edits` を入れて Lua に頼む。1 行は区切りを含めて 8 MiB まで。Lua がバッファと版を確かめて置き換え、`edit_result` の `id`・真偽の `ok` で返すまで HTTP POST の応答を待つ。受理後は Lua の新しい `doc` で描画を更新し、アプリ側の履歴・`Written`・`Reload` は使わない。保存は `:w`、取り消しは Neovim の `u` で行い、画面に取り消し・やり直しのボタンを出さない。

拒否は 409 の `rejected` にし、文字列の `message` を改行前・200文字までに切って知らせる。応答は既定で 5 秒待ち、時間切れは 504 の `timeout` を返すだけで、Neovim に編集が当たったかをアプリで決めない。休止中と待っている途中の `pause` は 409 の `paused`、標準入力の終了は 503 の `closed` で待ちを終え、サーバーを閉じる前に解除する。`resume` で休止を戻す。知らない番号・済んだ番号・時間切れ後の結果は黙って捨てる。出力へ積めなければ 503 の `busy`、行の上限超過は 413 の `large` にする。

ページ側は、編集モードへ入ると描画番号を指定して表の情報を取り、`gp:render` のたびに前の取得を中止して読み直す。画面の文書順の表の数・番号に加え、区画を木の順にたどって作った格子の行列数・結合・th/td と全セルを比べる。照合できない表は選ばせず、理由や警告を文字で知らせる。scope が current の場合は、`?doc=` のない今の文書だけに入口を出す。一覧には出さない。

選択枠・textarea・操作欄・知らせは body 直下の `#gp-edit-layer` に置く。層の z-index を md-table-sticky の全幅パネルより上にし、表・セルには要素や属性を追加しない。選択中だけ requestAnimationFrame でセルの位置を測り直し、スクロールする祖先と固定行列の scroll-padding の内側へ枠を切る。入力欄は、狭いセルでも読めるように右と下へセルより大きく出し、固定した行・列に隠れる上と左だけを切る。入力欄の文字の大きさは編集を始めるときに 1 回だけセルに合わせ、中身の高さは入力か幅が変わったときだけ測り直す。全幅パネルへ表を移しても、同じセルを追う。選んだセルは `scrollIntoView` で見える位置へ出す。ページのヘッダーと下の操作欄の後ろへ入れないための scroll-padding は、動かす間だけページに付ける（見出しへの移動の位置を変えないため）。全幅パネルの中は、CSS の `scroll-padding-bottom` で同じ余白を取る。編集できる表のカーソルも、表を変更せず、層の style に番号だけで作った `.md` のセレクターを置く。

表の選択中の下の操作欄は「行」「列」「セル」「表」「原文を編集」「元に戻す」「やり直し」で、右クリックにも「行 ▸」「列 ▸」「セル ▸」「表 ▸」を出す。無効な項目もキーで選んで理由を読める。変換と並べ替えは描き直した後の表へ選択を戻し、削除は選択を外す。削除後も履歴があれば操作欄の「元に戻す」「やり直し」を残し、選択のない状態の Ctrl+Z・Ctrl+Y・Ctrl+Shift+Z も同じ操作として受ける。

表以外のブロックの右クリックは `openBlockMenu` が扱い、「原文を編集」「外側を編集」「前にブロックを追加」「後ろにブロックを追加」を出す。`blockOf` または `rawBlockOf` でダブルクリックと同じ対象を引き、原文の口から `outer`・`anchor` と無効理由を読む。外側への移動と追加は、原文を開いてから既存の入力欄の操作へつなぐ。Shift、対象に掛かる文字の選択、IME の変換中、リンク・動画・音声などではブラウザーのメニューを残す。PlantUML の図のリンクだけは図の原文を扱う。

見出しのメニューは、見出し欄の「操作」と見出しの文字の右クリック、見出し欄の見出しか「操作」にフォーカスがあるときの Shift+F10・メニューキー、本文の「見出し ▸」、原文の操作欄の「見出し…」で共用する。本文の子メニューはサーバーの一覧にある見出しに出し、対象外の見出しでは無効にして理由を読めるようにする。レベル変更・削除・移動では描画の見出しとサーバーの一覧を番号・ID・レベルで照合し、未確定の原文・IME・読み込みや書き込みの待機中などは理由を知らせて断る。末尾の 2 種類のリンクのコピーはこれらの書き込みと分け、未確定の原文があっても入力を変えずに使える。節ごとの削除は題・行数・内側の見出し数を示す確認を出し、「削除する」だけで送る。「やめる」と Esc は送らない。見出しだけの削除は確認を出さない。

クリックでセルを選び、見えない textarea にフォーカスする。矢印・Tab で格子を移り、Enter・F2・ダブルクリックで現在の文字を編集し、文字入力や compositionstart では新しい文字で置き換える。HTML をセル用 Markdown にできない raw セルは原文にする。変換中のキーを操作として扱わない合成試験はあるが、実際の IME での入力は別途確認が必要。HTML の原文では Enter が改行、Ctrl+Enter が確定になる。

表以外では、`blockOf` が押した節点から祖先へたどり、`gpPreview.sourceOf` と `findSource` で、もとの要素名と公開の範囲を今の表示へ対応づける。形の正しい範囲を持つ p・h1〜h6・li・dt・dd・blockquote・pre・ul・ol・dl・hr・div.markdown-alert と、PlantUML の img をダブルクリックで編集する。数式と mermaid の描画結果、mermaid と PlantUML の失敗表示へ置き換わった節点も、もとの要素名と範囲から囲みを含む原文を開く。ライブラリの読み込み前も同じ対象を開く。li の直下なら子のリストも含む li、内側の p ならその段落だけを開く。注記の題名や余白では注記全体を開き、種類・題名の行と `>>>` の閉じの行も含める。脚注の定義の内側は、段落や項目だけを開かず、ラベルを含む定義全体を開く。

目次・操作欄・入力欄はブロックの対象にせず、表の内側はセルの編集に任せる。include 先・front matter は画面から編集できない。位置を持つブロックが見つからない場合は `rawBlockOf` が生の HTML を選ぶ。対象は位置を持つ祖先のない所に限り、表・目次・コードの包み・脚注の節は除く。`details` の題名や位置のない要素は、`gpPreview.htmlOf` で最上位の連なりへ対応づける。中に空行を挟んだ段落・リスト・コードなどは、それぞれ位置を持つ対象として開く。修飾キーのあるダブルクリックと文字選択のドラッグは扱わない。対象内のリンクのクリックは移動させず、PlantUML の SVG を開くクリックも止める（修飾キーを押しながらのクリックは、ブラウザに任せる）。編集モードの間は、Neovim のエディタの行へ移るダブルクリックも止める。表がなくても、表情報の `document.editable` が真なら使える。

入力欄のそばの操作欄のボタンか Alt+↑ で `outer` の先頭のブロックへ移り、「内側に戻る」か Alt+↓ で移る前の内側へ戻る。外側の種類が list・quote・deflist・alert・item・description・html なら、それぞれ「リスト全体を編集」「引用全体を編集」「説明リスト全体を編集」「注記全体を編集」「項目全体を編集」「説明全体を編集」「HTML のブロック全体を編集」、ほかは「外側のブロックを編集」と出す。移動は入力を確定せず、範囲ごとの下書きを保存して戻ると復元する。描き直しで画面から外れた内側の要素は飛ばし、戻る先が無ければ「内側に戻る」を隠す。IME の変換中は移らない。脚注の定義を開くと「ラベルを変えると、本文の参照と対応しなくなります」と知らせる。

編集の層は、位置を持つ対象をもとの要素名 `tag` と公開の範囲 `range` の組、生の HTML の連なりを `{tag: "html", prev, next}` の前後の境で持つ。先行する送信と描画の反映を待ち、この対象と最新の描画番号を `GET _/edit/source` に送り、原文を取って、セルと同じ textarea と「原文」の表示をブロックの位置へ重ねる。生の HTML では `findHTML` が返す連なりの要素の矩形を囲む範囲へ入力欄を置く。取得の409は開かずに終える。422で `outer` があれば開ける外側を開いて知らせ、なければ include 先・front matter などの理由を知らせて開かない。`>>>` の引用の中の最後の項目など、範囲を確かめられない対象も同じ扱いにする。Enter は改行、Ctrl+Enter（macOS は Cmd+Enter も）は確定、Esc は入力とその対象の下書きを捨て、外のクリックは確定にする。末尾の改行も含めて入力のまま `{render, range, text}` を共通の待ち行列へ置き、同じ文字なら送らない。確定後に選択は残さず、422なら入力を開き直す。ブロックの原文を読んだ描画から位置が変わった場合は、古い範囲へ送らず下書きを残す。編集中の画面の要素が数式・図の描き直しや配色の切り替えで置き換わった場合は、`refreshBlock` が文書の外の変更を数える `externalVersion` と開いたときの値を照合し、変わっていないときだけ `findBlock` で探し直す。位置を持つ対象は `findSource(tag, range)`、生の HTML の連なりは `findHTML(target)` の先頭の要素を使う。見つかれば入力欄を閉じずに付け替える。文書が外で変わった場合や同じ対象を見つけられない場合は、入力欄を閉じて下書きに残し、知らせる。ブロックを開くときは、見えている位置ならページを動かさない（表用の下の操作欄の余白は取らない）。ブロック用の操作欄は画面の端に収め、入力欄と重ねない。「原文」の札は、前後の本文やページのヘッダーに掛からないよう、入力欄の右下の内側に重ねる。

ブロックの原文を開いたとき、`anchor` があれば操作欄に「前に追加」「後ろに追加」を出す。`beginInsert` は現在の入力を確定せず下書きに残し、`findBlock` で探した追加先の上か下へ、空の入力欄と「追加」の札を重ね、画面の端に収める。生の HTML 全体を開いている場合は連なり全体の前後へ、内側の段落などを開いている場合は生の HTML の中の追加先の前後へ置く。セルの原文の入力欄にはこのボタンを出さない。表のセルを選ぶと、下の操作欄の「表」と右クリックの「表 ▸」から「表の前にブロックを追加」「表の後ろにブロックを追加」を選べる。`beginTableInsert` は照合済みの表情報の `anchor` を使い、固定や全幅表示中も表の外側へ入力欄を置く。入力欄は表のスクロールの包みで切らず、表番号と `anchor` が変わらない場合だけ描き直しにも付いていく。追加用の入力欄では外側・内側へ移るボタンを隠し、Alt+↑・Alt+↓ も効かせない。Ctrl+Enter（macOS は Cmd+Enter も）で確定、Esc で取り消し、外のクリックは文字があれば確定、無ければ取り消しにする。確定は `{render, insert, text}` を共通の待ち行列で送り、422 では入力を開き直す。前へ追加した後は `shiftInsertDrafts` で、後ろへずれた対象の下書きも増えた行数だけ位置をずらして残す。連なりの前後に段落を追加して境が変わる場合は、`rebindHTMLDraft` が追加前の入力の要素と追加しなかった側の境から、下書きを今の連なりへ結び直す。

操作欄の「追加」は「文書の先頭に追加」「文書の末尾に追加」のメニューを開く。サーバーの `empty` が真なら「最初のブロックを書く」に替え、末尾への追加として直接入力欄を開く。`beginDocumentInsert` は先頭・末尾を範囲とは別の対象として持ち、文書の上か下へ入力欄を重ねる。先頭への追加では `insertStart` を使って既存の下書きの行をずらす。メニューを Esc で閉じると「追加」へフォーカスを戻す。

どの追加用の入力欄にも「表を入れる…」を出し、列（1〜20）と本文の行（1〜100）を選ぶ欄を開く。「入れる」は [edit-grid.js](../../page/edit-grid.js) の `emptyPipeTable(cols, rows)` で、見出し「列1」・「列2」…と区切り行、空の本文を持つパイプの表を作る。関数も整数と範囲を検査する。カーソルか選択範囲へ文字として差し込み、前後に空行を補い、下書きへ保存する。この時点では送信せず、Ctrl+Enter などで追加を確定したときにサーバーの検査を通す。「閉じる」と Esc は大きさを選ぶ欄だけを閉じ、入力欄へフォーカスと選択位置を戻す。

追加用の入力欄の「注記…」「コード…」「折りたたみ」も、[edit-grid.js](../../page/edit-grid.js) の断片を同じ `insertFragment` で差し込む。`emptyAlert(kind)` は `note`・`tip`・`important`・`warning`・`caution` だけを受け、`> [!note]` などの種類の行と本文用の `> ` を作る。`emptyCodeBlock(language)` は `sh`・`bash`・`powershell` だけを受け、言語名の付いたバッククォート 3 つの囲みと空の本文の行を作る。`detailsBlock()` は `<details>`・`<summary>題</summary>`・空行・本文・空行・`</details>` を改行でつなぐ。

注記と言語は選ぶ欄を開いて「入れる」、折りたたみは押すだけで入力欄へ入れる。カーソルか選択範囲を使い、既存の文字との間に足りない空行を補う。注記とコードは本文へカーソルを置き、種類や言語を選ぶ欄の「閉じる」と Esc は入力欄へフォーカスと選択位置を戻す。IME の変換中は差し込まない。どの定型もこの時点では送信せず、入力欄で直して確定すると通常の追加の待ち行列とサーバーの試しの描画による検査を通る。定型専用の書き込みの口は作らない。

マウスを載せたときの破線の枠も、`updateHover` が `blockOf` と `rawBlockOf` でダブルクリックと同じ対象を決める。数式と図はその表示、水平線は線、項目は項目、注記の題名は注記全体、脚注は定義全体に出す。位置を持たない生の HTML は、`findHTML` が返す連なりの要素の全部に出す。編集の層の `style#gp-edit-hover` に、`#gp-content` から子の番号だけを `:nth-child()` でつないだセレクターを並べた規則を 1 つ置く。対象がなければ規則を空にし、本文の DOM に属性やクラスを足さず、CSS の `:hover` は使わない。本文の変更・スクロール・画面の大きさの変更後の当て直しは、編集モードの間だけ `requestAnimationFrame` で 1 フレームに 1 回にまとめる。水平線の押せる高さは、編集モードの [page/preview.css](../../page/preview.css) の `hr::before` で上下へ広げる。見た目と本文の DOM は変えない。

タスクは、`data-checkbox-sourcepos` があり `data-inapplicable` のないチェックボックスだけ、編集可能な文書の編集モード中に disabled を外す。脚注の定義の中も対象にし、表のセルの中は表のモデルが対応と格子の検査を通っているときだけ有効にする。クリックとフォーカス中の Space の通常の切り替えを受け、`{render, checkbox, checked}` を同じ待ち行列へ送る。反映待ちのチェックは新しい状態にし、失敗時は元へ戻して知らせる。`gp:render` のたびに有効・無効とチェックの状態を当て直し、編集モードを出ると無効に戻す。disabled の変更は差分更新の節点の対応を崩さず、別の details と表の要素が保たれることをブラウザ試験で確かめる。切り替えたチェックボックスは、`checked` の属性が変わるので描き直しで別の要素になる。フォーカスがあったなら、また押せるようになったとき（その描画の表情報が届いたとき）に、表の外は同じ親の同じ位置、表の中は同じセル内の何番目のチェックボックスかで探して戻す。セルの子は更新時に入れ替わるため、待ち行列の反映待ちのチェックもこの番号で追う。全幅表示で本文の外へ移った表も `preview.tables()` から集め、対応を失った表も無効へ戻す。タスクのクリックではセルの選択・原文の編集を始めず、「セルを選んで固定」の最中はタスクの切り替えを送らない。

確定した操作は待ち行列に置き、POST は一度に一件だけ送る。成功の応答・番号の進んだ描画・その表情報の三つが揃ってから、最新の描画番号で次を送る。unchanged では描画を待たず、三秒届かない場合は知らせて情報を読み直す。反映待ちの文字は層に重ね、再描画後は同じ表番号・行列へ選択を戻す。422 では入力した文字を開き直し、別のセルの入力途中の文字も下書きに残す。開き直さなかったとき（行・列の操作が断られた、編集モードの外で断られた）は、並んだ送信を続ける。409 では並べた送信を破棄して再照合し、自動で再送しない。`stale`・`changed` 以外の 409 と 503・504 はサーバーの `message` を知らせに使い、入力は下書きに残す。行列を変える操作は反映待ちの間は無効にして、待ち行列内で位置の意味が変わらないようにする。

外の変更で行や列がずれた後の位置へ書かないために、描画を「自分の書き込みのもの」と「外の変更」に分けて数える。自分の書き込みの描画は、送信ごとに最初の 1 回だけ（3 秒の待ちが切れた後に遅れて届く 1 回を含む）。ほかの描画と 409 の応答は外の変更として数え、その前に開いた入力の確定と、その前に並べた送信は、送らずに下書きへ戻して知らせる。下書きは、書き始めたときと同じ中身のセルを開いたときだけ入力欄に戻す。誤りの応答の `error.message` は、知らせに `textContent` で出す。選択中のコピーの文字は、セル用 Markdown（原文の編集になるセルは原文）を引用符付き TSV にする。

キーとクリックの受け手は window の capture に一度だけ登録し、キーは自分の textarea にフォーカスがあるときだけ扱う。Esc は IME → メニュー → 入力の取り消し → 挿入の待機 → 切り取りの印 → 範囲を 1 セルへ → 選択の解除の順に扱う。選択の解除だけは全幅表示の受け手へ通し、ほかは stopImmediatePropagation でそこで止める。固定するセルを選ぶ間と md-table-sticky の操作欄・検索欄は扱わない。`gp:stop` では入力を閉じて下書きを残し、編集モードは保持する。編集モードも配色と同じ sessionStorage に覚える。

範囲は活動中の `selected` とは別の `tableSelection` に、表番号・DOM の表・起点・終点・行列の形・外の変更の番号を持つ。[edit-grid.js](../../page/edit-grid.js) が DOM に頼らず矩形・結合の分断・移動・TSV・HTML・写しを計算する。Shift+矢印と同じ表での Shift+クリックで伸縮し、端点の結合セルの箱を一度だけ囲む。途中にある結合へ自動で範囲を広げず、結合の途中を切る範囲と検索で隠れた行をまたぐ範囲のコピーは断る。範囲と切り取りの枠は固定行列の境で最大四つに分け、`placeRect` で位置と切り取りを共用する。

操作欄は「行」「列」「表」「原文を編集」「元に戻す」「やり直し」にまとめる。セルの右クリック・Shift+F10・メニューキーでは同じ行列のメニューを子として開く。層の直下に `role=menu` と `role=menuitem` を置き、矢印・Home・End・Enter・Space・Esc・Tab で操作する。無効な項目は `aria-disabled` と `aria-describedby` で理由を示し、`reasonFor` を表示と実行で共用する。

copy・cut イベントは同期的に、表情報から `text/plain` の引用符付き TSV、2 セル以上の `text/html`、`application/x-gp-table` の包みを作る。TSV と HTML の形は md-table-sticky とそろえ、意図した違いとともに `sticky/test/fixtures/table-clipboard.json` の共通の見本で確かめる。HTML はエスケープした文字と結合だけで、原文・属性を入れず、セル内の改行に `<br style="mso-data-placement:same-cell">` を使う。Windows 11 の Edge と Excel で、結合とセル内の改行が Excel で再現されることを確かめた（`repos/md-tools/docs/verification/readme.md` の「表の範囲のコピー・貼り付けと Excel（0.4.0）」）。包みには版・`origin`・Fragment・切り取りの照合値を持つ。`origin` は表情報から取り、起動ごとの乱数を鍵にした `HMAC-SHA256("md-preview table origin\0" + 文書の鍵)` の先頭 16 バイトを 32 桁の 16 進にする。端末の絶対パスとサーバーの token を写しへ入れない。原文を保てない `copyLocked` のセルの範囲・表は値だけの Fragment にし、10000 セル・UTF-8 で 1.5 MiB の上限を超える写しは付けずに知らせる。

独自の形式は別のサイトからも受け取れるので信用しない。ページは型・大きさを検査し、知っている値だけを新しいオブジェクトへ写す。`internal/edit` は型と上限、`tableedit.ParseFragment` は原文・開始タグ・結合・単独で読み直した形を検査する。受け取った文字を DOM の HTML として使わない。不正な包みは TSV へ戻し、422 では文字だけを貼る Ctrl+Shift+V を案内する。

切り取りは写しと破線の印を作るだけで、同じ文書へ貼るときに `moveCells`・`moveRows`・`moveColumns` 一個で移動する。別の文書へは `pasteFragment` にして元を消さず、参照リンク・脚注・相対パスにも注意を出す。描画番号の変更・Esc・新しいコピー・編集モード終了・停止・409・反映が不明な失敗で印を消す。取り消した切り取りは貼らない。最後の写し `lastCopy` は保ち、「コピーした…を挿入」で使う。別のタブや Excel の挿入はメニューから `pendingInsert` を置き、消えない `wait` の知らせを出して次の paste を待つ。Esc・ほかのセル・メニュー・編集開始・外の変更・表の消滅・モード終了・停止で解く。メニューからのコピーだけは、クリック中に入力欄へフォーカスして `execCommand('copy')` を呼ぶ。

新しい op は `duplicateRows`・`duplicateColumns`・`insertRowsFrom`・`insertColumnsFrom`・`pasteFragment`・`moveRows`・`moveColumns`・`moveCells`。写しの挿入は Fragment または values、移動元は表番号・範囲・描画番号・hash・origin で照合する。サーバーは写しの行数・列数を各 1〜1000、矩形のセル数を 10000 以下、count を 1〜1000 に限り、origin は 32 桁、hash は 64 桁の 16 進を受け付ける。知らない名前と型の誤りは 400、原文・結合の意味の誤りは 422、移動元の照合の不一致は 409 にする。既存の空行列の追加・削除の count ループと分け、窓口を一回だけ呼ぶ。表をまたぐ移動も一個の op・履歴一手・Neovim の行の置き換え一個にする。構造の変更が成功したら後ろに並んでいた座標に頼る入力は下書きへ戻し、最新の表情報で複製先・挿入先・移動先・貼った所を範囲として選ぶ。422 は範囲と切り取りを保ち、409 は範囲を一セルへ戻して切り取りと待機を解く。504 などの反映が不明な失敗は範囲と最後の写しを保ち、印と待機を解く。

画面の編集の検証記録は、`repos/md-tools/docs/verification/readme.md` の「画面の編集の範囲の拡大（第 1 段）と、版 0.10.0 の配布の検証（2026-11-12）」にある。数式と図の編集の検証記録は、`repos/md-tools/docs/verification/readme.md` の「数式と図の編集と、版 0.11.0 の配布の検証（2026-11-12）」にある。水平線の編集とブロックの追加の検証記録は、`repos/md-tools/docs/verification/readme.md` の「水平線の編集とブロックの追加と、版 0.12.0 の配布の検証（2026-11-12）」にある。生の HTML のブロックの編集の検証記録は、`repos/md-tools/docs/verification/readme.md` の「生の HTML のブロックの編集と、版 0.13.0 の配布の検証（2026-11-12）」にある。

## 画面のコメント

`mdpreview --review <ファイル | フォルダー>` は、[internal/edit](../../internal/edit/review.go) の原文と対象の検査、[internal/review](../../internal/review/prompt.go) の依頼文の組み立て、[internal/vscode](../../internal/vscode/vscode.go) の Agents Window の起動と、[page/review.js](../../page/review.js) を接続する。`--edit` と併用できるが、ページでは編集とコメントのモードを同時に使わない。`--stdio` とは併用できず、Neovim の取り決めにもコメントを加えない。指定しない場合はコメントの経路とページの `review` 設定を有効にせず、`review.js` も操作や層を追加しない。一覧の画面にはコメントの入口を出さない。

コメントをためる操作と依頼文の作成では、Markdown に書かない。ページは利用者のクリックで依頼文をクリップボードへコピーし、その後に VS Code の Agents Window を文書のルートで開く。利用者が入力欄に貼り、内容を確かめて送る。mdpreview 自身は AI の API へ通信せず、依頼文をコマンドラインや URL に入れない。[VS Code の公式の説明](https://code.visualstudio.com/docs/agents/run/agents-window#_limitations)に従い、「/plan で計画」は依頼文の先頭に `/plan` を置き、Copilot か Claude のセッションで計画を頼む。「日本語で計画」はスラッシュコマンドを付けずに計画を頼み、「直接直す」は計画の承認を待たずに直すよう頼む。Agents Window のエージェントの一覧に Plan は無い。今のプレビューと同じファイルを直すときは作業場所を Branch にする。New Worktree の変更は別のファイルなので、今のプレビューには出ない。

コメントの口は [internal/server/review.go](../../internal/server/review.go) と、編集と共有する [internal/server/edit.go](../../internal/server/edit.go) の `readSource` にある。token は URL の先頭の区切りで照合し、合わない要求はコメントの口に入らない（POST は 405、GET は 404）。Host と Sec-Fetch-Site は共通で検査する。対象の原文を読むときは `Resolve` でルート内の実パスを確かめ、launch は prepare で検査した文書とルートを使う。`doc` を省くと起動した文書、付けるとそのファイル文書を指し、空文字列と省略は区別する。GET は HEAD も受ける。

| 口 | 要求と成功時の応答 |
| --- | --- |
| `GET _/review/tables?doc=&render=` | 編集と同じ文書・表・セルの情報を返す。`render` は正の描画番号 |
| `GET _/review/source?doc=&render=&tag=&range=` | 編集と同じ対象の検査を通し、ブロックの `text`・`render`・実際の `range`・`kind`・`outer`・`anchor` を返す。生の HTML は `tag=html` と `prevTag`・`prevRange`、`nextTag`・`nextRange` の境の組を使い、文書の先頭・末尾の組は省く |
| `POST _/review/prepare?doc=` | `{render, comments: [{target, selection?, text}], mode?}` を受け、`{id, prompt, comments, bytes}` を返す。応答の `comments` は件数、`bytes` は依頼文の UTF-8 のバイト数 |
| `POST _/review/launch?doc=` | prepare が返した `{id}` だけを受け、`{launched: true}` を返す。同じ ID の起動が済んでいれば、重ねて起こさず `again: true` を加える。同じ ID の起動がまだ終わっていなければ、409 の `launching` を返す |

POST は、Origin が要求の Host と完全に同じことと、Sec-Fetch-Site が空か same-origin であることを追加で確かめる。Content-Type は `application/json`、本文は UTF-8 の JSON オブジェクトに限り、prepare は 2 MiB、launch は 1 KiB まで。prepare の `render` は正の安全な整数、`comments` は 1〜50 件にする。省略できる `mode` は文字列の `plan`・`plan-text`・`direct` だけを受け、省略時は `plan` にする。空文字列・`null`・未知の値や誤った型は 400 の `invalid` にする。コメントは空白を除いた空文字列を受けず、`text` と省略できる `selection` はそれぞれ 1〜2,000 文字で、タブと改行以外の制御文字を断る。各オブジェクトの知らないキーと、型の誤りも断る。

`target` は次の 4 つの形だけを受ける。`block` は `{kind: "block", tag, range}` で、`range` は描画した HTML の公開の位置。`section` は `{kind: "section", tag, range}` で、`tag` は `h1`〜`h6`、`range` は節の先頭の見出しの公開の位置に限る。節全体の行範囲はページから受け取らない。`html` は `{kind: "html", prev?, next?}` で、境はそれぞれ `{tag, range}` にする。`cell` は `{kind: "cell", table, row, col}` で、表番号と行列は 0 始まり、0〜2147483647 の整数に限る。ブロックのタグと位置の構文、HTML の境の組は編集と同じ検査を通る。ページからファイル名・原文・行・起動先を受け取り、そのまま信用する形にはしない。

`edit.Service.Review` は mutex で直列にし、最新の描画番号の原文を読み、ファイルがその原文と同じことを検査する。ブロックは描画の一覧、最上位の生の HTML の連なりは前後の境と試しの描画、表のセルは原文と描画を対応づけた表・セルの一覧で確かめる。生の HTML の利用者が書いた位置を信用しない規則と、include・front matter・JSON の表・入れ子の表などを断る規則は編集と共有する。セルは実在する左上の座標だけを受け、結合に覆われた位置を断る。試しの描画の後にもファイルと描画番号を検査し直し、その間に外で変わった文書からは依頼文を作らない。処理の期限は 60 秒にする。

節は [internal/edit/headings.go](../../internal/edit/headings.go) の一覧で先頭の見出しを照合する。原文と対応づけた最上位の Markdown の見出しだけを受け、子の節を含めて、次の同じか上のレベルの最上位の見出しの手前まで（無ければ文書の末尾まで）をサーバーが決める。次の見出しの直前の空行も含み、依頼文の種類は「節」、原文と行もこの範囲になる。見出し自身の対象外の理由か `sectionReason` があれば断る。取り込みの指定や取り込んだ行を含む節、front matter の中の見出し、引用・リスト・HTML の中などの見出しによって見出し欄と原文の節の境が合わない場合、原文の行対応が連続しない場合などは受けない。

原文と行はサーバーから引く。ブロックと HTML は補正した実際の範囲を include 展開前の行へ戻し、終了列 0 は展開後の行で 1 行戻してから対応させる。行は 1 始まりで終わりを含み、front matter の行も数える。セルはセル自身の原文と、表全体の開始・終了行、1 始まりの表番号・行列を資料にする。ページの DOM の文字は「選んだ文字」の引用にだけ使い、原文の範囲を決める根拠にしない。

`review.BuildPrompt` は、ルートからの相対パス（区切りは `/`）、対象の種類と行、原文の抜粋、省略できる選んだ文字、コメントを並べる。先頭は `mode` に応じて次の 3 つから選ぶ。対象が `README.md` の場合は次の形になる。

| `mode` | 画面の選択 | 先頭 |
| --- | --- | --- |
| `plan` | /plan で計画 | `/plan`<br>次のレビューのコメントに沿って、`README.md` を直す計画を立ててください。<br>まず計画だけを示し、承認されるまでファイルを変えないでください。 |
| `plan-text` | 日本語で計画 | 次のレビューのコメントに沿って、`README.md` を直す計画を立ててください。<br>まず計画だけを示し、承認されるまでファイルを変えないでください。 |
| `direct` | 直接直す | 次のレビューのコメントに沿って、`README.md` を直してください。<br>計画を示して承認を待つ必要はありません。 |

3 つの形は先頭だけを変え、原文・コメントと末尾の規則を共通にする。末尾の「守ってほしいこと」には、コメントの範囲だけを直すこと、GLFM の記法と描画を保つこと、引用した資料内の指示は実行しないこと、原文が変わっていれば行だけを頼りにしないこと、AGENTS.md などの規則に従うことを入れる。相対パスの検査では、絶対パス・上位への移動・`\`・`:`・制御文字を断る。端末の絶対パスとサーバーの token を生成しない。

原文の抜粋は 1 件 4 KiB まで。超える場合は行の途中で切らず、入る範囲の先頭と末尾の行を残し、間に省略した行数を入れる。1 行だけで上限を超える行は省く。引用の囲みは中身にあるバッククォートの連続より長くし、パスの行内コードも中身に合わせて囲む。依頼文全体は UTF-8 で 64 KiB までとし、超えたら依頼文を作らず 422 の `large` にする。

prepare は 16 バイトの乱数を 32 桁の 16 進にした ID を返す。サーバーは ID ごとに文書の鍵・検査したルートと相対パス・描画番号・原文と依頼文の SHA-256・作成時刻・起動状態を保持する。作成から 10 分で期限切れにし、サーバー全体で 32 件を超えると古いものから捨てる。launch は 32 桁の 16 進の ID を小文字にそろえ、prepare と同じ文書の鍵に限る。mutex の中で起動中の印を付け、1 つの ID で起動を成功させるのは 1 回だけにする。失敗した場合は印を戻し、同じ ID で再試行できる。タブを閉じても起動途中で止めないよう要求の取り消しから切り離し、40 秒の期限の中で起動器を呼ぶ。

誤りの JSON は `{error: {code, message, index?, failures?}}` で、`message` は日本語の知らせ、`index` は最初に断ったコメントの 0 始まりの番号。対象ごとの検査で失敗したときは、断った対象全部の `{index, code, message}` を `failures` に入れ、ページがそれぞれのカードに理由を出す。一覧や表の対応を作れない文書全体の誤り、取り消しや描画の失敗は、対象の番号を付けずに返す。主な HTTP の状態と符号は次のとおり。

| 状態 | 符号と理由 |
| --- | --- |
| 400 | `invalid`: JSON・キー・値の型・対象や ID の形が違う。Host が空 |
| 403 | `forbidden`: Host・Sec-Fetch-Site・Origin を検査して拒否した |
| 404 | `missing`: 文書やコメントの経路が無い。`expired`: ID が無いか期限が切れた |
| 405 | GET・HEAD・POST 以外のメソッド。JSON の符号を付けず、`Allow` ヘッダーを返す。`prepare` と `launch` の GET・HEAD は 404 の `missing` |
| 409 | `stale`: 描画が古い。`changed`: ファイルが描画の原文と違うか、ID が別の文書を指す。`launching`: 同じ ID の起動がまだ終わっていない |
| 413 | `large`: POST の本文が上限を超えた |
| 415 | `media`: Content-Type が違う |
| 422 | `target`・`boundary`・`untrusted` など: ブロックの検査で拒否した。`excluded`・`range`・`merged`: 表やセルが対象外。`unnamed`: 名前の無い文書。`cancelled`: 原文の検査を取り消した。`invalid`・`large`: 依頼文の相対パスが不正か全体が 64 KiB を超えた。`large` は文書が 16 MiB を超えたときにも返す（コメントを分けても解消しない） |
| 500 | `internal`: コメントの処理を終えられない |
| 503 | `notfound`: VS Code が見つからない。`launch`: 起動・終了・待機に失敗した |

`internal/vscode.AgentsCommand` は、存在するフォルダーの絶対パスだけをルートに受け、PATH の空の項目と相対パスの項目を飛ばして `code` を探す。Windows 以外は実行の権限がある通常のファイルを選び、リンクを解決した実パスで `code --agents <ルート>` を起こす。Linux の実際の VS Code の起動は未検証。

Windows は `code.cmd` を実行せず、64 KiB まで読んで `Code.exe` と版ごとの `<版のフォルダー>/resources/app/out/cli.js` の配置を確かめる（版のフォルダーの無い前の配置も受ける）。`cli.js` の相対部分に `..`・区切りの混用・`:`・`%`・`"`・NUL・CR・LF・末尾の点と空白（Windows が名前から落とす）などを受けず（タブなどのほかの制御文字は、この段では断らず、解決後のパスがインストール先の内側にあることで閉じる）、`cli.js` と `Code.exe` はリンクやジャンクションの解決後もインストール先の内側にある通常のファイルに限る。`ELECTRON_RUN_AS_NODE` と `VSCODE_DEV` を親の環境から除き、`ELECTRON_RUN_AS_NODE=1` を付け、`Code.exe <cli.js> --agents <ルート>` を引数の配列で起こす。`--agents` を処理する CLI の入口を通すため、`Code.exe --agents <ルート>` だけで GUI を直接起こさない。`cmd.exe`・PowerShell・バッチを通さず、ルートに含まれる文字をシェルの構文として解釈させない。コンソールを作らない指定を使い、VS Code の画面まで隠す指定は使わない。

起動器は、VS Code を探す処理とコマンドの終了を合わせて 30 秒まで待ち（PATH に応答しないフォルダーがあっても止まらない）、期限の後は起こさない。標準入力・出力・エラーは捨てる。コマンドが開始できない場合・終了コードが 0 でない場合・時間切れを区別し、ページの知らせには端末のパスや内部のエラーを出さない。ページはコピーが成功した後だけ launch を呼ぶので、起動が失敗してもコピーした依頼文は使える。コピーが失敗した場合は launch を呼ばず、依頼文を選択して Ctrl+C を案内する。

ページは [edit-targets.js](../../page/edit-targets.js) のブロック・生の HTML・表の格子の検査を編集と共用する。`review.js` は、要素名と公開の位置、HTML の前後の境、表と左上のセルの座標で対象を保持する。文字の選択は 1 つの対象内だけを受ける。表は描画番号・文書順の数と番号・区画ごとの格子・行列数・セル順・結合・th/td を照合し、固定の全幅表示で本文の外へ移った表も対応づけたセルだけを受ける。本文へ属性を足さず、ブロックと HTML は子の番号だけのセレクターの枠、セルは body 直下の層の枠で示す。

本文の最上位の見出しを選ぶと「節全体へのコメントにする」を出す。既定はチェックなしで、対象を選び直すと外す。チェックに応じて `kind` を `block` と `section` に切り替え、選択した対象を「見出し: …」「節: …」にし、追加・保存したカードの題にも使う。カードの「直す」「本文へ移る」では保存した種類に合わせてチェックを戻す。枠と本文への移動は先頭の見出しを使い、節全体の範囲は prepare のサーバーの検査で決める。

右の欄（幅 700 px 以下では下）にコメントの入力・カード・依頼文を置く。「依頼文の形」はページを開くたびに `plan` を選び、選択を保存しない。形の変更は `changed()` を通して作成済みの依頼文と ID を捨てる。prepare は選んだ `mode` を送る。「追加」は Ctrl+Enter でも受け、IME の変換中のキーは扱わない。「直す」「消す」「本文へ移る」でカードを操作し、「依頼文を作る」は「今回は送らない」を除く未コピーだけを送る。コピーが成功したカードを「コピー済み」にし、「コピー済みを消す」で除ける。これは送信や実装の完了を意味しない。再描画で対象が消えた・内容が違う・対応を一つに決められない・表を検査できなくなった場合は「要確認」、prepare がその対象を断った場合は「誤り」を出す。要確認を送る前に件数を知らせ、「直す」へフォーカスして依頼文の作成を止める。「直す」で今の対象を選び直すか、「今回は送らない」で今回の依頼から外せる。「今回は送る」で戻せ、除外の印はコピー成功で外す。描画の版や表の情報が揃っていない間も、待つよう知らせて prepare を送らない。カード・コメント・知らせは `textContent`、入力欄と依頼文は `value` で入れ、HTML として解釈させない。

「要確認をまとめて送らない」は `stale`・`pending`・`!skip` のカードだけを `skip: true` にし、変更したカードの ID をページ内の `bulkSkipped` に記録する。「まとめて送らないを戻す」は、その集合に残ったカードだけを `skip: false` にする。手で「今回は送る」「今回は送らない」を押したカードは集合から外すので、もともとの印と手で付け直した印は一括の取り消しで変えない。`changed()` は削除されたカードと、直して保存して印が外れたカードの ID も除く。コピー成功はすべての `skip` と集合を消す。集合は保存せず、文書の切り替えと再読み込みでは復元しない。処理中と停止後は形の選択と一括のボタンを無効にし、理由を出す。

コメントの内容の指紋は、[page/preview.js](../../page/preview.js) の `fingerprint` が本文の写しから作る。ブロックは `b:`、生の HTML の連なりは `h:`、節は `s:` に、二つの 32 ビットの計算をつないだ 16 桁の値を付ける。位置・ブロック単体の見出しのレベル・脚注番号・見出しのアンカーと脚注の戻りリンクを除き、サーバーの URL の接頭辞も除くので token とポートを含めない。通常の文字の空白はそろえ、コードの中の改行と字下げ、タスクのチェックは区別する。数式・図・表の固定による画面の書き換えは指紋に影響しない。指紋はページの対象の照合用で、サーバーの原文の検査を置き換えない。

節の `s:` は、本文の写しで先頭の見出しから次の同じか上のレベルの最上位の見出しの直前までの最上位の節点を集める。末尾に集まる脚注の表示はそのまま含めず、定義の開始行が節の範囲にある `li[data-sourcepos]` を原文の行順に足す。節への所属は参照した場所や表示位置では決めない。最上位の見出しのレベルは先頭との差にそろえ、節ごとのレベル変更は同じ指紋にし、子の見出しだけのレベル変更は区別する。`pre` の外の空白は畳み、中の改行と字下げは保つ。目次（`ul.section-nav`）は一定の印にして存在だけを比べ、節の外の見出しの改題で目次の文字が変わっても指紋を変えない。位置のない HTML の見出しでも同じか上のレベルなら指紋の収集を止めるが、そのような境のあいまいな節はサーバーが依頼文の作成で断る。

セルは、表情報のセル用 Markdown の文字から `c:` の指紋を作る。同じ内容のセルを見分けるため、その行に掛かるほかのセルの文字（上の行からの結合も含む）を列順に並べた行の鍵と、その列の先頭行を覆うセルの文字の列の鍵、表の公開の開始行 `keys.start` と、付けたときに同じ内容のセルが同じ列・同じ行にあったかの印 `keys.dupCol`・`keys.dupRow` も持つ。位置の照合では、同じ内容のセルが同じ列にあれば行の鍵、同じ行にあれば列の鍵も比べる。隣のセルの変更だけで必ず要確認にする形にはしない。各描画で判定し直すので、同じ位置でも内容が違えば要確認になり、元の内容が戻れば外れる。

画面での編集は `edit.js` が応答の `change` の型・版・行対応を検査し、`gp:edited` で通知する。`review.js` はコメントの保存した版から現在の版まで、`before` と `after` が隣どうしで一致する鎖を探す。`keep` 内は行を平行移動し、変更した区間は前後の対応が囲む範囲を候補にする。前後で行数が同じ変更区間（見出しのレベルの変更など）は、同じ位置の行だけを候補にする。空になった削除区間、節の移動で境が交差する区間や別の移動元の行が入り込む区間は候補にしない。編集の応答より先に描画が届いた場合も、書き込みと版の取得が揃うまで判定を待つ。断られた応答の `change` は鎖に積まない。表の情報を読めなかった描画では、コメントに残した版を空で上書きしない（セルは要確認にする）。

ブロックの候補は公開の開始行と要素名で探し、見出しでは h1〜h6 を同じ種類として扱う。節も先頭の見出しの開始行だけを版の鎖で写し、写した範囲内の最上位の見出しを候補にする。節全体の指紋が一致する候補一つへだけ移し、節の移動・節ごとのレベル変更・取り消しとやり直しに追従させる。子の見出しだけのレベル変更や本文の変更、同じ指紋の候補が複数ある場合は要確認にする。HTML は前後の境（境があった側は、写した区間に候補の境があるものだけ）、セルは表の開始行から移動後の表を一つに決めて候補を引く。公開の開始行が 0 の表のセルは、移動先を探さず要確認にする。内容の指紋が同じ候補を一つに絞れたときだけ対象を移す。セルは、付けたときに同じ列（行）に同じ内容があれば行（列）の鍵が合う候補だけにし、行と列の鍵がどちらも変わった候補へは移さない。それでも複数なら両方の鍵が合うものに絞り、決められなければ要確認にする。取り消し・やり直しも版の鎖と逆向きの行対応で判定する。外のエディターやファイルの変更では鎖を作らず、同じ位置と内容だけを確かめ、別の位置へ移さない。対応の記録はページ内で 128 件・行の対応の合計 32768 区画までとし、超えたら古い記録から捨てる。

保存先はそのタブの sessionStorage の `gitlab-preview-review`。版 2 の `docs` に `current` と `file:<相対パス>` を分け、コメント・対象・選んだ文字・描画番号・コピーの状態・要確認と誤り、内容の指紋 `fp`・本文の `version`・セルの `keys`（行と列の鍵・表の開始行・同じ内容の印）・今回送らない印 `skip` を保存する。読み戻すときも形と大きさを検査し、不正な文書の分は捨てる。保存できなければメモリーで続ける。コメントモードの開閉は保存せず、依頼文と ID、編集の前後の版と行の対応の鎖も保存しない。再読み込みでは保存した位置と指紋だけで判定し直す。版 1 の保存も読み、読み戻したときに要確認でなかったコメントだけは、初めて確かめた内容を指紋として採る。コメントの変更・新しい描画・停止では古い依頼文を捨て、作成中の要求も中止する。編集中の入力・IME・送信待ち・原文取得があるときはコメントへ切り替えず、確定か取り消しを案内する。コメント中は `gpPreview.setEditing` と `holdScroll` で本文のリンクの扱いとスクロールを制御する。印刷ではコメントの欄・枠・知らせを隠す。

コメントの持ち出しは `review.js` の `exportItems`・`importItems` がページ内で扱い、ファイルへ書かず、サーバーへ持ち出しの要求も送らない。「書き出す」は今の文書の全カードを、コピー済み・要確認・今回送らない分も含めて JSON にして Clipboard API の `writeText` でコピーする。使えない場合は本文の外の一時的な textarea によるコピーも試し、成功か失敗を知らせる。カードのコピーの状態や作成済みの依頼文は変えない。JSON の形は次のとおり（`fp` の値は形の例）。

```json
{
  "format": "gitlab-preview-comments",
  "version": 1,
  "doc": "README.md",
  "items": [
    {
      "target": { "kind": "section", "tag": "h2", "range": "3:1-3:9" },
      "label": "節: 対象",
      "text": "子の節も含めて説明を確かめてください。",
      "fp": "s:0123456789abcdef"
    }
  ]
}
```

この `version` は持ち出しの形式の版で、sessionStorage の保存の版とは別。各項目は `target`・`label`・`text`・`fp` と、省略できる `selection`・セル用の `keys` だけにする。`keys` は `row`・`col` の鍵と、省略できる `start`・`dupCol`・`dupRow`。対象は prepare と同じ 4 種類の形を使う。サーバーの token・URL・端末の絶対パスを生成せず、依頼文と ID・描画番号・本文の起動ごとの版・コピーや要確認・今回送らない印・誤りなどの状態を持ち出しの項目に入れない。コメントや選んだ文字など利用者が入力した文字はそのまま入る。

`transferDocument` は URL の `?doc=` を直接使わず、描画で受け取った `file`（ルートからの相対パス、区切りは `/`）を `doc` にする。起動した文書と `?doc=` の文書でも同じ相対パスなら一致し、同名のファイルでも相対パスが違えば断る。無名の描画（`[無名]`）は `null` にするが、無名の文書から依頼文は作れない。ルートの絶対パスや文書全体のハッシュによる識別はせず、取り込み先の描画で対象を照合する。描画が届く前や `file` のない描画ではボタンを無効にし、待つ理由を出す。依頼文の作成中・コピー中・停止後も使えない。

「読み込む」は「書き出したコメントの JSON を貼り付けてください」の入力欄を開き、利用者が Ctrl+V で貼って「足す」を押す。クリップボードの読み取りはしない。「やめる」か貼る欄での Esc は文字を捨てて閉じ、「読み込む」にフォーカスを戻す。IME の変換中の Esc は処理しない。

読み込みは JSON を解析する前に UTF-8 で 4 MiB までに限り、`format`・`version`・`doc`・`items` と、入れ子の対象・境・鍵も含めて許可したキーと型を検査する。コメントと選んだ文字は空白だけを断り 2,000 文字まで、題は 200 文字までで、タブと改行以外の制御文字を断る。`fp` は空か `b:`・`h:`・`c:`・`s:` と小文字の 16 進 16 桁、セルの行列の鍵も小文字の 16 進 16 桁に限る。項目は 200 件まで。1 項目でも不正なら何も足さず、別の `doc` も断る。

今あるカードと読み込む項目の間、および読み込む項目どうしで、同じ対象かつ同じ `text` を重なりとして除く（読み込む項目どうしは先の 1 件だけを足す。画面で同じ対象に同じ文のカードを 2 枚作ると、書き出しには両方が入り、読み込みでは 1 件にまとまる）。選んだ文字や指紋・鍵・コピーの状態が違っていても重なりにする。足す分を決めてから、既存分との合計が保存 200 件・未コピー 50 件を超えないことを確かめ、超えれば何も足さない。既存のカードを置き換えず、足すカードには新しい ID と今の描画番号を付け、未コピー・除外なし・本文の版は空から始める。現在の位置と指紋を確かめ、一致した対象は今の版とセルの鍵に合わせ、見つからない・合わない・指紋が空の対象は要確認にする。古い位置から移動先を探さない。足した件数と重なりの件数を知らせ、追加があったときは保存して古い依頼文を捨てる。追加が 0 件なら作成済みの依頼文を残す。

節へのコメントと持ち出しは、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証。書き出した JSON を別の PC やブラウザーへ移す操作も未検証。

外のアプリを起こすのは、`--review` で起動し、利用者が「コピーして Agents Window を開く」を押した検証済みの launch だけ。実行ファイル・引数・フォルダー・URL をページから受け取らず、prepare で確かめたルートを使う。[公式の起動方法](https://code.visualstudio.com/docs/agents/run/agents-window#_open-the-agents-window)の `code --agents` と、利用者が貼り付けて送る形に限る。公式にない URL の受け口や、依頼文を埋め込む URL は使わない。外の拡張機能や非公開の受け口に依存せず、依頼文が URL やコマンドラインに残ることも避けるため。

## ブラウザの表示

[ページ](../../page/preview.js)は、消毒済みの本文と、見出し・知らせ・ファイル名を別に受け取る。本文以外は `textContent` で入れる。原文を抜き出した知らせには HTML が混ざることがあるため、見出しや通知の表示を通じて HTML として解釈させない。

同じ文書の再描画では、前回の本文の木と新しい木を比べ、変わらない部分の画面の要素を残す。比較する写しは URL とコード配色のクラスを直した直後の形で持ち、数式・図・表の操作が変えた画面の木とは双方向の対応で結ぶ。位置を示す `data-sourcepos`・`data-checkbox-sourcepos` の値だけの変化は、要素を残して属性に反映する。比較用の識別値は子の識別値から一度ずつ作り、大きな部分木を繰り返し比較しない。残した `details` の開閉や、描画済みの数式・図も保ち、配色の変更時は mermaid だけを描き直す。

表と見出し・本体・行の要素はタグが同じなら残し、セルは属性が同じなら子だけを `replaceChildren` で差し替える。子の数が変わったとき、または数は同じでも表の位置がずれたときは、直接の子にある表の数が同じなら、表を目印に前後を分けて更新する（表と段落の順序が入れ替わっても、表を作り直さない）。md-table-sticky が表の前へ置く操作欄とスクロールの包みは一まとまりとして避け、全幅表示中は元の場所の placeholder を差し込み位置にする。セルの子が md-table-sticky の内側の span 一つなら、その span の中を差し替える。これらの内部属性・状態への依存はページの表の固定の節へまとめる。表・行・セルの操作用の style は消さず、子の差し替えによって表の見張りに測り直しを伝える。外す表は表自体を取り除き、操作欄や包みは md-table-sticky 自身の後片付けに任せる。

初回・誤りの表示の前後・文書の変更と、対応する節点や親・並びに食い違いを見つけた場合は、本文を丸ごと入れ替えて対応を作り直す。同じ文書の全置換では、更新前に本文の写しの文書順で `details` と画面の対応から真偽の開閉を集め、新しい `details` の番号順に戻す。全幅表示で本文の外へ移った表の中も元の順で集め、閉じた状態も戻す。差分更新の途中から全置換へ戻るときも、更新を始める前に集めた値を使う。文書が変わったときは引き継がない。部分更新でも全置換でも、外す範囲の読み込み済み PlantUML の画像は同じ URL の新しい図へ使い回す。本文へ追加する節点は、受け取った消毒済み HTML の写しからだけ作る。

ページの JS どうしの接点は `window.gpPreview` に置く。設定・基準 URL・文書名・最後の描画と、元の本文の文書順に並べた画面の表を参照できる。`sourceOf(element)` は、サーバーの HTML の写しと画面の対応から、もとの要素名と公開の位置を `{tag, range}` で返し、写しの節点は外へ渡さない。数式や mermaid の描画結果（mermaid の失敗表示も含む）と PlantUML の失敗表示は、置き換え時に対応を結び直す。位置を持たない要素は中の要素へ読み替えず、数式と図へ置き換えた表示だけ、もとの包みの内側の位置も引く。`findSource(tag, range)` は、この組から今の画面の要素を探す。`htmlOf(element)` は、本文の写しの並びで、その節点を含む最上位の位置のない連なりの前後の境を引き、`{tag: "html", prev, next}` を返す。`findHTML(target)` は、同じ境から今の画面の連なりの要素を返す。どちらも本文の写しの並びで決め、写しの節点は外へ渡さない。`holdScroll(true)` の間はサーバーの scroll イベントだけからスクロールを同期する。`setEditing(true)` の間は表示の層からジャンプを送らず、PlantUML のリンクの扱いを編集の層へ任せる。本文と欄・行対応の同期後、数式や図を非同期に描く前に、描画番号を持つ `gp:render` を document へ通知する。停止時は `gp:stop` を通知し、編集とコメントの UI は別ファイルからこの接点を使う。

[index.html](../../page/index.html) は `preview.js` → `copy-code.js` → `edit-grid.js` → `edit-targets.js` → `edit.js` → `review.js` の順に defer で読み込む。`edit-targets.js` は `gpPreview` の対応から対象のブロック・生の HTML・表の格子を引く `window.gpEditTargets` を用意し、`edit.js` と `review.js` が共用する。`window.gpEditMode` と `window.gpReviewMode` でモードを切り替え、コメントへ入る前に編集の入力や送信が終わっていることを確かめる。

[copy-code.js](../../page/copy-code.js) は、消毒とフィルターを通した本文の `copy-code` をカスタム要素として定義する。ボタンと style は Shadow DOM に置き、本文の子の並びを変えない。これにより本文の写しとの照合を保ち、別の段落の差分更新でも囲みとボタンを残せる。定義済みなら登録を繰り返さない。押した時点の直上の `.markdown-code-block` の `pre > code` の `textContent` を読み、空行・タブ・末尾の空白もそのままコピーする。囲みの記号と言語名は入れない。成功は「コピーしました」、失敗は「コピーできませんでした」とし、成功から 2 秒後に「コピー」へ戻す。

Clipboard API の `writeText` を利用者の操作の中で呼び、無い場合と拒否された場合は body 直下の一時的な textarea で文字だけをコピーし、元のフォーカスを戻す。この一時的な欄も本文の差分更新の対象にしない。`preview.css` は囲みへのマウスの移動かボタンへのフォーカスで右上に出し、印刷では隠す。提案（`suggestion`）には `copy-code` がなく、数式と mermaid の描画後の表示にも残さない。編集とコメントはボタンからのイベントを本文の操作として受け取らない。

見出しへのリンクは `headingLink(index, withFile)` が、見出し欄の番号と最新の描画の見出しの ID が一致することを確かめて作る。ID は表示の文字から作り直さず、同じ題の `-1` なども描画の値を使う。題は見出し欄の `textContent` の空白をまとめて 1 行にし、`\`・`[`・`]` を Markdown 用にエスケープする。ファイル名つきは `last.file` の最後の `/`（念のため `\` も区切りにする）より後ろだけを使い、`[題](ファイル.md#id)`、ID だけは `[題](#id)` にする。ファイル名と ID は別々に `encodeURIComponent` で符号化し、残る `(`・`)` も `%28`・`%29` にする。リンクを作れない理由は `headingLinkReason` がまとめ、無名の文書ではファイル名つきを無効にして、メニューの項目にその理由を出す。

編集モードの外では、見出し欄の項目の右クリック・Shift+F10・メニューキーで本文の外の `gp-heading-link-menu` を開く。編集モードでは [edit.js](../../page/edit.js) の見出しのメニューの末尾に「リンクをコピー（ファイル名つき）」「リンクをコピー（#id）」を置き、同じ `copyHeadingLink` を呼ぶ。レベル変更や削除の可否とは分け、コピーはサーバーへの編集要求を送らない。Clipboard API と body 直下の一時的な入力欄を使い、結果は本文の外の `role="status"` で知らせる。

折りたたみの一括操作は `queryLive('details')` で本文と全幅表示の表の中を集める。対象が無ければボタンを隠し、1 つでも閉じていれば「すべて開く」、全部開いていれば「すべて閉じる」にする。手での開閉も `toggle` で反映する。閉じる直前に取り消しできる `gp:before-details-close` を送り、編集の層は原文の入力対象が閉じた折りたたみの中に隠れる場合に止め、確定か取り消しを案内する。開閉は保存せず、再読み込みでは原文の `open` に従う。

画像の拡大は body 直下の `dialog#gp-image-dialog` に別の img と代替の文字を置く。本文の画像の DOM と差分更新の対応を変えず、相対 URL を直した後の `src` を使う。編集モードとコメントモードの外で、修飾キーのない左クリックだけを受ける。利用者が書いたリンクの中の画像は除き、描画が元の画像と同じ URL で包んだ `a.no-attachment-icon` は扱う。PlantUML・数式・mermaid の画像は除く。Esc・背景・「閉じる」で閉じ、表示用の `src` を外して、元の画像かリンクが残っていればフォーカスを戻す。ダブルクリックの 2 回目（`detail` が 2 以上のクリック）が背景に当たっても閉じない。Esc は全幅表示の表より先に画像を閉じる。編集やコメントへの切り替え、停止、ページを離れるとき、印刷の前（`beforeprint`）にも閉じ、印刷では隠す。

コードと見出しのリンクのコピー、折りたたみの一括操作、画像の拡大は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証。

GitLab との差を知らせる [internal/notices](../../internal/notices/notices.go) は、完成した木を変えない。差の説明を加えるために、比較する本文の構造を変えないため。include の展開後の位置も原文の行へ対応させ、知らせから本文へ移る位置に使う。

配色・本文幅・表の固定と、見出し欄の開閉と幅・知らせの欄の開閉は、そのタブの `sessionStorage` に保存する。見出し欄の幅は `gitlab-preview-appearance` の `outlineWidth` に保存し、読み戻す値は有限の数で 180〜480 px に入るものだけを整数へ丸める。既定は 260 px。

欄と本文の境の `role="separator"` のつまみでドラッグし、←・→ は 10 px、Shift+←・Shift+→ は 50 px、Home・End は最小・上限、Enter とダブルクリックは既定へ戻す。ドラッグ中の Esc・pointercancel・ポインターの捕捉を失った場合は取り消し、ドラッグ中の Esc は編集とコメントより先に受ける。

上限は 480 px と画面の幅から 320 px を引いた値の小さい方（最小は 180 px）で、右のコメント欄を開いているときは 680 px を引く。画面とコメント欄の変化で表示幅と aria の値を当て直し、画面に合わせて狭めただけでは広い画面向けの保存値を変えない。幅 700 px 以下ではつまみを隠し、欄は 42vw にする。

印刷用の CSS では操作欄・見出し欄・つまみ・知らせを隠し、本文を印刷する。HTML への書き出しにも見出し欄とつまみを入れない。[preview.css](../../page/preview.css) は、プレビューの操作と本文のスタイルを分けて持つ。

「表を固定」は、埋め込んだ `sticky/src/sticky-table.js` を実行して表のそばにツールバーを出し、もう一度押すと外す。ブックマークを足さずに使え、同じサーバーから配るので CSP を緩めずに済む。`window.__mdTableSticky` の状態を確かめて必要なときだけ読み、読み込み中は重ねて実行しない。ブックマークレットで先に動かしていても二重に足さず、ボタンとブックマークレットのどちらからでも同じ解除処理で戻す。保存した固定の指定は最初の本文の描画後に当て、ボタンの押下状態は描画のたびに現在の状態から決める。

「検索」の各条件は「列」の選択と文字を持ち、既定は「すべての列」にする。「条件を足す」で空の欄を含めて 5 個まで足し、「条件を消す」で外す（最初の条件は文字と列を空と既定に戻す）。空の条件は使わず、NFKC・小文字・空白をそろえた部分一致で比べる。`columnSearchMatches` は、選んだ列を `colspan` で覆うセルも対象にする。`intersectSearchRows` は各条件で一致したセルの `[row, row + rowspan)` を行の集合にし、条件ごとの集合の交わり（AND）を、結合のまとまりへ広げる前に求める。結合でつながっていても、別の論理行にある条件だけでは一致にしない。

「一致した行だけ表示」は、その交わりの行を `filterRows` へ渡す。見出し・固定する行・`thead`・`tfoot` と、縦の結合や区切りを保つための行は残すが、強調・件数・「前」「次」は交わりの行を覆う一致セルだけを対象にする。チェックなしでは各条件の一致セルの和集合を重複なく行・列の順にたどる。列の選択は位置で持ち、同じ位置の見出しが変われば名前を更新する。列が無くなれば「列 N（現在はありません）」を残して別の列へ切り替えず、文字のあるその条件は一致しない。条件と列の選択は保存せず、閉じると消す。詳しい操作と行を残す規則は [md-table-sticky の設計](../../sticky/docs/reference/design.md#表内検索)にある。

列ごとの絞り込みは mdpreview のページとブックマークレットで同じ原文を使う。ブラウザ試験は mdpreview のページで行っており、gitlab.com の実際の画面、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証。

列幅は md-table-sticky の表の記録だけに持ち、固定を使うかどうかの保存とは別に、保存領域へ書かない。「折り返す」の欄の右端のつまみで 32〜1600 px に変え、手動の幅を当てるセルは折り返す。結合セルは、覆うすべての列を手で決めたときだけ合計の幅にする。覆う列の一部だけを手で決めたときは、幅の数値は当てずに折り返す。本文の差分更新で表と記録を残すため、本文のセルの文字だけの変更では幅を保つ。見出しの文字・開始位置・結合の形が変わった列は自動に戻し、見出しの無い表で列数が変わるとすべて戻す。再読み込みでも自動に戻す。印刷前は手動の幅を外し、印刷後に戻す。幅の当て方と形の判定は [md-table-sticky の設計](../../sticky/docs/reference/design.md#列の幅の調節)にある。

`page/edit.js` は `data-md-table-sticky-resizer` のつまみからの `pointerdown`・`click` を編集として扱わない。`window.__mdTableSticky.resizing` がある間の Esc も編集では処理せず、md-table-sticky の capture の受け手が開始時の幅へ戻す（入力の取り消しや選択の解除は起きない）。ドラッグを離したときの `click` は、つまみと離した位置の共通の祖先へ届く場合がある。先に登録される編集とコメント（`page/review.js`）の capture の受け手は `resizeClick` が真なら処理を譲り、md-table-sticky の受け手がその `click` を 1 回だけ捨てる。これにより、セルの選択を変えず、入力欄の外を押した扱いで入力を確定しない。次の `pointerdown` と `pointerup` 後のタイマーでも待機を解き、後の通常のクリックを妨げない。

列幅のブラウザ試験は GitLab をまねたページで行っており、gitlab.com の実際の画面での列幅は未確認。この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「表の列幅の調節と、版 0.17.0 の配布の検証（2026-11-13）」にある。

## Neovim との取り決め

Neovim の橋渡しは [LazyVimStarter](https://github.com/ryo-aoki-pc/LazyVimStarter) が持ち、アプリは [internal/stdio](../../internal/stdio/stdio.go) で受ける。ファイルの保存を待たずに本文とカーソル位置を受け取るため、`mdpreview --stdio` の標準入力・標準出力に UTF-8 の JSON を 1 行ずつ流す。標準出力には、人が読む案内を混ぜない。

- 取り決めの版は 1。最初の `hello` で版と表示の指定を受け、`ready` で URL を返す。ブラウザは Neovim 側で開く
- `doc` と `scroll` で本文と位置を受ける。休止中の入力は捨て、再開後に受けた本文で描画を戻す。休止しても URL は保つ
- `clients` でタブ数、`jump` で文書のパスと行を返す。ダブルクリックによる移動は、編集中の文書を見ているときだけ有効にする
- 入力の 1 行は 96 MB まで。誤りのある行は捨て、標準入力が閉じたら描画を取り消し、サーバーと描画エンジンも閉じる

ダブルクリックの要求にも、token・送信元・JSON の型と本文の大きさを検査する。ブラウザが渡した任意のパスを、そのままエディタで開く取り決めにはしない。細かな入力と終了の規則は [AGENTS.md](../../AGENTS.md#neovim-との取り決め) にある。

## 公式スタイル

公式の CSS・フォントは、アプリに同梱して再配布せず、利用者が `mdpreview install-style` を実行した端末で取得する。取得の入口を [internal/assets の Install](../../internal/assets/install.go) に分け、プレビューを起こす操作や導入状態の確認に、取得を伴わせない。

[assets.lock.json](../../assets/assets.lock.json) に、元の版・取得元・大きさ・ハッシュ・ライセンスを固定する。保存先はアプリと別の `md-preview-assets` とし、版と lock のハッシュから決めたフォルダーに置く。実行ファイルを更新しても、取得した資産を巻き込まないため。

[internal/assets の Load](../../internal/assets/loaded.go) は通信せず、lock・導入情報・全ファイルの大きさと sha256 を比べる。パスを検査した上で読み、検査したバイト列だけをサーバーへ渡す。導入情報のファイル名をそのまま配信の許可に使わない。

未導入なら同梱のスタイルを使う。導入後は次に起こしたプレビューから公式の CSS と GitLab Sans を使い、コードの配色はライト・ダーク共通の Dracula にする。公式資産を使えない場合も同梱のスタイルで表示を続ける。

## HTML への書き出し

[internal/export](../../internal/export/export.go) は、プレビューと同じ描画の流れとパス検査を使って、消毒済みの本文を単一の HTML にする。サーバーを起こすための URL や操作欄を含めず、`file://` から読む用途にする。

- 入力は UTF-8 のファイル 1 つ、16 MiB まで。描画は `context` の期限で 60 秒で打ち切り、大きさと処理時間に上限を置く
- 同梱スタイルの本文と印刷用の部分を使い、公式資産は含めない。HTML を渡すために、公式資産の再配布を必要としない形にする
- 文書に数式があれば KaTeX と数式のフォント、mermaid の図があれば mermaid を埋める。本文の木に `copy-code` があれば、プレビューと同じ `page/copy-code.js` も埋める。数式・mermaid・`copy-code` のどれも無ければスクリプトを入れず、CSP の `script-src` を `'none'` にする
- PlantUML は手元で描いた SVG を img の data URL に埋め、包む a のリンク先を外す。描けない図は文字のコードブロックに戻して件数を知らせる。PlantUML のためのスクリプトやサーバーの URL は入れない
- コードのコピーは、書き出した HTML でも Shadow DOM の同じボタンと代替のコピーを使う。本文の囲みの中の文字をコピーし、マウスとフォーカスでの表示・成功と失敗の文言・印刷で隠す扱いもプレビューと共通にする
- 埋め込む各スクリプトのバイト列から CSP の sha256 を作る。本文が加えた別のスクリプトを動かす許可にはしない
- ルート内の相対 URL を、書き出し先から見た相対パスに直す。`--embed-images` で埋める画像を除き、メディアのファイルを HTML に埋めたりコピーしたりはしない。リンク先の Markdown をまとめて HTML にする処理もない
- 書き出し先がルートの外のときは、相対 URL を直さない。書き出し先から見た形にすると、ルートより上のフォルダーの名前（利用者名など）が HTML に入り、渡した相手に見えるため
- 入力の Markdown と同じ書き出し先は拒む。引数の書き間違いで、原稿を HTML で上書きしないため
- 出力は隣の一時ファイルへ書き、完成後に入れ替える。作りかけの HTML を出力先へ残すことを避ける

知らせの件数は [CLI](../../internal/cli/cli.go) が標準エラーへ出す。`-o` を省いたときの標準出力には HTML だけを出し、案内が文書に混ざらないようにする。配色の既定は OS に従う `system`、本文幅の既定は全幅の `fluid`。`system` の暗い配色は画面だけに使い、印刷は明るい配色にする。

### 画像の埋め込み

`mdpreview render --embed-images` を指定したときだけ、[images.go](../../internal/export/images.go) が本文の `img` の `src` を data URL にする。処理の順は、消毒済みの HTML の木を作る → PlantUML の図を埋める → 画像を埋める → 残った URL を書き出し先からの相対パスへ直す、にする。フラグなしでは画像を読んで埋め込む処理を通さない。

対象はルート内の通常のファイルの PNG・JPEG・GIF・WebP に限る。パスのクエリーとフラグメントを外して符号化を戻し、文書のフォルダーを基準にして `paths.Resolve` と `resolve.Resolve` で実パスを検査する。同じ実パスは 1 回だけ読み、リンクで同じファイルを指す場合も重ねて読まない。拡張子（`.png`・`.jpg`・`.jpeg`・`.gif`・`.webp`、大文字も認める）と、ファイル先頭の PNG・JPEG・GIF87a / GIF89a・RIFF / WEBP のバイト列の両方で種類を確かめ、一致した参照だけを `data:<MIME>;base64,...` にする。画像の内容全体をデコードして正しさを検査するものではない。

1 枚は 8 MiB、合計は 32 MiB まで。合計は埋めた実ファイルのバイト数を 1 回だけ足し、同じファイルへの参照を重ねて数えない。合計を超える画像を飛ばした後も、残りに収まる画像は埋める。SVG・対応外の種類・種類と拡張子の食い違い・外部 URL・ルートの外や許可しないパス・見つからない画像・読み取れない画像・上限超過は埋めず、通常の URL の書き換えに任せる。動画と音声は対象にしない。本文にもともとある `data:` の画像と、先に埋めた PlantUML はそのままにし、警告もしない。

埋めなかった参照は理由ごとに数え、`画像を埋め込みませんでした（N 件）: <理由>` を標準エラーへ出す。画像の警告だけでは終了コードを失敗にせず、埋められる画像と HTML の書き出しを続ける。警告にファイル名・URL・端末の絶対パスを含めず、外部 URL を取得する通信もしない。

画像を埋めた HTML のブラウザでの表示は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証。

## 導入

利用する端末には実行ファイルを 1 つ置く。描画エンジン・ページ・数式と図のライブラリ・ライセンスの原文を埋め込み、Go・Node.js・Rust やコンテナを利用時の前提にしない。置き場所は `~/.local/bin/mdpreview`（Windows は `%USERPROFILE%\.local\bin\mdpreview.exe`）。取得したファイルを sha256 で確かめ、導入も更新も同じ手順で置く。

配布は [release.yml](../../.github/workflows/release.yml) が `v` + 数字 3 つのタグで行い、`mdpreview` と `mdtable` を 1 つの GitHub Release に置く。[scripts/build-release.sh](../../scripts/build-release.sh) が次の7つを作る。

- `mdpreview-windows-amd64.exe`・`mdpreview-linux-amd64`・`mdpreview-linux-arm64` — 各 OS・CPU 向けの mdpreview
- `mdtable-windows-amd64.exe` — Windows の amd64 向けの mdtable
- `mdpreview-THIRD-PARTY-LICENSES.txt`・`mdtable-THIRD-PARTY-LICENSES.txt` — それぞれの `--licenses` の出力
- `SHA256SUMS` — 上の6つの sha256

版はルートの `internal/version/version.go` で共通にし、[licenses/manifest.json](../../licenses/manifest.json) の md-preview、[mdtable/licenses/manifest.json](../../mdtable/licenses/manifest.json) の md-table-excel、`package.json`・`package-lock.json` に同じ値を記す。

同梱しているもののライセンスは [licenses/](../../licenses/) の一覧と原文で管理し、`mdpreview --licenses` で原文を出す。Go 本体とモジュール・描画エンジン・KaTeX・mermaid の版と原文の対応を試験で確かめる。公式スタイルはこの実行ファイルに入れず、利用者が明示して取得する。
