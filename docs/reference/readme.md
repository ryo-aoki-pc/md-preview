# md-preview の設計

`mdpreview` の設計の判断と理由。導入は [導入と更新](../install.md)、操作は [使い方](../usage.md)、開発で守ることは [AGENTS.md](../../AGENTS.md) にある。

## 描画の流れ

描画は、Markdown を HTML にする段、消毒とフィルターの段、ブラウザに表示する段に分ける。プレビューと HTML への書き出しは、同じ [renderDocument](../../lib/pipeline.mjs) を通す。表示先によって消毒や構文の扱いが変わることを避けるため。

1. CR と front matter を処理し、`::include{file=…}` を展開する
1. GitLab の gem `gitlab-glfm-markdown` のコードを WebAssembly にした [描画エンジン](../../lib/engine.mjs) で HTML にする
1. HTML を木として読み、コードの言語・JSON の表など、GitLab で消毒より前に置かれるフィルターを通す
1. [消毒の規則](../../lib/sanitize.mjs)で、許可していない要素・属性・リンクを除く
1. 数式・図・目次・脚注などを処理し、最後にコードを配色する
1. HTML と、見出し・取り込みの記録・GitLab との違いの知らせを返す

エンジンの出力だけでは消毒が済んでいない。HTML を文字列の置き換えで直さず、木に対して許可リストを適用する。フィルターの順序も GitLab に合わせ、消毒の後ろで足す属性をそれぞれ検査する。コードの配色が作る要素と属性は、その段で値を制限する。

描画の関数は、include の読み込みとメディアの存在確認を、呼ぶ側から渡す関数に任せる。Markdown の処理とファイルを読む権限を分けるため。[worker](../../lib/worker.mjs) は、同じパス検査を通したルート内のファイルだけを、この関数へ渡す。

## GitLab に合わせる範囲と確かめ方

構文解析と整形は、似た解析器で作り直す代わりに GitLab の gem のコードを使う。`glfm.rs`・`formatter.rs` の写しは変更せず、Node.js から呼ぶ入口を付けて WebAssembly にする。gem に渡すオプションの元になる GitLab のソースも保存し、試験で値を比べる。固定した版とハッシュは [engine.lock.json](../../engine/engine.lock.json) にある。

その後ろの Ruby のフィルターは JavaScript に写す。GitLab の利用者・プロジェクト・権限や外部の図サービスが必要な処理は、[pipeline.mjs](../../lib/pipeline.mjs) に省く理由を記す。対応する処理が無い場所を、見た目だけで解決したことにはしない。

[見本との比較](../../test/fixtures.test.mjs)は、合成の Markdown を GitLab が描いた HTML と、手元の最終 HTML を木にして比べる。属性の順、遅延画像、脚注の乱数、絵文字の囲み、コードの配色の字句は、試験で列挙した差だけを正規化する。それ以外の既知の差は、文書・木の場所・理由・両側の値を固定する。参照のリンクを一律に文字へ戻すような、違いを隠す正規化はしない。

見本を作る [開発用スクリプト](../../tools/make-fixtures.mjs)と、保存済みの見本を読む試験を分けている。試験のたびに GitLab に接続せず、同じ入力と出力で比べるため。合わせた範囲と GitLab との差は [README](../../README.md#消毒とフィルター) にある。

## サーバーとファイルを読む範囲

プレビューは [HTTP サーバー](../../lib/server.mjs)を手元に起こす。127.0.0.1 だけで待ち受け、URL に毎回 16 バイトの乱数を 32 桁の 16 進で入れる。ループバックへの待ち受けだけに頼らず、`Host` と `Sec-Fetch-Site` も検査し、CORS の許可を返さない。別のサイトから手元の文書へアクセスさせないための境界にする。

ファイルを開く入口は [resolve()](../../lib/resolve.mjs) に集める。URL のパスを戻し、`..`・バックスラッシュ・`.git`、Windows のドライブやデバイス名として扱われる書き方を拒む。さらに実パスを求めて、ルートの外へ出るリンクも拒む。文字列の上でルートの下に見えるだけでは、配信を認めない。

数式と図のライブラリも、同じサーバーから配る。配信対象は [page/lib/lock.json](../../page/lib/lock.json) にあるファイルに限り、`node_modules` をそのまま公開しない。ページの CSP は `script-src 'self'` とし、文書が任意のスクリプトを読み込む入口を作らない。

## 文書の状態と取り込みの見張り

描画は [session](../../lib/session.mjs) が持つ worker に任せ、文書の更新をまとめる。ブラウザとの通信と Markdown の処理を分け、処理が時間切れになったときに worker を終了できるようにする。

編集中の文書と、相対リンクや一覧から開いたファイル文書は別の状態を持つ。描画の通知は文書ごとに送り、エディタのスクロールは編集中の文書のタブだけへ送る。別の文書を読んでいるタブを、編集中の文書の位置へ動かさないため。

- ファイル文書の監視は 32 件まで。最後のタブが離れて 5 秒後に監視と結果を捨て、読まれていない文書を持ち続けない
- include の展開は [include.mjs](../../lib/include.mjs) で行う。32 回まで・再帰しない・展開後 16 MiB までに制限し、取り込み先からさらに読み込みを広げない
- 取り込み先の監視も、ルートの内側かを検査して文書ごとに 32 個までにする。無いファイルは安全な親の下で出現を待ち、作成されたときにも描き直す
- 編集中の文書を描き直すときは、最後に受けた本文を使う。include が変わったときに、未保存の内容をディスク上の古い本文に戻さない

見張りのパスの検査は [include-watch.mjs](../../lib/include-watch.mjs)、置き換え保存や削除・作成への追従は [watch.mjs](../../lib/watch.mjs) に分けている。

## ブラウザの表示

[ページ](../../page/preview.js)は、消毒済みの本文と、見出し・知らせ・ファイル名を別に受け取る。本文以外は `textContent` で入れる。原文を抜き出した知らせには HTML が混ざることがあるため、見出しや通知の表示を通じて HTML として解釈させない。

GitLab との差を知らせる [notices.mjs](../../lib/notices.mjs) は、完成した木を変えない。差の説明を加えるために、比較する本文の構造を変えないため。include の展開後の位置も原文の行へ対応させ、知らせから本文へ移る位置に使う。

配色・本文幅と、見出し欄・知らせの欄の開閉は `sessionStorage` に保存する。印刷用の CSS では操作欄・見出し欄・知らせを隠し、本文を印刷する。[preview.css](../../page/preview.css) は、プレビューの操作と本文のスタイルを分けて持つ。

## Neovim との取り決め

Neovim の橋渡しは [LazyVimStarter](https://github.com/ryo-aoki-pc/LazyVimStarter) が持ち、アプリは [stdio.mjs](../../lib/stdio.mjs) で受ける。ファイルの保存を待たずに本文とカーソル位置を受け取るため、`mdpreview --stdio` の標準入力・標準出力に UTF-8 の JSON を 1 行ずつ流す。標準出力には、人が読む案内を混ぜない。

- 取り決めの版は 1。最初の `hello` で版と表示の指定を受け、`ready` で URL を返す。ブラウザは Neovim 側で開く
- `doc` と `scroll` で本文と位置を受ける。休止中の入力は捨て、再開後に受けた本文で描画を戻す。休止しても URL は保つ
- `clients` でタブ数、`jump` で文書のパスと行を返す。ダブルクリックによる移動は、編集中の文書を見ているときだけ有効にする
- 入力の 1 行は 96 MB まで。誤りのある行は捨て、標準入力が閉じたらサーバーと worker も閉じる

ダブルクリックの要求にも、token・送信元・JSON の型と本文の大きさを検査する。ブラウザが渡した任意のパスを、そのままエディタで開く取り決めにはしない。細かな入力と終了の規則は [AGENTS.md](../../AGENTS.md#neovim-との取り決め) にある。

## 公式スタイル

公式の CSS・フォントは、アプリに同梱して再配布せず、利用者が `mdpreview install-style` を実行した端末で取得する。取得の入口を [assets/install.mjs](../../assets/install.mjs) に分け、プレビューを起こす操作や導入状態の確認に、取得を伴わせない。

[assets.lock.json](../../assets/assets.lock.json) に、元の版・取得元・大きさ・ハッシュ・ライセンスを固定する。保存先はアプリと別の `md-preview-assets` とし、版と lock のハッシュから決めたフォルダーに置く。アプリの導入先を更新で入れ替えても、取得した資産を巻き込まないため。

[loadAssets](../../lib/assets.mjs) は通信せず、lock・導入情報・全ファイルの大きさと sha256 を比べる。パスを検査した上で読み、検査したバイト列だけをサーバーへ渡す。導入情報のファイル名をそのまま配信の許可に使わない。

未導入なら同梱のスタイルを使う。導入後は次に起こしたプレビューから公式の CSS と GitLab Sans を使い、コードの配色はライト・ダーク共通の Dracula にする。公式資産を使えない場合も同梱のスタイルで表示を続ける。

## HTML への書き出し

[export.mjs](../../lib/export.mjs) は、プレビューと同じ worker とパス検査を使って、消毒済みの本文を単一の HTML にする。サーバーを起こすための URL や操作欄を含めず、`file://` から読む用途にする。

- 入力は UTF-8 のファイル 1 つ、16 MiB まで。worker の描画は 60 秒で打ち切り、大きさと処理時間に上限を置く
- 同梱スタイルの本文と印刷用の部分を使い、公式資産は含めない。HTML を渡すために、公式資産の再配布を必要としない形にする
- 文書に数式があれば KaTeX と数式のフォント、mermaid の図があれば mermaid を埋める。必要なときだけ含め、どちらも無ければスクリプトを入れない
- 埋め込む各スクリプトのバイト列から CSP の sha256 を作る。本文が加えた別のスクリプトを動かす許可にはしない
- ルート内の相対 URL を、書き出し先から見た相対パスに直す。メディアをコピーしたり、リンク先の Markdown をまとめて HTML にしたりはしない
- 書き出し先がルートの外のときは、相対 URL を直さない。書き出し先から見た形にすると、ルートより上のフォルダーの名前（利用者名など）が HTML に入り、渡した相手に見えるため
- 入力の Markdown と同じ書き出し先は拒む。引数の書き間違いで、原稿を HTML で上書きしないため
- 出力は隣の一時ファイルへ書き、完成後に入れ替える。作りかけの HTML を出力先へ残すことを避ける

知らせの件数は [CLI](../../cli.mjs) が標準エラーへ出す。`-o` を省いたときの標準出力には HTML だけを出し、案内が文書に混ざらないようにする。配色の既定は OS に従う `system`、本文幅の既定は全幅の `fluid`。`system` の暗い配色は画面だけに使い、印刷は明るい配色にする。

## 導入

[scripts/setup.mjs](../../scripts/setup.mjs) は、clone をソースの更新に使い、実行するファイルと本番の依存をリポジトリの外に置く。clone の `node_modules` に実行を依存させず、ソースを更新する場所と利用する場所を分けるため。

作業用フォルダーで `npm ci --omit=dev --ignore-scripts` と自己確認を通し、導入情報を記録してから入れ替える。同時実行は鍵で防ぐ。Node.js 22 以上と、同梱した WebAssembly を使うので、利用する端末に Rust やコンテナは要らない。

起動役は `~/.local/bin`（Windows は `%USERPROFILE%\.local\bin`）に置く。Windows では PowerShell・cmd・Git Bash 用を分ける。cmd の文字コードと展開に合わない導入先では cmd 用を作らず、PowerShell と Git Bash 用を置く。導入と更新は同じスクリプトを使い、`--check` では何も変えずに写したファイル・依存・起動役・PATH を確かめる。
