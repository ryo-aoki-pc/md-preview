# md-preview の使い方（AlmaLinux 10・Windows 11）

- Markdown を GitLab の描画でプレビューする `mdpreview` コマンド（[md-preview](../README.md)）。本文は GitLab に送らず、手元で描く
- 導入と更新は [md-preview の導入と更新](install.md) にある
- どの項も単独で通せる。項のリードの前提を先に満たす
- bash のブロックはブラケットペーストの効く端末に、PowerShell のブロックは PowerShell 7 に貼り、貼った後に Enter を押す。貼った後は、反転表示の「確認」から後ろの出力を箇条書きで確かめる
- PowerShell 7 の導入と実行ポリシーは、setup-notes の [アプリを入れる](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/windows-setup.md#アプリを入れる)の手順 6〜9 に従う
- PowerShell の貼り方は [Windows Terminal で複数行を 1 つの入力として貼る](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/shell-terminal.md#windows-terminal-で複数行を-1-つの入力として貼る)に従う

**参照**

- Neovim の導入は、setup-notes の [LazyVim の GitLab プレビューを導入する](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/neovim.md#lazyvim-の-gitlab-プレビューを導入する)・[Windows 11 で LazyVim の GitLab プレビューを導入する](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/neovim.md#windows-11-で-lazyvim-の-gitlab-プレビューを導入する)に従う
- 外へ通信する場面は [README](../README.md#外へ通信する場面) にある

- PlantUML のコードブロックは、`plantuml` コマンドが PATH にあれば、手元で SVG にして表示する（Windows 11 の導入は [Windows 11 で PlantUML を入れる](install.md#windows-11-で-plantuml-を入れる)）。コマンドが無い場合、`--no-plantuml` を付けた場合、原文が 256 KiB を超える場合は、コードブロックのまま表示し、「GitLab との違い」の「図」で知らせる
- `--no-plantuml` はプレビュー・`--stdio`・`render` で使える。SVG にならなかった図は、原文のコードブロックで表示する。`render` では描けた SVG を HTML の画像に埋め、描けなかった図の件数を標準エラーへ知らせる。図の原文は外へ送らず、図の中から手元のファイルや URL を読む記法も止める
- 編集モードの外では、Neovim から使うとき（ダブルクリックで行へ移れるとき）は、PlantUML の図のダブルクリックでエディタの行へ移り、クリックでは SVG を新しいタブで開かない。単体のプレビューでは、クリックで SVG を新しいタブで開く
- 編集モードの間は、PlantUML の図のクリックでは SVG を開かず、数式と図のダブルクリックで囲みを含む原文を開く。Neovim から使うときも、エディタの行へ移らず原文を開く

## AlmaLinux 10 で使う

- GNOME にログインした自分のユーザーで行う。前提の項は、各項のリードのリンクから開く

### mdpreview で Markdown をプレビューする

- 試験用の小さな Markdown を作り、ブラウザで表示を確かめる
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、プレビューを起こす。

   ```bash
   (
     # 試験用の Markdown を、専用のフォルダーに作って開く
     preview_dir=$(mktemp -d) || exit
     trap 'rm -rf -- "$preview_dir"' EXIT
     printf '# プレビューの確認\n\n本文です。\n' > "$preview_dir/preview.md" || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --no-open "$preview_dir/preview.md"
   )
   ```

   - `プレビュー: http://127.0.0.1:<ポート>/<32 桁の 16 進>/` の形の URL が出ればよい
   - エラーが出たら、中断して [導入の手順](install.md#md-preview-を導入更新する)で導入状態を確かめる

1. ブラウザで、この項の手順 1 に出た URL を開く。

   - 本文に「プレビューの確認」と「本文です。」が出ればよい
   - 操作欄の左に `preview.md` と出ればよい

1. ブラウザの操作欄で、表示を切り替える。

   - 「一覧」でルート内の Markdown の一覧を開き、ファイル名を押して文書を開く
   - 「見出し」で、左の見出し欄を出し入れする。見出しを押すと、本文のその見出しへ移る
   - 「表を固定」で、表のそばにツールバーを出す。もう一度押すと外す
   - 「配色」でシステム・ライト・ダーク、「本文幅」で全幅・固定幅を選ぶ
   - 「GitLab との違い <件数>」があれば押す。種類ごとの見出しと「<行番号> 行: <抜き出し>」を読み、行を押して本文の該当する行へ移る
   - 別の Markdown を指す相対リンクがある文書では、そのリンクを押して同じタブで移る。ブラウザの戻る・進むで行き来する
   - 印刷するときは、ブラウザの印刷を開いて本文を確かめる

1. プレビューを起こした端末で、Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

<details id="mdpreview-で-markdown-をプレビューする-の補足と注意点">
  <summary>mdpreview で Markdown をプレビューする の補足と注意点</summary>

**[mdpreview で Markdown をプレビューする](#mdpreview-で-markdown-をプレビューする)の手順 1**

- `--no-open` を外すと、既定のブラウザを開く。`--browser <実行ファイル>` で別のブラウザを指定する
- 試験用の Markdown を専用のフォルダーに作るのは、そのフォルダーがルートになるため（「一覧」に出るのは、その中の Markdown だけ）。止めると、フォルダーごと消す
- 自分の文書を開くときは、試験用ファイルの代わりに Markdown のパスを渡す。保存すると描き直す。未保存の内容を見るときは Neovim から使う
- フォルダーを開く形は `mdpreview docs`。指定したフォルダーをルートにし、最初に一覧を出す。`--root` とは併用しない
- ファイルを渡したときのルートは、上へたどって最初に `.git` があるフォルダー。無ければ、そのファイルのあるフォルダー。`--root <フォルダー>` で変えられる
- 画像・動画・音声・別の文書・include で読めるのはルート内のファイルだけ。`.git` の中は読まない
- `--port <番号>` で待ち受けるポートを指定する。省略すると空いているポートを選ぶ
- `::include{file=…}` で取り込むファイルの変更・削除・作成にも合わせて描き直す
- 公式スタイルは任意。[md-preview の公式スタイルを取得する](install.md#md-preview-の公式スタイルを取得する)に従う

**[mdpreview で Markdown をプレビューする](#mdpreview-で-markdown-をプレビューする)の手順 3**

- 「GitLab との違い」は、知らせが 1 件以上あるときだけ出る。この項の試験用文書には、知らせの対象になる記法を入れていない
- 数式は KaTeX、mermaid のコードブロックは mermaid で描く。どちらも同じサーバーから配る同梱のライブラリを使う
- 印刷用の表示では、操作欄・見出し欄・知らせを隠す

</details>

### mdpreview のプレビューで表を編集する

- パイプの表と結合セルのある HTML の表、表の外のブロックの原文、タスクのチェックボックスを、プレビューの画面で直してファイルに書く
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、編集を有効にしてプレビューを起こす。

   ```bash
   (
     # 試験用の Markdown を、専用のフォルダーに作って開く。止めたときに、書き込まれた内容を出してから消す
     preview_dir=$(mktemp -d) || exit
     trap 'printf "\n\033[7m 保存された内容 \033[0m\n"; cat -- "$preview_dir/edit.md"; rm -rf -- "$preview_dir"' EXIT
     printf '%s\n' \
       '# 表の編集の確認' '' \
       '編集する段落。' '' '- [ ] 作業' '' \
       '| 名前 | 個数 |' '| --- | --- |' '| りんご | 1 |' '| みかん | 2 |' '' \
       '<table>' '<tbody>' \
       '<tr><td rowspan="2">結合したセル</td><td>右上</td></tr>' \
       '<tr><td>右下</td></tr>' \
       '</tbody>' '</table>' > "$preview_dir/edit.md" || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --edit --no-open "$preview_dir/edit.md"
   )
   ```

   - `プレビュー: http://127.0.0.1:<ポート>/<32 桁の 16 進>/` の形の URL が出ればよい
   - エラーが出たら、中断して [導入の手順](install.md#md-preview-を導入更新する)で導入状態を確かめる

1. ブラウザで、この項の手順 1 に出た URL を開き、操作欄の「編集」を押す。

   - 表が 2 つ出て、「編集」が押された状態になればよい
   - 上の表の「りんご」をクリックする。そのセルに枠が付き、画面の下に操作欄が出ればよい

1. セルを直し、行を足して、元に戻す。

   - 「りんご」をダブルクリックし、「青りんご」に直して Enter を押す。表の文字が「青りんご」に変わればよい
   - 「青りんご」をクリックし、画面の下の「行」→「下に挿入」を押す。その下に空の行が足されればよい
   - 「元に戻す」を押す。足した行が消えればよい

1. 行を複製し、コピーした行を挿入する。

   - 「青りんご」をクリックし、「行」→「複製」を押す。すぐ下に同じ行が増え、「元に戻す」1 回で戻ればよい
   - 「青りんご」をクリックし、「行」→「コピー」を押す。「みかん」をクリックし、「行」→「コピーした 1 行を下に挿入」を押す。その下に「青りんご」の行が増えればよい
   - 「元に戻す」を押し、挿入した行を戻す

1. 段落の原文を直し、タスクのチェックボックスを切り替える。

   - 「編集する段落。」をダブルクリックし、「直した段落。」に直して Ctrl+Enter を押す。段落が「直した段落。」に変わればよい
   - 「作業」のチェックボックスをクリックする。チェックが付けばよい

1. 「表を固定」で全幅表示にしたまま、セルを直す。

   - 操作欄の「表を固定」を押し、下の表のツールバーの「全幅で表示」を押す
   - 「右上」をダブルクリックし、「右上（変更）」に直して Enter を押す。入力欄が全幅表示の上に出て、確定の後も全幅表示のままならよい
   - 入力を確定した状態で Esc を押す。挿入の待機・切り取り・範囲が無ければ、選択の枠と全幅表示が同じ押下で閉じればよい

1. プレビューを起こした端末で、Ctrl+C を押して止める。

   - 「保存された内容」の下に出る Markdown に、「青りんご」・「右上（変更）」・「直した段落。」・`- [x] 作業` が入っていればよい
   - コマンドの入力に戻ればよい

<details id="mdpreview-のプレビューで表を編集する-の補足と注意点">
  <summary>mdpreview のプレビューで表を編集する の補足と注意点</summary>

**[mdpreview のプレビューで表を編集する](#mdpreview-のプレビューで表を編集する)の手順 1**

- 自分の文書には `mdpreview --edit README.md`、フォルダーには `mdpreview --edit docs` を使う。フォルダーでは一覧から文書を選ぶ。`--edit` がなければ編集ボタンも書き込みもない
- Neovim から使うとき（LazyVimStarter の `<leader>cp`）は、`--edit` は要らない。「編集」で直した内容は Neovim のバッファへ入り、ファイルには書かない（保存は `:w`、取り消しは `u`。画面に「元に戻す」「やり直し」は出ない）。編集できるのは、Neovim で開いている文書だけ。Neovim の側でバッファを変えた直後や、変更できないバッファでは、編集を断って理由を知らせる。`vim.g.gitlab_preview_edit = false` で無効にできる
- 画面の編集は直ちにファイルへ書く。BOM とファイルの権限を保ち、隣の一時ファイルから入れ替えるため、ハードリンクは切れ、同じ実体を指していた別名には反映しない。Windows でそのファイルだけに付けたアクセス権（ACL）と、Linux の所有者・拡張属性は、引き継がれないことがある
- 取り込んだ include 先・JSON から作った表・入れ子の表・対応を確かめられない表は編集できない。UTF-8 でないファイル・単独の CR で行の対応がずれる文書・16 MiB を超える文書も対象外
- セル用 Markdown を同じ描画に書き戻せない内容、壊れた HTML の原文、表の外へはみ出す貼り付けなどは書かず、理由を知らせる。ファイルを外で変えた場合も上書きしない
- 取り消しの履歴は文書ごとに200手・全体で32 MiBまで。プレビューを終了すると失われる。外で変わったファイルには古い履歴を適用しない

**[mdpreview のプレビューで表を編集する](#mdpreview-のプレビューで表を編集する)の手順 3〜5**

| 状態 | 操作 | 動き |
| --- | --- | --- |
| 選択中 | 矢印 | 結合セルを一つとして隣へ移る |
| 選択中 | Tab / Shift+Tab | 次 / 前のセルへ移る。行の端では行をまたぐ |
| 選択中 | Shift+矢印 / Shift+クリック | 同じ表で選択範囲を伸縮する。結合セルの途中を切る範囲はコピーできない |
| 選択中 | Enter・F2・ダブルクリック | 今の文字を残して編集する |
| 選択中 | 文字入力・単一の文字列の貼り付け | 今の文字を置き換える編集を始める |
| 選択中 | Delete / Backspace | 範囲の全セル / 活動中の 1 セルを空にして書く |
| 選択中 | Ctrl+Z / Ctrl+Y・Ctrl+Shift+Z | 元に戻す / やり直す |
| 選択中 | Ctrl+C | 範囲をコピーする。文字は引用符付き TSV、2 セル以上は HTML、mdpreview 向けには原文・属性を保つ写しも渡す |
| 選択中 | Ctrl+X | コピーして破線の切り取りの印を付ける。同じ文書へ貼ると移動する |
| 選択中 | Ctrl+V / Ctrl+Shift+V | 範囲の左上へ写し / 文字だけを貼る。行列を挿入するときは「貼り付けて…に挿入…」で先に待機する |
| 選択中 | 右クリック / Shift+F10・メニューキー | セルのメニューを開く。行・列の操作は子のメニューから選ぶ |
| 選択中 | Esc | メニュー → 挿入の待機 → 切り取りの印 → 範囲を 1 セルへ → 選択の解除の順に一つずつ解く。最後は同じ押下で全幅表示も閉じる |
| 編集中 | Enter / Shift+Enter | 確定して下 / 上へ移る |
| 編集中 | Tab / Shift+Tab | 確定して次 / 前へ移る |
| 編集中 | Alt+Enter | セル内に改行を入れる |
| 編集中 | Esc | 入力を取り消して選択へ戻る。全幅表示は続く |
| HTML の原文を編集中 | Enter / Ctrl+Enter | 改行 / 確定 |
| ブロックの原文を編集中 | Enter / Ctrl+Enter（macOS は Cmd+Enter も） | 改行 / 確定 |
| ブロックの原文を編集中 | Alt+↑ | 1 つ外側のブロックへ移る。入力は確定しない |
| ブロックの原文を編集中 | Alt+↓ | 移る前の内側のブロックへ戻る。入力は確定しない |
| ブロックの原文を編集中 | Esc / 入力欄の外のクリック | 入力とその対象の下書きを取り消す / 確定。選択は残さない |
| ブロックを追加中 | Enter / Ctrl+Enter（macOS は Cmd+Enter も） | 改行 / 確定 |
| ブロックを追加中 | Esc / 入力欄の外のクリック | 取り消し / 文字があれば確定、無ければ取り消し |
| タスクのチェックボックス | クリック / フォーカス中の Space | チェックを切り替える。`[~]` は対象外 |

- 入力欄に出るのは、セル用 Markdown（`**太字**` などの記法のまま。セル内の改行は改行）。パイプの表では、縦棒は `\|`、改行は `<br>` にして書く
- タブや改行を含む貼り付け（Excel でコピーした範囲など）は、選んだセルを左上にして複数のセルへ入れる。引用符で囲んだ改行・タブ・二重の引用符にも対応する。貼り付ける値もセル用 Markdown として読む（`a*b*c` は強調になる）。編集中の貼り付けは入力欄に入る
- 行・列の操作は画面下の「行」「列」のメニューか、セルの右クリックから選ぶ。無効な項目もキーで選べて、メニューの下に理由を出す。削除の確認窓は出ない。「元に戻す」で戻す
- 結合セルの途中を切るコピー・切り取り・複製は断る。結合全体を含むように選び直す。パイプの表の見出し行を複製・挿入すると見出し直下のデータ行になり、見出し行の上への挿入・削除・行の切り取りはできない。表の検索で隠れた行をまたぐ範囲は、検索を解除してから選び直す
- 「コピーした…を挿入」は、このページで最後にコピーした内容を使う。ほかのタブや Excel の内容は「貼り付けて…に挿入…」を選び、Ctrl+V を押す。メニューからはブラウザーの決まりでクリップボードを読めないため、セルの「貼り付け」は無効で、Ctrl+V を案内する
- 同じ文書の有効な切り取りは、貼ると元を消して移動する。ほかのセルの編集などで描画が変わると取り消されるので、もう一度切り取る。別の文書への切り取りはコピーとして貼り、元を消さない
- 別の文書からの参照リンク・脚注・相対パスは、貼り付け先の文書で解釈される。貼った後にリンク先などを確かめる。原文を保てないセル、または大きすぎる範囲（10000 セル超・写しが UTF-8 で 1.5 MiB 超）は、値だけをコピーして知らせる。大きさの上限を超える場合は独自の形式を付けない。Windows 11 の Edge と Excel で、結合とセル内の改行のある範囲を Excel へ貼ると結合と改行が再現されること、Excel でコピーした行を「貼り付けて下に挿入…」と Ctrl+V で貼れることを確かめた（`repos/md-tools/docs/verification/readme.md` の「表の範囲のコピー・貼り付けと Excel（0.4.0）」）。Excel for Mac・LibreOffice と、AlmaLinux 10 のブラウザでのクリップボードは未検証
- HTML の表では「原文を編集」を使える。セル用 Markdown に直すと形が変わるセルは、通常の編集でも原文を開く
- 表の外は、段落・見出し・リストの項目と全体・説明リストの用語と説明と全体・引用・コードブロック・数式のブロック・図（mermaid・PlantUML）・水平線・注記・脚注の定義の Markdown の原文と、本文のいちばん外側の生の HTML のブロックを編集できる
- ダブルクリックで、押した所のいちばん内側のブロックを開く。リストの項目の文字なら子のリストを含む項目、項目の中の段落ならその段落だけを開く
- 本文のいちばん外側に書いた `<details>…</details>`・`<div align="center">…</div>`・位置のない `<p>`・`<br>`・`<img>` などの生の HTML のブロックは、題名（`summary`）や文字をダブルクリックすると全体の原文を開く
- 生の HTML の原文には、開始タグから閉じタグまでと、その間の Markdown が入る。Ctrl+Enter で確定すると置き換わる
- 生の HTML のブロックが段落などを挟まずに続くときは、まとめて 1 つとして開く。HTML のブロックの直後に空行なしで続く文字も入る
- 生の HTML のブロックのすぐ前後の HTML のコメント（`<!-- … -->`）も原文に入り、そのまま直せる。空行で区切られ、生の HTML の外にあるリンクの参照の定義・脚注の定義だけの段は入らない
- `<details>` の中に空行を挟んで書いた段落・リスト・コードなどは、それぞれをダブルクリックで開ける。「HTML のブロック全体を編集」か Alt+↑ で全体へ移り、「内側に戻る」か Alt+↓ で戻ると、入力途中の文字が残っている
- リスト・引用・注記などの中の生の HTML は、それだけを開けない。ダブルクリックでは外側の項目などを開き、その原文として直す。生の HTML の表（`<table>`）は、表のセルとして編集する
- 目次（`[[_TOC_]]`）のすぐ隣の生の HTML は、ブロック全体を開けない
- include の展開・front matter に掛かる範囲、続きの行のある脚注の定義など、取り除くとほかの描画が変わる行を挟む範囲は、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- 生の HTML 全体を開く際、利用者が書いた `data-sourcepos` を含むブロックや、前後の境の位置が利用者の書いた属性である場合も、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- マウスを載せると、ダブルクリックで開く対象に破線の枠が出る。数式と図はその表示、水平線は線、項目は項目、注記の題名は注記全体に出る。生の HTML の位置のない要素では、まとめて開く要素の全部に出る
- ` ```math `・`$$…$$` の数式のブロック、mermaid の図、`plantuml` コマンドで描いた PlantUML の図をダブルクリックすると、囲みを含む原文を開く。Ctrl+Enter で確定すると置き換えて描き直す。`$$…$$` は段落として開く
- 水平線（`---`・`***`・`___` など）をダブルクリックすると原文を開く。確定すると置き換わり、段落や見出しにも書き換えられる。編集モードの間は、線の上下の余白も押せる。線の見た目は変わらない
- 水平線で終わる項目と、そのリストも開ける。原文には水平線の行まで入る
- 行の中の数式（`$x$`）をダブルクリックすると、その段落を開く
- mermaid と PlantUML の図を描けなかった表示からも、ダブルクリックで原文を開いて直せる。数式と図のライブラリを読み込んでいる間も、同じ対象を開ける
- 数式と図の描き直しや配色の切り替えで表示が置き換わっても、入力欄は閉じず、その対象に付いていく。文書が外で変わったときは、入力欄を閉じ、入力途中の文字を下書きに残す
- 注記の題名や余白を押すと、注記全体を開く。`> [!note]`・`>>> [!note]` の種類と題名の行、`>>>` の閉じの行を含む全体を直せる
- 入力欄のそばの操作欄のボタンか Alt+↑ で、1 つ外側のブロックへ移る。項目が 1 つだけのリストのように、内側と同じ範囲になる外側は飛ばす
- ボタンは外側の種類に合わせて「リスト全体を編集」「引用全体を編集」「説明リスト全体を編集」「注記全体を編集」「項目全体を編集」「説明全体を編集」「HTML のブロック全体を編集」、ほかは「外側のブロックを編集」と出る
- 「内側に戻る」か Alt+↓ で、移る前の内側のブロックへ戻る。移るときは入力途中の文字を確定せずに残し、戻ると入力欄に出す。IME の変換中は移らない
- ブロックの原文を開くと、入力欄のそばの操作欄に「前に追加」「後ろに追加」が出る。押すと、編集中の入力は確定せず下書きに残り、空の入力欄が開く。右下の札は「追加」になる
- 追加の入力欄は、いちばん外側のブロックの上か下に出る。リストの項目ならリスト全体、引用の中の段落なら引用全体の前後に追加する
- 生の HTML のブロック全体を開いているときは、その全体の前後に追加する。中の段落などを開いているときは、生の HTML の中で、その対象の前後に追加する
- 追加は Ctrl+Enter（macOS は Cmd+Enter も）で確定し、Esc で取り消す。入力欄の外をクリックすると、文字があれば確定し、無ければ取り消す。追加中は、外側・内側へ移るボタンと Alt+↑・Alt+↓ は使えない
- 追加する文の前後の空行は除き、前後のブロックとの間に空行を 1 行ずつ置く。既に空行があれば足さず、文書の先頭・末尾の側にも足さない。改行（LF・CRLF）はその場所に合わせる
- 追加した文が前後のブロックに取り込まれたり、前後を巻き込んだりする場合は、「追加した文が前後のブロックに取り込まれます。」と知らせ、書き込まず入力を残す
- 後ろに内容がある所へ閉じていないコードの囲み（` ``` ` だけ）・`>>>`・`<details>` を足すと断られる。リストのすぐ後ろへの字下げした文や項目（`- b`）の追加も断られる。リストに項目を足すときは、リスト全体を開いて書き足す
- 文書の最後の生の HTML のブロックの前に、閉じない要素（`<div>` だけ、など）を足して既存のブロックを取り込む場合も断られる
- 空白だけの追加は、「追加する文を入力してください。」と知らせて断る
- 表のセルと脚注の定義には追加のボタンが出ない。表の前後には、前後のブロックから追加する。include 先・front matter、範囲を確かめられないいちばん外側のブロック、生の HTML に `data-sourcepos` を書いた要素からも追加できない
- ファイルを編集しているときは、追加も「元に戻す」「やり直し」で 1 手として戻せる。Neovim にはバッファの 1 個の行の置き換えとして届き、`u` で戻せる
- 空行なしの説明リストの用語は、描画エンジンの位置を編集の側で正して開く
- `>>>` の引用の中の最後の項目など、範囲を確かめられないブロックを押すと、開ける外側のブロックを開いて知らせる。外側もなければ、理由を知らせて開かない
- 生の HTML に `data-sourcepos`・`data-checkbox-sourcepos` を書いた要素は、描画エンジンが付けた位置と区別できないので編集できない。同じ要素名・同じ位置を持つ本物の要素も編集できなくなる
- 脚注の定義の中を押すと、ラベル `[^1]:` を含む定義全体を開き、「ラベルを変えると、本文の参照と対応しなくなります」と知らせる
- 脚注のラベルを変えて確定すると、置き換えた上で「脚注のラベルが変わりました。本文の参照を確かめてください。」と知らせる。脚注の中の段落だけは編集できない
- 編集モードの間は、原文を直せる所のリンクを押しても移動しない。PlantUML の図のクリックで SVG を開く操作と、Neovim のエディタの行へ移る操作も止め、図のダブルクリックで原文を開く。リンクで移るときは、「編集」をもう一度押して編集モードを出る
- Ctrl などを押しながらのリンクのクリックは止めないので、新しいタブで開ける
- 目次・include 先・front matter は画面から編集できない。リスト・引用などの中の生の HTML だけを開くこともできない。表と脚注の中のタスクのチェックボックスも切り替えられない
- 表と脚注の中の数式と図は、それだけを開いて編集できない。脚注の定義は、ラベルを含む全体を開く
- 原文の取得や書き込みを断ったときは、理由を知らせる。Ctrl・Shift・Alt を押しながらのダブルクリックでは、編集を始めない
- 編集モードと表の固定は再読み込み後もそのタブに覚える。実際の IME の操作は未検証で、変換のイベントを合成したブラウザ試験だけを行っている

</details>

### mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る

- 本文にコメントをため、計画を頼む依頼文をコピーして、文書のルートで開いた VS Code の Agents Window に貼って送る
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある。Agents Window を開くには、VS Code の `code` コマンドも PATH にあること。Copilot のセッションを使うときは、VS Code で Copilot にサインインしておく
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. コメントを付ける Markdown のパスを入力し、プレビューを起こす。パスは引用符を付けずに入力する。

   ```bash
   (
     # コメントを付ける文書を選び、コメントを有効にして開く
     read -er -p 'Markdown のパス: ' review_file || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --review "$review_file"
   )
   ```

   - ブラウザで文書が開き、操作欄に「コメント」が出ればよい
   - エラーが出たら、中断して文書のパスと [導入の手順](install.md#md-preview-を導入更新する)で導入状態を確かめる

1. 操作欄の「コメント」を押す。

   - 右にコメントの欄が出ればよい。狭い画面では下に出る

1. 本文のブロックか表のセルを押す。文字を引用したいときは、1 つの対象の中で文字を選ぶ。

   - 欄に選んだ対象が出ればよい。文字も選んだ場合は「選んだ文字」に出る
   - コメントを付けられない所は、理由の知らせを確かめ、対象を選び直す

1. 欄にコメントを書き、「追加」を押す。Ctrl+Enter でも追加できる。

   - コメントのカードが「未コピー」で出ればよい
   - この項の手順 3〜4 を、必要なコメントの数だけ繰り返す

1. 「依頼文を作る」を押し、依頼文の対象のファイル・行・原文と、コメントを確かめる。

   - 先頭が `/plan` で、まず計画だけを示す依頼文が出ればよい
   - 「要確認」や「誤り」のカードがあれば、対象やコメントを直して、依頼文を作り直す

1. 「コピーして Agents Window を開く」を押す。

   - 依頼文がコピーされ、文書のルートで VS Code の Agents Window が開けばよい（AlmaLinux 10 での VS Code の起動は未検証。この項の補足を見る）
   - 初めて開くフォルダーでは、作者を信頼するかの確認が出る。フォルダーと内容を確かめてから進む

1. Agents Window で、セッションの種類を Copilot か Claude、作業場所を Branch にする。

   - 開いたフォルダーがプレビューのルートであることを確かめる
   - Git の文書では、Branch は今のフォルダーを直接直す。New Worktree は別の worktree で直す

1. Agents Window の入力欄に Ctrl+V で依頼文を貼り、内容を確かめて Enter で送る。

   - `/plan` を含めて貼る。Agents Window のエージェントの一覧から Plan を探す操作は要らない

1. 返ってきた計画を確かめ、直す範囲と内容がよければ実装を承認する。

   - 実装後に、直した内容と差分を確かめる
   - Branch でプレビューと同じファイルが保存されると、直した結果がプレビューに出ることを確かめる

1. 終わったら、プレビューを起こした端末で Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

<details id="mdpreview-のプレビューでコメントを付けてvs-code-の-agents-window-へ送る-の補足と注意点">
  <summary>mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る の補足と注意点</summary>

**[mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る](#mdpreview-のプレビューでコメントを付けてvs-code-の-agents-window-へ送る)の手順 1**

- `--review` は単体ファイルとフォルダーのプレビューで使う。Neovim から開くプレビュー（`--stdio`）では使えない
- `--edit --review` を付けると、「編集」と「コメント」を切り替えて使える。同時には使えず、編集の入力中は切り替えない。編集を確定するか取り消してから「コメント」を押す
- ファイルを渡したときのルートは、上へたどって最初に `.git` があるフォルダー。無ければ、そのファイルのあるフォルダー。`--root <フォルダー>` で変えられる。Agents Window もこのルートで開く

**[mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る](#mdpreview-のプレビューでコメントを付けてvs-code-の-agents-window-へ送る)の手順 3〜5**

- 段落・見出し・リスト・引用・コード・数式のブロック・図・水平線・注記・脚注の定義と、最上位の生の HTML の連なり、表のセルが対象になる。「表を固定」で固定・全幅表示にした表のセルにも付けられる
- include 先・front matter・JSON からできた表・入れ子の表、原文との対応や範囲を確かめられない対象は使えない。理由の知らせを確かめる
- 「選んだ文字」は表示の文字の引用。原文の文字の位置を指すものではなく、依頼文の位置はそのブロックの行（セルでは表全体の行）になる。複数の対象にまたがる文字は添えられない
- カードの「直す」でコメントや対象を直し、「消す」でそのカードを消し、「本文へ移る」で対象を表示する。「未コピー」はまだ依頼文をコピーしていないコメント、「コピー済み」はコピーしたコメント。「要確認」は対象が消えたか、表を確かめられなくなったもの。「誤り」は依頼文を作るときに断られた理由を示す
- 「依頼文を作る」は未コピーのコメントをまとめる。「コピー済みを消す」はコピー済みのカードを消す。コピー済みは、エージェントへ送ったことや実装が済んだことを示さない
- コメントは文書ごとに、そのタブの sessionStorage に保存する。同じタブの再読み込みでは読み戻すが、永続的な保存や別のタブとの共有には使わない
- 1 回の依頼は 50 件まで。コメントと「選んだ文字」はそれぞれ 2,000 文字まで。原文の抜粋は各 4 KiB までで、超えたら入る範囲の先頭と末尾の行を残して省略する。依頼文全体が 64 KiB を超えると作らないので、コメントを分ける
- 行は 1 から数え、終わりの行も含む。include の展開前の原文を、front matter の行も含めて数える。ファイルが外で変わったときは、最新の表示を確かめて依頼文を作り直す

**[mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る](#mdpreview-のプレビューでコメントを付けてvs-code-の-agents-window-へ送る)の手順 6〜9**

- VS Code が無い、`code` が PATH に無い、または起動できない場合は知らせが出る。依頼文はコピー済みなので、自分で開いた入力欄へ貼れる。Agents Window を開く必要がなければ、「コピー」だけを使う
- コピーに失敗した場合は、依頼文の欄が選択される。Ctrl+C でコピーする
- 同じ依頼文で Agents Window を開くのは 1 回だけ。起動を待つ間はボタンが押せない。開いた後に押し直すと、起こし直さずに「Agents Window はもう開いています。」と出る。別のタブから同じ依頼文で同時に押すと「Agents Window を開いています。」と出るので、少し待つ。期限切れの知らせが出たら「依頼文を作る」を押し直す
- [VS Code の公式の説明](https://code.visualstudio.com/docs/agents/run/agents-window#_limitations)では、Agents Window のプランモードは Copilot か Claude のセッションで `/plan` を使う。エージェントの一覧に Plan は無い
- New Worktree を選ぶと別のファイルを直すので、その結果は今のプレビューに出ない。今のプレビューで確かめるときは Branch を使う
- mdpreview は AI の API へ送らず、利用者が依頼文を貼って送る。依頼文に端末の絶対パスとサーバーの token は入れない
- Windows 11・VS Code 1.145.3 で、画面のボタンから文書の Git のルートで Agents Window が開くことと、新しいフォルダーの信頼の確認を確かめた。Copilot・Claude へ実際に送って計画が返ること、AlmaLinux 10 での VS Code の起動、実際の IME、手で操作するブラウザでの一連の手順は未検証
- 検証記録は、`repos/md-tools/docs/verification/readme.md` の「画面のコメントと Agents Window への送付と、版 0.14.0 の配布の検証（2026-11-13）」にある

</details>

### mdpreview で Markdown を HTML に書き出す

- 試験用の Markdown を HTML に書き出し、ブラウザで開く
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、HTML に書き出す。

   ```bash
   # 試験用の Markdown を HTML に書き出す
   preview_dir=$(mktemp -d) &&
     printf '# 書き出しの確認\n\n本文です。\n' > "$preview_dir/preview.md" &&
     mdpreview render -o "$preview_dir/preview.html" "$preview_dir/preview.md"
   ```

   - エラーなく終われば、この項の手順 2 へ進む
   - エラーが出たら、中断して入力ファイルと書き出し先を確かめる

1. 書き出したファイルを確かめる。

   ```bash
   printf '\n\033[7m 確認 \033[0m\n'
   ls -l -- "$preview_dir/preview.html"
   ```

   - `preview.html` があり、大きさが 0 より大きければよい
   - 表示されたファイルのパスを、この項の手順 3 で使う

1. ブラウザで、書き出した HTML を開く。

   - Ctrl+O を押し、この項の手順 2 で確かめたファイルを開く
   - 本文に「書き出しの確認」と「本文です。」が出ればよい

1. 試験用のフォルダーを消す。

   ```bash
   # この項の手順 1 で作った試験用のフォルダーを消す
   [ -n "${preview_dir:-}" ] && rm -r -- "$preview_dir"
   unset preview_dir
   ```

   - 何も出なければよい
   - この項の手順 1 と同じ端末で行う（別の端末では、消すフォルダーが分からない）

<details id="mdpreview-で-markdown-を-html-に書き出す-の補足と注意点">
  <summary>mdpreview で Markdown を HTML に書き出す の補足と注意点</summary>

**[mdpreview で Markdown を HTML に書き出す](#mdpreview-で-markdown-を-html-に書き出す)の手順 1**

- 自分の文書を使う形は `mdpreview render -o preview.html README.md`。`-o` を省くと標準出力に HTML を書く。書き出し先のフォルダーは先に用意する
- 知らせがあれば、標準エラーに種類ごとの件数を出す。例は `mdpreview: 参照: 2 件`、`mdpreview: 見つからないメディア: 1 件`。ほかの種類の名前は「図」「提案」「取り込み」「絵文字」と、件数が多くて省いた分の「省略した知らせ」
- `--theme system|light|dark` で配色、`--width fluid|fixed` で本文幅を選ぶ。既定は `system`（OS に従う）と `fluid`（全幅）
- `system` の暗い配色は画面だけに使い、印刷は明るい配色にする
- `--root <フォルダー>` でルートを指定できる。省略したときのルートの決め方はプレビューと同じ
- ルート内の相対パスの画像・動画・音声・リンクは、書き出し先から見た相対パスに直す。メディアのファイル自体は HTML に埋め込まない
- 書き出し先がルートの外のときは、相対パスを文書のフォルダーから見た形のままにし、そのことを標準エラーに知らせる（書き出し先から見た形にすると、ルートより上のフォルダーの名前が HTML に入るため）。リンクと画像を合わせるには、ルートの中へ書き出す
- 入力の Markdown と同じファイルは、書き出し先にできない
- 別の Markdown へのリンクもファイルへのリンクとして残る。リンク先の HTML をまとめて作る機能はない
- 公式スタイルを導入していても、書き出しには同梱のスタイルを使う。必要な KaTeX・mermaid と数式のフォントを埋め込む。数式も図も無ければスクリプトを入れない
- mermaid の図があると、ライブラリを埋め込むため HTML が大きくなる。数式と図を含む文書を書き出した例では約 6.2 MB

**[mdpreview で Markdown を HTML に書き出す](#mdpreview-で-markdown-を-html-に書き出す)の手順 3**

- サーバーを起こさず、`file://` から開く。HTML とメディアを別の場所へ移すときは、相対パスの関係を保つ

</details>

### Windows 11 の mdpreview で Markdown をプレビューする

- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く

1. 管理者ではない PowerShell 7 を開く。

1. 試験用の Markdown を作り、プレビューを起こす。

   ```powershell

       New-Item -ItemType Directory -Path $previewDirectory -ErrorAction Stop | Out-Null
       Set-Content -LiteralPath "$previewDirectory\preview.md" -Value "# プレビューの確認`n`n本文です。" -Encoding utf8 -ErrorAction Stop
   ```

1. プレビューを起こした PowerShell 7 で、Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

- 数式は KaTeX、mermaid のコードブロックは mermaid で描く。どちらも同じサーバーから配る同梱のライブラリを使う
- 印刷用の表示では、操作欄・見出し欄・知らせを隠す

### Windows 11 の mdpreview のプレビューで表を編集する

- パイプの表と結合セルのある HTML の表、表の外のブロックの原文、タスクのチェックボックスを、プレビューの画面で直してファイルに書く
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く

1. 管理者ではない PowerShell 7 を開く。

   - スタートメニューで「PowerShell」を探し、クリックして開く（「Windows PowerShell」ではない。「管理者として実行」にはしない）
   - 「PowerShell」が無ければ、[アプリを入れる](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/windows-setup.md#アプリを入れる)の手順 6〜9 を通す

1. 試験用の Markdown を作り、編集を有効にしてプレビューを起こす。

   ```powershell
   & {
     # 試験用の Markdown を、専用のフォルダーに作って開く。止めたときに、書き込まれた内容を出してから消す
     $previewDirectory = Join-Path ([IO.Path]::GetTempPath()) ("md-preview-" + [guid]::NewGuid())
     try {
       New-Item -ItemType Directory -Path $previewDirectory -ErrorAction Stop | Out-Null
       $lines = @(
         '# 表の編集の確認', '',
         '編集する段落。', '', '- [ ] 作業', '',
         '| 名前 | 個数 |', '| --- | --- |', '| りんご | 1 |', '| みかん | 2 |', '',
         '<table>', '<tbody>',
         '<tr><td rowspan="2">結合したセル</td><td>右上</td></tr>',
         '<tr><td>右下</td></tr>',
         '</tbody>', '</table>'
       )
       Set-Content -LiteralPath "$previewDirectory\edit.md" -Value $lines -Encoding utf8 -ErrorAction Stop
       "`n$([char]27)[7m 確認 $([char]27)[0m"
       mdpreview --edit --no-open "$previewDirectory\edit.md"
     } finally {
       if (Test-Path -LiteralPath "$previewDirectory\edit.md") {
         Write-Host "`n$([char]27)[7m 保存された内容 $([char]27)[0m"
         Write-Host (Get-Content -LiteralPath "$previewDirectory\edit.md" -Raw -Encoding utf8)
       }
       Remove-Item -LiteralPath $previewDirectory -Recurse -Force -ErrorAction SilentlyContinue
     }
   }
   ```

   - `プレビュー: http://127.0.0.1:<ポート>/<32 桁の 16 進>/` の形の URL が出ればよい

1. ブラウザで、この項の手順 2 に出た URL を開き、操作欄の「編集」を押す。

   - 表が 2 つ出て、「編集」が押された状態になればよい

   - 「青りんご」をクリックし、画面の下の「行」→「下に挿入」を押す。その下に空の行が足されればよい
   - 「元に戻す」を押す。足した行が消えればよい

1. 行を複製し、コピーした行を挿入する。

   - 「青りんご」をクリックし、「行」→「複製」を押す。すぐ下に同じ行が増え、「元に戻す」1 回で戻ればよい

<details id="windows-11-の-mdpreview-のプレビューで表を編集する-の補足と注意点">
  <summary>Windows 11 の mdpreview のプレビューで表を編集する の補足と注意点</summary>

**[Windows 11 の mdpreview のプレビューで表を編集する](#windows-11-の-mdpreview-のプレビューで表を編集する)の手順 2**

- 自分の文書には `mdpreview --edit README.md`、フォルダーには `mdpreview --edit docs` を使う。フォルダーでは一覧から文書を選ぶ。`--edit` がなければ編集ボタンも書き込みもない
- Neovim から使うとき（LazyVimStarter の `<leader>cp`）は、`--edit` は要らない。「編集」で直した内容は Neovim のバッファへ入り、ファイルには書かない（保存は `:w`、取り消しは `u`。画面に「元に戻す」「やり直し」は出ない）。編集できるのは、Neovim で開いている文書だけ。Neovim の側でバッファを変えた直後や、変更できないバッファでは、編集を断って理由を知らせる。`vim.g.gitlab_preview_edit = false` で無効にできる
- 画面の編集は直ちにファイルへ書く。BOM とファイルの権限を保ち、隣の一時ファイルから入れ替えるため、ハードリンクは切れ、同じ実体を指していた別名には反映しない。Windows でそのファイルだけに付けたアクセス権（ACL）と、Linux の所有者・拡張属性は、引き継がれないことがある
- include 先・JSON の表・入れ子の表・原文と対応を確かめられない表は編集できない。UTF-8 でないファイル・単独の CR で行の対応がずれる文書・16 MiB を超える文書も対象外
- セル用 Markdown を同じ描画に書き戻せない内容、壊れた HTML の原文、表の外へはみ出す貼り付けなどは書かず、理由を知らせる。外で変わったファイルも上書きしない
- 取り消しの履歴は文書ごとに200手・全体で32 MiBまで。終了すると失われ、外で変わったファイルには適用しない

**[Windows 11 の mdpreview のプレビューで表を編集する](#windows-11-の-mdpreview-のプレビューで表を編集する)の手順 4〜6**

| 選択中 | Tab / Shift+Tab | 次 / 前のセルへ移る。行の端では行をまたぐ |
| 選択中 | Shift+矢印 / Shift+クリック | 同じ表で選択範囲を伸縮する。結合セルの途中を切る範囲はコピーできない |
| 選択中 | Enter・F2・ダブルクリック | 今の文字を残して編集する |
| 選択中 | 文字入力・単一の文字列の貼り付け | 今の文字を置き換える編集を始める |

| 編集中 | Tab / Shift+Tab | 確定して次 / 前へ移る |
| 編集中 | Alt+Enter | セル内に改行を入れる |
| 編集中 | Esc | 入力を取り消して選択へ戻る。全幅表示は続く |
| HTML の原文を編集中 | Enter / Ctrl+Enter | 改行 / 確定 |
| ブロックの原文を編集中 | Enter / Ctrl+Enter（macOS は Cmd+Enter も） | 改行 / 確定 |
| ブロックの原文を編集中 | Alt+↑ | 1 つ外側のブロックへ移る。入力は確定しない |
| ブロックの原文を編集中 | Alt+↓ | 移る前の内側のブロックへ戻る。入力は確定しない |
| ブロックの原文を編集中 | Esc / 入力欄の外のクリック | 入力とその対象の下書きを取り消す / 確定。選択は残さない |
| ブロックを追加中 | Enter / Ctrl+Enter（macOS は Cmd+Enter も） | 改行 / 確定 |
| ブロックを追加中 | Esc / 入力欄の外のクリック | 取り消し / 文字があれば確定、無ければ取り消し |
| タスクのチェックボックス | クリック / フォーカス中の Space | チェックを切り替える。`[~]` は対象外 |

- 入力欄に出るのは、セル用 Markdown（`**太字**` などの記法のまま。セル内の改行は改行）。パイプの表では、縦棒は `\|`、改行は `<br>` にして書く
- タブや改行を含む貼り付け（Excel でコピーした範囲など）は、選んだセルを左上にして複数のセルへ入れる。引用符で囲んだ改行・タブ・二重の引用符にも対応する。貼り付ける値もセル用 Markdown として読む（`a*b*c` は強調になる）。編集中の貼り付けは入力欄に入る
- 行・列の操作は画面下の「行」「列」のメニューか、セルの右クリックから選ぶ。無効な項目もキーで選べて、メニューの下に理由を出す。削除の確認窓は出ない。「元に戻す」で戻す
- 結合セルの途中を切るコピー・切り取り・複製は断る。結合全体を含むように選び直す。パイプの表の見出し行を複製・挿入すると見出し直下のデータ行になり、見出し行の上への挿入・削除・行の切り取りはできない。表の検索で隠れた行をまたぐ範囲は、検索を解除してから選び直す
- 「コピーした…を挿入」は、このページで最後にコピーした内容を使う。ほかのタブや Excel の内容は「貼り付けて…に挿入…」を選び、Ctrl+V を押す。メニューからはブラウザーの決まりでクリップボードを読めないため、セルの「貼り付け」は無効で、Ctrl+V を案内する
- 同じ文書の有効な切り取りは、貼ると元を消して移動する。ほかのセルの編集などで描画が変わると取り消されるので、もう一度切り取る。別の文書への切り取りはコピーとして貼り、元を消さない
- 別の文書からの参照リンク・脚注・相対パスは、貼り付け先の文書で解釈される。貼った後にリンク先などを確かめる。原文を保てないセル、または大きすぎる範囲（10000 セル超・写しが UTF-8 で 1.5 MiB 超）は、値だけをコピーして知らせる。大きさの上限を超える場合は独自の形式を付けない。Windows 11 の Edge と Excel で、結合とセル内の改行のある範囲を Excel へ貼ると結合と改行が再現されること、Excel でコピーした行を「貼り付けて下に挿入…」と Ctrl+V で貼れることを確かめた（`repos/md-tools/docs/verification/readme.md` の「表の範囲のコピー・貼り付けと Excel（0.4.0）」）。Excel for Mac・LibreOffice と、AlmaLinux 10 のブラウザでのクリップボードは未検証
- HTML の表では「原文を編集」を使える。セル用 Markdown に直すと形が変わるセルは、通常の編集でも原文を開く
- 表の外は、段落・見出し・リストの項目と全体・説明リストの用語と説明と全体・引用・コードブロック・数式のブロック・図（mermaid・PlantUML）・水平線・注記・脚注の定義の Markdown の原文と、本文のいちばん外側の生の HTML のブロックを編集できる
- ダブルクリックで、押した所のいちばん内側のブロックを開く。リストの項目の文字なら子のリストを含む項目、項目の中の段落ならその段落だけを開く
- 本文のいちばん外側に書いた `<details>…</details>`・`<div align="center">…</div>`・位置のない `<p>`・`<br>`・`<img>` などの生の HTML のブロックは、題名（`summary`）や文字をダブルクリックすると全体の原文を開く
- 生の HTML の原文には、開始タグから閉じタグまでと、その間の Markdown が入る。Ctrl+Enter で確定すると置き換わる
- 生の HTML のブロックが段落などを挟まずに続くときは、まとめて 1 つとして開く。HTML のブロックの直後に空行なしで続く文字も入る
- 生の HTML のブロックのすぐ前後の HTML のコメント（`<!-- … -->`）も原文に入り、そのまま直せる。空行で区切られ、生の HTML の外にあるリンクの参照の定義・脚注の定義だけの段は入らない
- `<details>` の中に空行を挟んで書いた段落・リスト・コードなどは、それぞれをダブルクリックで開ける。「HTML のブロック全体を編集」か Alt+↑ で全体へ移り、「内側に戻る」か Alt+↓ で戻ると、入力途中の文字が残っている
- リスト・引用・注記などの中の生の HTML は、それだけを開けない。ダブルクリックでは外側の項目などを開き、その原文として直す。生の HTML の表（`<table>`）は、表のセルとして編集する
- 目次（`[[_TOC_]]`）のすぐ隣の生の HTML は、ブロック全体を開けない
- include の展開・front matter に掛かる範囲、続きの行のある脚注の定義など、取り除くとほかの描画が変わる行を挟む範囲は、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- 生の HTML 全体を開く際、利用者が書いた `data-sourcepos` を含むブロックや、前後の境の位置が利用者の書いた属性である場合も、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- マウスを載せると、ダブルクリックで開く対象に破線の枠が出る。数式と図はその表示、水平線は線、項目は項目、注記の題名は注記全体に出る。生の HTML の位置のない要素では、まとめて開く要素の全部に出る
- ` ```math `・`$$…$$` の数式のブロック、mermaid の図、`plantuml` コマンドで描いた PlantUML の図をダブルクリックすると、囲みを含む原文を開く。Ctrl+Enter で確定すると置き換えて描き直す。`$$…$$` は段落として開く
- 水平線（`---`・`***`・`___` など）をダブルクリックすると原文を開く。確定すると置き換わり、段落や見出しにも書き換えられる。編集モードの間は、線の上下の余白も押せる。線の見た目は変わらない
- 水平線で終わる項目と、そのリストも開ける。原文には水平線の行まで入る
- 行の中の数式（`$x$`）をダブルクリックすると、その段落を開く
- mermaid と PlantUML の図を描けなかった表示からも、ダブルクリックで原文を開いて直せる。数式と図のライブラリを読み込んでいる間も、同じ対象を開ける
- 数式と図の描き直しや配色の切り替えで表示が置き換わっても、入力欄は閉じず、その対象に付いていく。文書が外で変わったときは、入力欄を閉じ、入力途中の文字を下書きに残す
- 注記の題名や余白を押すと、注記全体を開く。`> [!note]`・`>>> [!note]` の種類と題名の行、`>>>` の閉じの行を含む全体を直せる
- 入力欄のそばの操作欄のボタンか Alt+↑ で、1 つ外側のブロックへ移る。項目が 1 つだけのリストのように、内側と同じ範囲になる外側は飛ばす
- ボタンは外側の種類に合わせて「リスト全体を編集」「引用全体を編集」「説明リスト全体を編集」「注記全体を編集」「項目全体を編集」「説明全体を編集」「HTML のブロック全体を編集」、ほかは「外側のブロックを編集」と出る
- 「内側に戻る」か Alt+↓ で、移る前の内側のブロックへ戻る。移るときは入力途中の文字を確定せずに残し、戻ると入力欄に出す。IME の変換中は移らない
- ブロックの原文を開くと、入力欄のそばの操作欄に「前に追加」「後ろに追加」が出る。押すと、編集中の入力は確定せず下書きに残り、空の入力欄が開く。右下の札は「追加」になる
- 追加の入力欄は、いちばん外側のブロックの上か下に出る。リストの項目ならリスト全体、引用の中の段落なら引用全体の前後に追加する
- 生の HTML のブロック全体を開いているときは、その全体の前後に追加する。中の段落などを開いているときは、生の HTML の中で、その対象の前後に追加する
- 追加は Ctrl+Enter（macOS は Cmd+Enter も）で確定し、Esc で取り消す。入力欄の外をクリックすると、文字があれば確定し、無ければ取り消す。追加中は、外側・内側へ移るボタンと Alt+↑・Alt+↓ は使えない
- 追加する文の前後の空行は除き、前後のブロックとの間に空行を 1 行ずつ置く。既に空行があれば足さず、文書の先頭・末尾の側にも足さない。改行（LF・CRLF）はその場所に合わせる
- 追加した文が前後のブロックに取り込まれたり、前後を巻き込んだりする場合は、「追加した文が前後のブロックに取り込まれます。」と知らせ、書き込まず入力を残す
- 後ろに内容がある所へ閉じていないコードの囲み（` ``` ` だけ）・`>>>`・`<details>` を足すと断られる。リストのすぐ後ろへの字下げした文や項目（`- b`）の追加も断られる。リストに項目を足すときは、リスト全体を開いて書き足す
- 文書の最後の生の HTML のブロックの前に、閉じない要素（`<div>` だけ、など）を足して既存のブロックを取り込む場合も断られる
- 空白だけの追加は、「追加する文を入力してください。」と知らせて断る
- 表のセルと脚注の定義には追加のボタンが出ない。表の前後には、前後のブロックから追加する。include 先・front matter、範囲を確かめられないいちばん外側のブロック、生の HTML に `data-sourcepos` を書いた要素からも追加できない
- ファイルを編集しているときは、追加も「元に戻す」「やり直し」で 1 手として戻せる。Neovim にはバッファの 1 個の行の置き換えとして届き、`u` で戻せる
- 空行なしの説明リストの用語は、描画エンジンの位置を編集の側で正して開く
- `>>>` の引用の中の最後の項目など、範囲を確かめられないブロックを押すと、開ける外側のブロックを開いて知らせる。外側もなければ、理由を知らせて開かない
- 生の HTML に `data-sourcepos`・`data-checkbox-sourcepos` を書いた要素は、描画エンジンが付けた位置と区別できないので編集できない。同じ要素名・同じ位置を持つ本物の要素も編集できなくなる
- 脚注の定義の中を押すと、ラベル `[^1]:` を含む定義全体を開き、「ラベルを変えると、本文の参照と対応しなくなります」と知らせる
- 脚注のラベルを変えて確定すると、置き換えた上で「脚注のラベルが変わりました。本文の参照を確かめてください。」と知らせる。脚注の中の段落だけは編集できない
- 編集モードの間は、原文を直せる所のリンクを押しても移動しない。PlantUML の図のクリックで SVG を開く操作と、Neovim のエディタの行へ移る操作も止め、図のダブルクリックで原文を開く。リンクで移るときは、「編集」をもう一度押して編集モードを出る
- Ctrl などを押しながらのリンクのクリックは止めないので、新しいタブで開ける
- 目次・include 先・front matter は画面から編集できない。リスト・引用などの中の生の HTML だけを開くこともできない。表と脚注の中のタスクのチェックボックスも切り替えられない
- 表と脚注の中の数式と図は、それだけを開いて編集できない。脚注の定義は、ラベルを含む全体を開く
- 原文の取得や書き込みを断ったときは、理由を知らせる。Ctrl・Shift・Alt を押しながらのダブルクリックでは、編集を始めない
- 編集モードと表の固定は再読み込み後もそのタブに覚える。実際の IME の操作は未検証で、変換のイベントを合成したブラウザ試験だけを行っている

</details>

### Windows 11 の mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る

- 本文にコメントをため、計画を頼む依頼文をコピーして、文書のルートで開いた VS Code の Agents Window に貼って送る
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある。Agents Window を開くには、VS Code の `code` コマンドも PATH にあること。Copilot のセッションを使うときは、VS Code で Copilot にサインインしておく
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く

1. 管理者ではない PowerShell 7 を開く。

   - スタートメニューで「PowerShell」を探し、クリックして開く（「Windows PowerShell」ではない。「管理者として実行」にはしない）
   - 「PowerShell」が無ければ、[アプリを入れる](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/windows-setup.md#アプリを入れる)の手順 6〜9 を通す

1. コメントを付ける Markdown のパスを入力し、プレビューを起こす。パスは引用符を付けずに入力する。

   ```powershell
   & {
     # コメントを付ける文書を選び、コメントを有効にして開く
     $reviewFile = Read-Host 'Markdown のパス'
     "`n$([char]27)[7m 確認 $([char]27)[0m"
     mdpreview --review $reviewFile
   }
   ```

   - ブラウザで文書が開き、操作欄に「コメント」が出ればよい
   - エラーが出たら、中断して文書のパスと [導入の手順](install.md#windows-11-で-md-preview-を導入更新する)で導入状態を確かめる

1. 操作欄の「コメント」を押す。

   - 右にコメントの欄が出ればよい。狭い画面では下に出る

1. 本文のブロックか表のセルを押す。文字を引用したいときは、1 つの対象の中で文字を選ぶ。

   - 欄に選んだ対象が出ればよい。文字も選んだ場合は「選んだ文字」に出る
   - コメントを付けられない所は、理由の知らせを確かめ、対象を選び直す

1. 欄にコメントを書き、「追加」を押す。Ctrl+Enter でも追加できる。

   - コメントのカードが「未コピー」で出ればよい
   - この項の手順 4〜5 を、必要なコメントの数だけ繰り返す

1. 「依頼文を作る」を押し、依頼文の対象のファイル・行・原文と、コメントを確かめる。

   - 先頭が `/plan` で、まず計画だけを示す依頼文が出ればよい
   - 「要確認」や「誤り」のカードがあれば、対象やコメントを直して、依頼文を作り直す

1. 「コピーして Agents Window を開く」を押す。

   - 依頼文がコピーされ、文書のルートで VS Code の Agents Window が開けばよい
   - 初めて開くフォルダーでは、作者を信頼するかの確認が出る。フォルダーと内容を確かめてから進む

1. Agents Window で、セッションの種類を Copilot か Claude、作業場所を Branch にする。

   - 開いたフォルダーがプレビューのルートであることを確かめる
   - Git の文書では、Branch は今のフォルダーを直接直す。New Worktree は別の worktree で直す

1. Agents Window の入力欄に Ctrl+V で依頼文を貼り、内容を確かめて Enter で送る。

   - `/plan` を含めて貼る。Agents Window のエージェントの一覧から Plan を探す操作は要らない

1. 返ってきた計画を確かめ、直す範囲と内容がよければ実装を承認する。

   - 実装後に、直した内容と差分を確かめる
   - Branch でプレビューと同じファイルが保存されると、直した結果がプレビューに出ることを確かめる

1. 終わったら、プレビューを起こした端末で Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

- 行は 1 から数え、終わりの行も含む。include の展開前の原文を、front matter の行も含めて数える。ファイルが外で変わったときは、最新の表示を確かめて依頼文を作り直す

- VS Code が無い、`code` が PATH に無い、または起動できない場合は知らせが出る。依頼文はコピー済みなので、自分で開いた入力欄へ貼れる。Agents Window を開く必要がなければ、「コピー」だけを使う
- コピーに失敗した場合は、依頼文の欄が選択される。Ctrl+C でコピーする
- 同じ依頼文で Agents Window を開くのは 1 回だけ。起動を待つ間はボタンが押せない。開いた後に押し直すと、起こし直さずに「Agents Window はもう開いています。」と出る。別のタブから同じ依頼文で同時に押すと「Agents Window を開いています。」と出るので、少し待つ。期限切れの知らせが出たら「依頼文を作る」を押し直す

- mdpreview は AI の API へ送らず、利用者が依頼文を貼って送る。依頼文に端末の絶対パスとサーバーの token は入れない

### Windows 11 の mdpreview で Markdown を HTML に書き出す

- 試験用の Markdown を HTML に書き出し、ブラウザで開く
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く
- PowerShell のリダイレクトで HTML を保存せず、`-o` で書き出し先を指定する

1. 管理者ではない PowerShell 7 を開く。

   - スタートメニューで「PowerShell」を探し、クリックして開く（「Windows PowerShell」ではない。「管理者として実行」にはしない）
   - 「PowerShell」が無ければ、[アプリを入れる](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/windows-setup.md#アプリを入れる)の手順 6〜9 を通す

1. 試験用の Markdown を作り、HTML に書き出す。

   ```powershell
   # 試験用の Markdown を HTML に書き出す
   $previewDirectory = Join-Path ([IO.Path]::GetTempPath()) ("md-preview-" + [guid]::NewGuid())
   & {
     New-Item -ItemType Directory -Path $previewDirectory -ErrorAction Stop | Out-Null
     Set-Content -LiteralPath "$previewDirectory\preview.md" -Value "# 書き出しの確認`n`n本文です。" -Encoding utf8 -ErrorAction Stop
     mdpreview render -o "$previewDirectory\preview.html" "$previewDirectory\preview.md"
     if ($LASTEXITCODE -ne 0) { return }
     "`n$([char]27)[7m 確認 $([char]27)[0m"
     Get-Item -LiteralPath "$previewDirectory\preview.html" | Format-List FullName, Length
   }
   ```

   - `preview.html` のパスと、0 より大きい大きさが出ればよい
   - 表示されたファイルのパスを、この項の手順 3 で使う
   - エラーが出たら、中断して入力ファイルと書き出し先を確かめる

1. ブラウザで、書き出した HTML を開く。

   - Ctrl+O を押し、この項の手順 2 で確かめたファイルを開く
   - 本文に「書き出しの確認」と「本文です。」が出ればよい

1. 試験用のフォルダーを消す。

   ```powershell
   # この項の手順 2 で作った試験用のフォルダーを消す
   if ($previewDirectory) { Remove-Item -LiteralPath $previewDirectory -Recurse; $previewDirectory = $null }
   ```

   - 何も出なければよい
   - この項の手順 2 と同じ PowerShell 7 の窓で行う（別の窓では、消すフォルダーが分からない）

<details id="windows-11-の-mdpreview-で-markdown-を-html-に書き出す-の補足と注意点">
  <summary>Windows 11 の mdpreview で Markdown を HTML に書き出す の補足と注意点</summary>

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)のリード**

- PowerShell の版によっては、パイプやリダイレクトが文字コードや改行を変える。`-o` ならアプリが UTF-8 の HTML を直接書く

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)の手順 2**

- 自分の文書を使う形は `mdpreview render -o preview.html README.md`。`-o` を省くと標準出力に HTML を書く。書き出し先のフォルダーは先に用意する
- 知らせがあれば、標準エラーに種類ごとの件数を出す。例は `mdpreview: 参照: 2 件`、`mdpreview: 見つからないメディア: 1 件`。ほかの種類の名前は「図」「提案」「取り込み」「絵文字」と、件数が多くて省いた分の「省略した知らせ」
- `--theme system|light|dark` で配色、`--width fluid|fixed` で本文幅を選ぶ。既定は `system`（OS に従う）と `fluid`（全幅）
- `system` の暗い配色は画面だけに使い、印刷は明るい配色にする
- `--root <フォルダー>` でルートを指定できる。省略したときのルートの決め方はプレビューと同じ
- ルート内の相対パスの画像・動画・音声・リンクは、書き出し先から見た相対パスに直す。メディアのファイル自体は HTML に埋め込まない
- 書き出し先がルートの外のときは、相対パスを文書のフォルダーから見た形のままにし、そのことを標準エラーに知らせる（書き出し先から見た形にすると、ルートより上のフォルダーの名前が HTML に入るため）。リンクと画像を合わせるには、ルートの中へ書き出す
- 入力の Markdown と同じファイルは、書き出し先にできない
- 別の Markdown へのリンクもファイルへのリンクとして残る。リンク先の HTML をまとめて作る機能はない
- 公式スタイルを導入していても、書き出しには同梱のスタイルを使う。必要な KaTeX・mermaid と数式のフォントを埋め込む。数式も図も無ければスクリプトを入れない
- mermaid の図があると、ライブラリを埋め込むため HTML が大きくなる。数式と図を含む文書を書き出した例では約 6.2 MB

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)の手順 3**

- サーバーを起こさず、`file://` から開く。HTML とメディアを別の場所へ移すときは、相対パスの関係を保つ

</details>
