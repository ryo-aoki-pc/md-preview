# md-preview の使い方（AlmaLinux 10・Windows 11）

- Markdown を GitLab の描画でプレビューする `mdpreview` コマンド（[md-preview](../README.md)）。本文は GitLab に送らず、手元で描く
- 導入と更新は [md-preview の導入と更新](install.md) にある
- どの項も単独で通せる。項のリードの前提を先に満たす
- bash のブロックはブラケットペーストの効く端末に、PowerShell のブロックは PowerShell 7 に貼り、貼った後に Enter を押す。貼った後は、反転表示の「確認」から後ろの出力を箇条書きで確かめる
- [PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)が入っていて、実行ポリシーが `RemoteSigned`（`Unrestricted`・`Bypass` でもよい）であることを確かめてある
- PowerShell の貼り方は [Windows Terminal で複数行を 1 つの入力として貼る](https://github.com/ryo-aoki-pc/setup-notes/blob/main/docs/shell-terminal.md#windows-terminal-で複数行を-1-つの入力として貼る)に従う

## AlmaLinux 10 で使う

- GNOME にログインした自分のユーザーで行う。前提の項は、各項のリードのリンクから開く

### mdpreview で Markdown をプレビューする

- 試験用の小さな Markdown を作り、ブラウザで表示を確かめる
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、プレビューを起こす。

   ```bash
   (
     # 試験用の Markdown を、専用のフォルダーに作って開く
     preview_dir=$(mktemp -d) || exit
     trap 'rm -rf -- "$preview_dir"' EXIT
     printf '# プレビューの確認\n\n本文です。\n\n[リンク切れの確認](missing.txt)\n\n| 品名 | 説明 |\n| --- | --- |\n| りんご | 青森県で採れた、甘みと酸味のつりあった果物 |\n\n    echo 確認\n\n<details>\n<summary>補足</summary>\n\n折りたたんだ本文です。\n\n</details>\n' > "$preview_dir/preview.md" || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --no-open "$preview_dir/preview.md"
   )
   ```

   - `プレビュー: http://127.0.0.1:<ポート>/<32 桁の 16 進>/` の形の URL が出ればよい
   - エラーが出たら、中断して [導入の手順](install.md#md-preview-を導入更新する)で導入状態を確かめる

1. ブラウザで、この項の手順 1 に出た URL を開く。

   - 本文に「プレビューの確認」と「本文です。」と、「品名」「説明」の表が出ればよい
   - 操作欄の左に `preview.md` と出ればよい

1. ブラウザの操作欄で、表示を切り替える。

   - 「一覧」でルート内の Markdown の一覧を開き、ファイル名を押して文書を開く
   - 「見出し」で、左の見出し欄を出し入れする。見出しを押すと、本文のその見出しへ移る
   - 見出し欄の「プレビューの確認」を右クリックし、「リンクをコピー（ファイル名つき）」を押す。このページの外の文字を入力できる所（テキストエディターなど）に貼り、`[プレビューの確認](preview.md#…)` の形になればよい。「リンクをコピー（#id）」では `[プレビューの確認](#…)` になる。`…` は描画された見出しの ID を符号化した文字になる
   - 見出し欄と本文の境のつまみを左右へドラッグし、欄の幅を変える。つまみをダブルクリックすると既定の幅に戻る
   - コードブロックにマウスを載せ、右上の「コピー」を押す。「コピーしました」と出たらこのページの外の文字を入力できる所（テキストエディターなど）に貼り、囲みの中の文字と同じならよい。Tab でボタンへフォーカスして Enter でもコピーできる
   - 「すべて開く」を押す。「補足」の本文が出て、ボタンが「すべて閉じる」になればよい。押し直して折りたたむ
   - 画像のある文書では、編集モードとコメントモードの外で画像をクリックする。大きく出た画像を、Esc・背景・「閉じる」で閉じる
   - 「表を固定」で、表のそばにツールバーと列ごとの「折り返す」の欄を出す。もう一度押すと外す
   - 表のツールバーの「検索」を押し、「列」で「列 1（品名）」を選んで「りんご」を入力する。「条件を足す」で 2 つ目の条件を出し、「列 2（説明）」で「青森」を探す。「一致した行だけ表示」にチェックを入れ、りんごの行が残ればよい
   - 2 つ目の文字を「みかん」に変え、本文の行が隠れて「0 件」になればよい。その条件の「条件を消す」でりんごの行を戻し、「前」「次」で一致したセルへ移る。検索の「閉じる」で、すべての行を戻す
   - 「折り返す」の各ラベルの右端の縦の線（つまみ）を左右へドラッグして列幅を変える。つまみにフォーカスすると、←・→ で 10 px、Shift+←・Shift+→ で 50 px ずつ変わる。ドラッグ中に Esc を押すと開始時の幅へ戻る
   - つまみにフォーカスして Delete を押すか、つまみをダブルクリックすると、その列が自動の幅へ戻る。2 つの列の幅を変えた後、「列幅を戻す」で全列が自動の幅へ戻る
   - 「配色」でシステム・ライト・ダーク、「本文幅」で全幅・固定幅を選ぶ
   - 描画から少し待ち、「GitLab との違い <件数>」を押す。「リンク切れ」に `missing.txt` が出ればよい。「<行番号> 行: <抜き出し>」を押し、本文の「リンク切れの確認」の行へ移る
   - 操作欄の「再点検」を押す。「点検中…」から「再点検」へ戻り、「リンク切れ」に `missing.txt` が残ればよい。自分の文書でリンク先のファイルだけを直した場合も、このボタンで調べ直す
   - 別の Markdown を指す相対リンクがある文書では、そのリンクを押して同じタブで移る。ブラウザの戻る・進むで行き来する
   - 印刷するときは、ブラウザの印刷を開いて本文を確かめる

1. プレビューを起こした端末で、Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

  <summary>mdpreview で Markdown をプレビューする の補足と注意点</summary>

**[mdpreview で Markdown をプレビューする](#mdpreview-で-markdown-をプレビューする)の手順 1**

- `--no-open` を外すと、既定のブラウザを開く。`--browser <実行ファイル>` で別のブラウザを指定する
- 試験用の Markdown を専用のフォルダーに作るのは、そのフォルダーがルートになるため（「一覧」に出るのは、その中の Markdown だけ）。止めると、フォルダーごと消す
- 自分の文書を開くときは、試験用ファイルの代わりに Markdown のパスを渡す。保存すると描き直す。未保存の内容を見るときは Neovim から使う
- フォルダーを開く形は `mdpreview docs`。指定したフォルダーをルートにし、最初に一覧を出す。`--root` とは併用しない
- ファイルを渡したときのルートは、上へたどって最初に `.git` があるフォルダー。無ければ、そのファイルのあるフォルダー。`--root <フォルダー>` で変えられる
- 画像・動画・音声・別の文書・include で読めるのはルート内のファイルだけ。`.git` の中は読まない
- `--port <番号>` で待ち受けるポートを指定する。省略すると空いているポートを選ぶ
- `::include{file=…}` で取り込むファイルの変更・削除・作成にも合わせて描き直す
- 公式スタイルは任意。[md-preview の公式スタイルを取得する](install.md#md-preview-の公式スタイルを取得する)に従う

**[mdpreview で Markdown をプレビューする](#mdpreview-で-markdown-をプレビューする)の手順 3**

- 「GitLab との違い」は、知らせが 1 件以上あるときだけ出る。この項の試験用文書では、存在しない `missing.txt` へのリンクを「リンク切れ」に出す
- リンクは描画の約 400 ms 後に、外へ通信せずに点検する。文書の中の `#id`、ルート内の相対ファイル、別の Markdown の見出しの `#id` を調べる。外部 URL、見出しのアンカー、目次、脚注、画像そのものを開くリンク、図のリンクは対象にしない
- 別の文書は 32 件・各 10 MiB まで、点検全体は 10 秒まで。ルートの外、上限を超えた分、読み取れない・描画できない文書は「点検していないリンク」に出す。「リンク切れ」と合わせて件数に入り、行がある項目から本文へ移れる
- 「再点検」はリンクの知らせが 0 件でも出る。点検の失敗は「リンクを点検できませんでした。再点検してください。」と出るので、押し直す。対象と上限の設計は [リンク切れの点検](reference/readme.md#リンク切れの点検)にある
- リンク点検の画面の操作は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある
- 数式は KaTeX、mermaid のコードブロックは mermaid で描く。どちらも同じサーバーから配る同梱のライブラリを使う
- 見出し欄の幅は既定が 260 px、180〜480 px の間で変えられる。上限は 480 px と画面の幅から 320 px を引いた幅の小さい方（最小は 180 px）。右のコメント欄を開いているときは、画面の幅から 680 px を引く
- つまみにフォーカスして ←・→ で 10 px ずつ、Shift+←・Shift+→ で 50 px ずつ変える。Home は最小、End は上限、Enter は既定の幅に戻す。ドラッグ中の Esc は変更を取り消す
- 幅 700 px 以下の画面ではつまみを出さず、見出し欄は画面の幅の 42% になる。幅と欄の開閉は、配色・本文幅と同じ、そのタブの sessionStorage に保存する
- 見出しへのリンクは、見出し欄の項目の右クリック、フォーカス中の Shift+F10・メニューキーからコピーする。ファイル名つきは今の文書のファイル名だけを使うので、同じフォルダーの文書へ貼るときに使う。ID は描画の値を使い、同じ題の `-1` なども区別する。ファイル名と ID は符号化し、リンクの題は 1 行にまとめ、`[`・`]`・`\` はエスケープする。無名の文書ではファイル名つきは使えず、「無名の文書では、ファイル名つきのリンクを作れません」と出る
- コードのコピーは、表示された囲みの中の文字を空行・タブ・末尾の空白も含めてそのまま写す。囲みの記号と言語名は入れない。成功すると「コピーしました」、失敗すると「コピーできませんでした」と出る。提案（`suggestion`）・数式・mermaid の表示には出ない。書き出した HTML にも同じボタンが付く
- 折りたたみ（`<details>`）がなければ「すべて開く」「すべて閉じる」は出ない。1 つでも閉じていれば「すべて開く」、すべて開いていれば「すべて閉じる」になる。全幅表示の表の中も対象にし、差分更新と全置換の後も開閉を保つ。開閉は保存せず、再読み込みで Markdown に書いた状態へ戻る
- 原文の入力欄が隠れる「すべて閉じる」は止め、「原文の入力欄が隠れるため閉じられません。編集を確定するか取り消してから操作してください」と知らせる。確定か取り消しをしてから押し直す
- 画像の拡大は、利用者が書いたリンクの中の画像・PlantUML・数式・mermaid には使わない。Ctrl・Shift・Alt などを押しながらのクリックと中ボタンはブラウザーに任せる。画像をダブルクリックしても、開いた拡大は閉じない。印刷を始めると拡大は閉じる
- コードと見出しのリンクのコピー、折りたたみの一括の開閉、画像の拡大は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「コードと見出しのリンクのコピー・折りたたみ・画像の拡大・依頼文の形・要確認の一括・追加欄の定型と、版 0.19.0 の配布の検証（2026-11-14）」にある
- 印刷用の表示では、操作欄・見出し欄・幅のつまみ・知らせ・コードのコピーのボタン・画像の拡大表示を隠す。HTML への書き出しにも見出し欄とつまみを入れない
- 表の「検索」は各条件の「列」で「すべての列」か列番号と見出しの名前を選ぶ。「条件を足す」で空の欄も含めて 5 個まで足し、「条件を消す」で外す。最初の条件を消すと、その文字は空、列は「すべての列」に戻る
- 検索は NFKC で全角・半角をそろえ、小文字にし、空白をまとめた部分一致で比べる。空の条件は使わない。「一致した行だけ表示」は、文字のある条件の全部に合う同じ行（AND）を残す。縦の結合でつながる行もまとめて残すが、別の行で合う条件を組み合わせて一致にはしない
- 絞り込み中の強調・件数・「前」「次」は、全部の条件に合う行を覆う一致セルだけを対象にする。見出し・固定している行・縦の結合や区切りを保つために残した行の一致も、この条件を満たす場合だけ数える。チェックなしでは、各条件の一致セルを重複なく行・列の順にたどる
- 列は位置で選ぶ。見出しが変われば名前も変わり、列が無くなると「列 N（現在はありません）」と出る。別の列へは切り替わらないので、列を選び直す。条件と列の選択は保存せず、検索を閉じると消える。ページとブックマークレットで同じ操作を使う
- 列ごとの絞り込みは、gitlab.com の実際の画面、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある
- 表の列幅は 32〜1600 px。手で決めた幅では「折り返さない」にしても文字を折り返す。表示だけの設定で、Markdown は変えず、幅は保存しない。印刷では幅を外し、印刷後に戻す
- 本文の差分更新で本文のセルの文字だけが変わったときは列幅を保つ。見出しの文字・結合や列の位置が変わった列は自動に戻す。見出しの無い表で列数が変わると全列を戻す
- 列幅のブラウザ試験は GitLab をまねたページで行っており、gitlab.com の実際の画面での列幅は未確認
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「表の列幅の調節と、版 0.17.0 の配布の検証（2026-11-13）」にある

### mdpreview のプレビューで表を編集する

- パイプの表と結合セルのある HTML の表、表の外のブロックの原文、タスクのチェックボックス、見出しと節を、プレビューの画面で直してファイルに書く。パイプの表全体の原文を直し、ブロックの上下の移動とリストの項目の段の上げ下げができる
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、編集を有効にしてプレビューを起こす。

   ```bash
   (
     # 試験用の Markdown を、専用のフォルダーに作って開く。止めたときに、書き込まれた内容を出してから消す
     preview_dir=$(mktemp -d) || exit
     trap 'printf "\n\033[7m 保存された内容 \033[0m\n"; cat -- "$preview_dir/edit.md"; rm -rf -- "$preview_dir"' EXIT
     printf '%s\n' \
       '# 表の編集の確認' '' \
       '編集する段落。' '' '- [ ] 作業' '- 次の項目' '' '脚注の参照[^1]。' '' \
       '| 名前 | 個数 |' '| --- | --- |' '| りんご | 1 |' '| みかん | 2 |' '| 表の作業 | [ ] |' '' \
       '<table>' '<tbody>' \
       '<tr><td rowspan="2">結合したセル</td><td>右上</td></tr>' \
       '<tr><td>右下</td></tr>' \
       '<tr><td>HTML のタスク</td><td>' '' '- [ ] HTML の作業' '' '</td></tr>' \
       '</tbody>' '</table>' '' \
       '| 品名 | 数量 |' '| --- | --- |' '| 項目10 | 20 |' '| 項目2 | 3 |' '| 項目1 | 10 |' '' \
       '## 最初の節' '' '最初の節の本文。' '' '### 内側の見出し' '' '内側の本文。' '' \
       '## 次の節' '' '次の節の本文。' '' \
       '[^1]: 脚注の内容。' '' '    - [ ] 脚注の作業' > "$preview_dir/edit.md" || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --edit --no-open "$preview_dir/edit.md"
   )
   ```

**[mdpreview のプレビューで表を編集する](#mdpreview-のプレビューで表を編集する)の手順 1**

- 自分の文書には `mdpreview --edit README.md`、フォルダーには `mdpreview --edit docs` を使う。フォルダーでは一覧から文書を選ぶ。`--edit` がなければ編集ボタンも書き込みもない
- Neovim から使うとき（LazyVimStarter の `<leader>cp`）は、`--edit` は要らない。「編集」で直した内容は Neovim のバッファへ入り、ファイルには書かない（保存は `:w`、取り消しは `u`。画面に「元に戻す」「やり直し」は出ない）。編集できるのは、Neovim で開いている文書だけ。Neovim の側でバッファを変えた直後や、変更できないバッファでは、編集を断って理由を知らせる。`vim.g.gitlab_preview_edit = false` で無効にできる
- 画面の編集は直ちにファイルへ書く。BOM とファイルの権限を保ち、隣の一時ファイルから入れ替えるため、ハードリンクは切れ、同じ実体を指していた別名には反映しない。Windows でそのファイルだけに付けたアクセス権（ACL）と、Linux の所有者・拡張属性は、引き継がれないことがある
- 取り込んだ include 先・JSON から作った表・入れ子の表・対応を確かめられない表は編集できない。UTF-8 でないファイル・単独の CR で行の対応がずれる文書・16 MiB を超える文書も対象外
- セル用 Markdown を同じ描画に書き戻せない内容、壊れた HTML の原文、表の外へはみ出す貼り付けなどは書かず、理由を知らせる。ファイルを外で変えた場合も上書きしない
- 取り消しの履歴は文書ごとに200手・全体で32 MiBまで。プレビューを終了すると失われる。外で変わったファイルには古い履歴を適用しない

- リスト・引用・注記などの中の生の HTML は、それだけを開けない。ダブルクリックでは外側の項目などを開き、その原文として直す。生の HTML の表（`<table>`）は、表のセルとして編集する

- include の展開・front matter に掛かる範囲、続きの行のある脚注の定義など、取り除くとほかの描画が変わる行を挟む範囲は、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- 生の HTML 全体を開く際、利用者が書いた `data-sourcepos` を含むブロックや、前後の境の位置が利用者の書いた属性である場合も、「このブロックは、原文の範囲を確かめられません。」と知らせて開かない
- マウスを載せると、ダブルクリックで開く対象に破線の枠が出る。数式と図はその表示、水平線は線、項目は項目、注記の題名は注記全体に出る。生の HTML の位置のない要素では、まとめて開く要素の全部に出る
- ` ```math `・`$$…$$` の数式のブロック、mermaid の図、`plantuml` コマンドで描いた PlantUML の図をダブルクリックすると、囲みを含む原文を開く。Ctrl+Enter で確定すると置き換えて描き直す。`$$…$$` は段落として開く
- 水平線（`---`・`***`・`___` など）をダブルクリックすると原文を開く。確定すると置き換わり、段落や見出しにも書き換えられる。編集モードの間は、線の上下の余白も押せる。線の見た目は変わらない
- 水平線で終わる項目と、そのリストも開ける。原文には水平線の行まで入る
- 行の中の数式（`$x$`）をダブルクリックすると、その段落を開く
- mermaid と PlantUML の図を描けなかった表示からも、ダブルクリックで原文を開いて直せる。数式と図のライブラリを読み込んでいる間も、同じ対象を開ける
- 数式と図の描き直しや配色の切り替えで表示が置き換わっても、入力欄は閉じず、その対象に付いていく。文書が外で変わったときは、入力欄を閉じ、入力途中の文字を下書きに残す
- 注記の題名や余白を押すと、注記全体を開く。`> [!note]`・`>>> [!note]` の種類と題名の行、`>>>` の閉じの行を含む全体を直せる
- 入力欄のそばの操作欄のボタンか Alt+↑ で、1 つ外側のブロックへ移る。項目が 1 つだけのリストのように、内側と同じ範囲になる外側は飛ばす
- ボタンは外側の種類に合わせて「リスト全体を編集」「引用全体を編集」「説明リスト全体を編集」「注記全体を編集」「項目全体を編集」「説明全体を編集」「HTML のブロック全体を編集」、ほかは「外側のブロックを編集」と出る
- 「内側に戻る」か Alt+↓ で、移る前の内側のブロックへ戻る。移るときは入力途中の文字を確定せずに残し、戻ると入力欄に出す。IME の変換中は移らない
- ブロックの原文を開くと、入力欄のそばの操作欄に「前に追加」「後ろに追加」が出る。押すと、編集中の入力は確定せず下書きに残り、空の入力欄が開く。右下の札は「追加」になる
- 追加の入力欄は、いちばん外側のブロックの上か下に出る。リストの項目ならリスト全体、引用の中の段落なら引用全体の前後に追加する
- 生の HTML のブロック全体を開いているときは、その全体の前後に追加する。中の段落などを開いているときは、生の HTML の中で、その対象の前後に追加する
- 追加は Ctrl+Enter（macOS は Cmd+Enter も）で確定し、Esc で取り消す。入力欄の外をクリックすると、文字があれば確定し、無ければ取り消す。追加中は、外側・内側へ移るボタンと Alt+↑・Alt+↓ は使えない
- 追加する文の前後の空行は除き、前後のブロックとの間に空行を 1 行ずつ置く。既に空行があれば足さず、文書の先頭・末尾の側にも足さない。改行（LF・CRLF）はその場所に合わせる
- 追加した文が前後のブロックに取り込まれたり、前後を巻き込んだりする場合は、「追加した文が前後のブロックに取り込まれます。」と知らせ、書き込まず入力を残す
- 後ろに内容がある所へ閉じていないコードの囲み（` ``` ` だけ）・`>>>`・`<details>` を足すと断られる。リストのすぐ後ろへの字下げした文や項目（`- b`）の追加も断られる。リストに項目を足すときは、リスト全体を開いて書き足す
- 文書の最後の生の HTML のブロックの前に、閉じない要素（`<div>` だけ、など）を足して既存のブロックを取り込む場合も断られる
- 空白だけの追加は、「追加する文を入力してください。」と知らせて断る
- 操作欄の「追加」から、文書の先頭・末尾にも追加できる。先頭は front matter の後ろになる。空白と空行だけの文書では「追加」の代わりに「最初のブロックを書く」が出て、入力した文で全体を置き換える。参照の定義やコメントだけの文書は空とは扱わない
- 文書の末尾が閉じていない `<!--`・`<details>`・コードの囲みなどで、追加した文がその中に取り込まれる場合は断る
- 表のセルを選び、画面の下の「表」か右クリックの「表 ▸」から、表の前後への追加を選べる。表の操作ができる最上位の表だけが対象。リスト・引用の中、入れ子、HTML の表の最初と最後の行に表以外の文字がある場合などは、理由を出して断る
- 追加の入力欄の「注記…」で「メモ（note）」「ヒント（tip）」「重要（important）」「警告（warning）」「注意（caution）」を選んで「入れる」を押す。`> [!note]` などの種類の行と、本文用の `> ` が入る
- 「コード…」で `sh`・`bash`・`powershell` を選んで「入れる」を押す。言語名の付いたバッククォート 3 つの囲みと空の本文の行が入る。「折りたたみ」は `<details>`・`<summary>題</summary>`・本文・閉じタグの定型をすぐに入れる
- 注記・コード・折りたたみの定型は、入力欄のカーソルの位置（文字を選んでいればその範囲）へ入れ、前後に必要な空行を補う。入力欄で直してから Ctrl+Enter で追加を確定する。「閉じる」か Esc は種類や言語を選ぶ欄だけを閉じる。確定では通常の追加と同じ検査を通し、周りの表示が変わる場合などは書かず理由を知らせる
- 追加欄の定型は、実際の IME、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「コードと見出しのリンクのコピー・折りたたみ・画像の拡大・依頼文の形・要確認の一括・追加欄の定型と、版 0.19.0 の配布の検証（2026-11-14）」にある
- 追加の入力欄の「表を入れる…」で、列を 1〜20、本文の行を 1〜100 から選び、「入れる」を押す。見出しが「列1」・「列2」…の空のパイプの表が、入力欄のカーソルの位置（文字を選んでいればその範囲）に入る。入力欄で内容を直してから、Ctrl+Enter で追加を確定する。「閉じる」か Esc は大きさを選ぶ欄だけを閉じる
- セルの原文の入力欄と脚注の定義には「前に追加」「後ろに追加」のボタンが出ない。include 先・front matter、範囲を確かめられないいちばん外側のブロック、生の HTML に `data-sourcepos` を書いた要素からも追加できない
- ファイルを編集しているときは、追加も「元に戻す」「やり直し」で 1 手として戻せる。Neovim にはバッファの 1 個の行の置き換えとして届き、`u` で戻せる
- 空行なしの説明リストの用語は、描画エンジンの位置を編集の側で正して開く
- `>>>` の引用の中の最後の項目など、範囲を確かめられないブロックを押すと、開ける外側のブロックを開いて知らせる。外側もなければ、理由を知らせて開かない
- 生の HTML に `data-sourcepos`・`data-checkbox-sourcepos` を書いた要素は、描画エンジンが付けた位置と区別できないので編集できない。同じ要素名・同じ位置を持つ本物の要素も編集できなくなる
- 脚注の定義の中を押すと、ラベル `[^1]:` を含む定義全体を開き、「ラベルを変えると、本文の参照と対応しなくなります」と知らせる
- 脚注のラベルを変えて確定すると、置き換えた上で「脚注のラベルが変わりました。本文の参照を確かめてください。」と知らせる。脚注の中の段落だけは編集できない
- 編集モードの間は、原文を直せる所のリンクを押しても移動しない。PlantUML の図のクリックで SVG を開く操作と、Neovim のエディタの行へ移る操作も止め、図のダブルクリックで原文を開く。リンクで移るときは、「編集」をもう一度押して編集モードを出る
- Ctrl などを押しながらのリンクのクリックは止めないので、新しいタブで開ける
- 目次・include 先・front matter は画面から編集できない。リスト・引用などの中の生の HTML だけを開くこともできない
- 表の操作ができる表のセル（生の HTML の表と、パイプの表の `| [ ] |`）と脚注の定義の中も、タスクをクリックかフォーカス中の Space で切り替えられる。JSON の表・入れ子の表・対応できない表・include で取り込んだ表の中は無効のまま。「表を固定」の「セルを選んで固定」の最中は、チェックを切り替えず固定の境界を選ぶ
- 表と脚注の中の数式と図は、それだけを開いて編集できない。脚注の定義は、ラベルを含む全体を開く
- 原文の取得や書き込みを断ったときは、理由を知らせる。Ctrl・Shift・Alt を押しながらのダブルクリックでは、編集を始めない

### mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る

- 本文にコメントをため、計画か直接の修正を頼む形を選んだ依頼文をコピーして、文書のルートで開いた VS Code の Agents Window に貼って送る
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある。Agents Window を開くには、VS Code の `code` コマンドも PATH にあること。Copilot のセッションを使うときは、VS Code で Copilot にサインインしておく
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. コメントを付ける Markdown のパスを入力し、プレビューを起こす。パスは引用符を付けずに入力する。

   ```bash
   (
     # コメントを付ける文書を選び、コメントを有効にして開く
     read -er -p 'Markdown のパス: ' review_file || exit
     printf '\n\033[7m 確認 \033[0m\n'
     mdpreview --review "$review_file"
   )
   ```

   - ブラウザで文書が開き、操作欄に「コメント」が出ればよい
   - エラーが出たら、中断して文書のパスと [導入の手順](install.md#md-preview-を導入更新する)で導入状態を確かめる

1. 操作欄の「コメント」を押す。

   - 右にコメントの欄が出ればよい。狭い画面では下に出る

1. 本文のブロックか表のセルを押す。文字を引用したいときは、1 つの対象の中で文字を選ぶ。

   - 欄に選んだ対象が出ればよい。文字も選んだ場合は「選んだ文字」に出る
   - 節全体に付けるときは、本文のいちばん外側の見出しを選び、「節全体へのコメントにする」にチェックを入れる。「節: …」と出ればよい。チェックを外すと見出しだけが対象になる
   - コメントを付けられない所は、理由の知らせを確かめ、対象を選び直す

1. 欄にコメントを書き、「追加」を押す。Ctrl+Enter でも追加できる。

   - コメントのカードが「未コピー」で出ればよい。節全体を選んだ場合は、カードの題が「節: …」になる
   - この項の手順 3〜4 を、必要なコメントの数だけ繰り返す
   - コメントを持ち出すときは「書き出す」を押し、「コメントを書き出してコピーしました。」が出ることを確かめる。このページの外の文字を入力できる所に Ctrl+V で貼り、コメントの JSON が出ることを確かめる
   - 書き出したコメントを足すときは、JSON をコピーしてから、同じ文書のコメント欄で「読み込む」を押す。「書き出したコメントの JSON を貼り付けてください」の欄に Ctrl+V で貼り、「足す」を押す。追加した件数と、重なりで足さなかった件数の知らせを読む。同じカードがある文書へそのまま読み込むと、追加は 0 件で重なりになる。足したカードがあれば「未コピー」で出ることを確かめる

1. 「依頼文の形」で「/plan で計画」「日本語で計画」「直接直す」を選び、「依頼文を作る」を押す。対象のファイル・行・原文と、コメントを確かめる。

   - ページを開いたときは「/plan で計画」が選ばれている。その形では先頭が `/plan` で、まず計画だけを示す依頼文が出ればよい。ほかの形の先頭は、この項の補足で確かめる
   - 「要確認」の件数が出たら、該当するカードの「直す」を押し、本文で対象を選び直して「保存（対象を変える）」を押す。同じ位置の内容を確かめ直す場合は「保存」と出る。今回の依頼に含めないときは「今回は送らない」を押す。「今回は送る」で戻せる
   - 要確認をまとめて今回の依頼から外すときは「要確認をまとめて送らない」を押す。「まとめて送らないを戻す」で、そのボタンで付けた印だけを戻せる
   - 「誤り」のカードがあれば、それぞれの理由を読み、対象やコメントを直して作り直す。表の情報を読み込んでいる知らせが出たら、少し待って押し直す

1. 「コピーして Agents Window を開く」を押す。

   - 依頼文がコピーされ、文書のルートで VS Code の Agents Window が開けばよい（AlmaLinux 10 での VS Code の起動は未検証。この項の補足を見る）
   - Agents Window が前のフォルダーのまま開くことがある。新しいフォルダーの信頼の確認が出たら、フォルダーと内容を確かめて「Trust Folder & Continue」を押す。確認を進めた後に文書のフォルダーへ切り替わるので、開いたフォルダーを確かめる

1. Agents Window の「Show Session Options」を開き、セッションの種類を Copilot か Claude、作業場所を Branch にする。

   - セッションの種類は、既定が Codex のことがある。Copilot へ送るときは Copilot を選ぶ（Claude のセッションへの送付は未検証）
   - 開いたフォルダーがプレビューのルートであることを確かめる
   - Git の文書では、Branch は今のフォルダーを直接直す。New Worktree は別の worktree で直す

1. Agents Window の入力欄に Ctrl+V で依頼文を貼り、内容を確かめて Enter で送る。

   - 選んだ形の依頼文をそのまま貼る。「/plan で計画」では `/plan` を含める。Agents Window のエージェントの一覧から Plan を探す操作は要らない
   - 「/plan で計画」を選んだ場合、Copilot では `/plan` がスラッシュコマンドとして扱われ、「Review Plan」と「Implement / Reject」が出ることを確かめる。承認するまでファイルを変えないことも確かめる

1. 「/plan で計画」「日本語で計画」では、返ってきた計画を確かめ、直す範囲と内容がよければ実装を承認する。「直接直す」では、計画の承認を待たずに直す依頼になる。

   - 実装後に、直した内容と差分を確かめる
   - Branch でプレビューと同じファイルが保存されると、直した結果がプレビューに出ることを確かめる

1. 終わったら、プレビューを起こした端末で Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

- `--review` は単体ファイルとフォルダーのプレビューで使う。`--stdio` と引数では併用しない
- Neovim から使うとき（LazyVimStarter の `<leader>cp`）も、同じ画面でコメントを付けられる。橋渡しが `hello` で `review: 1` を送ると有効になる。LazyVimStarter では既定で有効で、`vim.g.gitlab_preview_review = false` で無効にできる。Neovim 側の操作と設定は、LazyVimStarter の `docs/extra/setup.md` にある
- Neovim では、依頼文を作る前に `:w` で保存する。バッファとディスクの本文が同じときだけ作り、BOM と改行（CRLF・LF）の違いは無視する。違う場合は「Neovim で保存（:w）してから依頼文を作ってください。」と出る。コメントを付ける段階では保存は要らない
- 名前のないバッファでもコメントを付けられるが、依頼文は作れない。「名前のないバッファでは依頼文を作れません。ファイルに保存してから作ってください。」と出るので、保存してから作り直す

- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「Neovim から使うときの画面のコメントと、版 0.24.0 の配布の検証（2026-11-14）」にある
- `--edit --review` を付けると、「編集」と「コメント」を切り替えて使える。同時には使えず、編集の入力中は切り替えない。編集を確定するか取り消してから「コメント」を押す

- 「依頼文の形」はページを開くたびに「/plan で計画」になる。形を変えると作った依頼文を捨てるので、「依頼文を作る」を押し直す。対象が `README.md` の場合、先頭の段落は次の形になる

- 依頼文の形の選択と要確認の一括操作の検証記録は、`repos/md-tools/docs/verification/readme.md` の「コードと見出しのリンクのコピー・折りたたみ・画像の拡大・依頼文の形・要確認の一括・追加欄の定型と、版 0.19.0 の配布の検証（2026-11-14）」にある
- 段落・見出し・リスト・引用・コード・数式のブロック・図・水平線・注記・脚注の定義と、最上位の生の HTML の連なり、表のセルが対象になる。「表を固定」で固定・全幅表示にした表のセルにも付けられる
- include 先・front matter・JSON からできた表・入れ子の表、原文との対応や範囲を確かめられない対象は使えない。理由の知らせを確かめる
- 「節全体へのコメントにする」は、本文のいちばん外側の見出しを選んだときだけ出る。既定はチェックなしで、本文で対象を選び直すと外れる。節は選んだ見出しから、子の節を含め、次の同じか上のレベルの見出しの手前まで（無ければ文書の末尾まで）。依頼文の種類は「節」で、行と原文も節全体になる
- 節の先頭にできるのは、原文と対応づけた最上位の Markdown の見出しだけ。include の指定や取り込んだ行を含む節、front matter の中の見出し、引用・リスト・HTML の中などの見出しによって境があいまいになる節は送れない。カードを追加できても依頼文の作成で断る場合があるので、「誤り」の理由を確かめる
- 「選んだ文字」は表示の文字の引用。原文の文字の位置を指すものではなく、依頼文の位置はそのブロックの行（節では節全体、セルでは表全体の行）になる。複数の対象にまたがる文字は添えられない
- カードの「直す」でコメントや対象を直し、「消す」でそのカードを消し、「本文へ移る」で対象を表示する。「未コピー」はまだ依頼文をコピーしていないコメント、「コピー済み」はコピーしたコメント。「誤り」は依頼文を作るときに断られた対象それぞれの理由を示す
- 「要確認」は対象が消えた・内容が変わった・対応を一つに決められない・表を確かめられなくなったもの。位置が同じでも内容が違えば要確認にし、元に戻して同じ対象の内容が戻れば外す
- `--edit --review` の画面での編集と「元に戻す」「やり直し」の後は、位置と内容を確かめて、内容の変わらないブロック・生の HTML の連なり・表のセル・節へコメントを追従させる。表の開始位置や同じ内容の候補を一つに決められない場合は要確認にする。外のエディターやファイルの変更では、別の位置へ移さない
- 節へのコメントは、画面の節の移動や節ごとの見出しのレベル変更でも、節全体の内容が一致し、候補が一つなら付いてくる。子の見出しだけのレベル変更や本文の変更は要確認になる。脚注の定義は、表示される場所ではなく原文の開始行がある節に含める。コードの外の空白はまとめて比べるが、コードの中の改行と字下げは区別する
- 今回送るコメントに要確認があると依頼文を作らず、件数を知らせる。「直す」で対象を選び直すか、「今回は送らない」で外す。「今回は送る」で戻せ、コメント自体は消えない。除外の印は依頼文をコピーすると外れる。表の情報の読み込みが揃う前も依頼文を作らず、待つよう知らせる
- 「要確認をまとめて送らない」は、未コピーで今回送る対象になっている要確認だけに「今回は送らない」の印を付ける。「まとめて送らないを戻す」はその操作で付けた分だけを戻し、もともと付いていた印と、手で付け直した印は戻さない
- 一括で戻す記録は保存しない。依頼文のコピー成功で記録を全部捨て、カードを直して保存・削除したときはそのカードの記録を外す。文書の切り替えと再読み込みでも記録は失われる
- 「依頼文を作る」は「今回は送らない」を除く未コピーのコメントをまとめる。「コピー済みを消す」はコピー済みのカードを消す。コピー済みは、エージェントへ送ったことや実装が済んだことを示さない
- コメントは文書ごとに、そのタブの sessionStorage に版 2 の形で保存する。Neovim ではバッファの文書ごとに分け、バッファを移ると前の文書のコメントを保存して次の文書の分を読み戻す。対象の位置・内容の指紋・文書の版と、コメント・コピーの状態・要確認・今回送らない印などを保存する。同じタブの再読み込みでは読み戻すが、編集の前後を追う記録は消え、保存した位置と内容で確かめ直す。永続的な保存や別のタブとの自動の共有には使わない
- 「書き出す」は、今の文書のコメントをコピー済み・要確認・今回送らない分も含めて JSON にしてクリップボードへコピーする。コメントのコピーの状態は変えず、ファイルへは書かない。JSON には形式の名前と版・文書の相対パス、対象・題・コメント・選んだ文字・内容の指紋・セルの照合用の鍵を入れる。サーバーの token・端末の絶対パス・URL を自動で入れず、依頼文・起動ごとの版・コピーや要確認などの状態も持ち出さない。コメントなどに自分で書いた文字はそのまま入る
- 文書は描画のルートからの相対パスで見分け、別の文書のコメントは足さない。今あるカードを残して足し、同じ対象で同じコメントの文は、選んだ文字が違っていても重なりとして足さない。読み込んだカードはすべて未コピーになり、今回送らない印を外し、今の位置と内容の指紋を確かめ直す。対象が無い・内容が合わない場合は要確認になる。別の位置は探さない
- 読み込む JSON は UTF-8 で 4 MiB、項目は 200 件まで。足した後の合計も保存 200 件・未コピー 50 件までにする。型・値・余分な項目名など、1 つでも形が違う場合や上限を超える場合は何も足さない。「読み込む」の貼る欄は「やめる」か Esc で閉じ、貼った文字を捨てる。描画が届く前や依頼文の作成中・コピー中・停止後は持ち出しを使えない
- 節へのコメントと持ち出しは、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証。書き出した JSON を別の PC やブラウザーへ移す操作も未検証
- 節へのコメントと持ち出しの検証記録は、`repos/md-tools/docs/verification/readme.md` の「節へのコメント・コメントの書き出しと読み込みと、版 0.20.0 の配布の検証（2026-11-14）」にある
- 1 回の依頼は 50 件まで。コメントと「選んだ文字」はそれぞれ 2,000 文字まで。原文の抜粋は各 4 KiB までで、超えたら入る範囲の先頭と末尾の行を残して省略する。依頼文全体が 64 KiB を超えると作らないので、コメントを分ける
- 行は 1 から数え、終わりの行も含む。include の展開前の原文を、front matter の行も含めて数える。ファイルが外で変わったときは、最新の表示と要確認のカードを確かめて依頼文を作り直す
- コメントの内容の照合と編集への追従は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME では未検証。検証記録は、`repos/md-tools/docs/verification/readme.md` の「見出しの操作・表以外の右クリックのメニュー・コメントの追従と、版 0.18.0 の配布の検証（2026-11-13）」にある

### mdpreview で Markdown を HTML に書き出す

- 試験用の Markdown を HTML に書き出し、ブラウザで開く
- 前提: [md-preview を導入・更新する](install.md#md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: GNOME にログインした自分のユーザーの端末（bash）。`sudo` は使わない

1. 試験用の Markdown を作り、HTML に書き出す。

   ```bash
   # 試験用の Markdown を HTML に書き出す
   preview_dir=$(mktemp -d) &&
     printf '%s' 'iVBORw0KGgoAAAANSUhEUgAAACAAAAAgCAIAAAD8GO2jAAAAK0lEQVR4nGNQLd1AU8QwasGoBaMWjFowasGoBaMWjFowasGoBaMWlA4RCwA0/ihM7D1ZAgAAAABJRU5ErkJggg==' | base64 --decode > "$preview_dir/image.png" &&
     printf '# 書き出しの確認\n\n本文です。\n\n![埋め込みの確認](image.png)\n' > "$preview_dir/preview.md" &&
     mdpreview render --embed-images -o "$preview_dir/preview.html" "$preview_dir/preview.md"
   ```

   - エラーなく終われば、この項の手順 2 へ進む
   - エラーが出たら、中断して入力ファイルと書き出し先を確かめる

1. 書き出したファイルを確かめる。

   ```bash
   printf '\n\033[7m 確認 \033[0m\n'
   ls -l -- "$preview_dir/preview.html"
   ```

   - `preview.html` があり、大きさが 0 より大きければよい
   - 表示されたファイルのパスを、この項の手順 3 で使う

1. ブラウザで、書き出した HTML を開く。

   - Ctrl+O を押し、この項の手順 2 で確かめたファイルを開く
   - 本文に「書き出しの確認」と「本文です。」、青い四角の画像が出ればよい
   - ブラウザでページのソースを表示し、本文の画像の `src` が `data:image/png;base64,` で始まればよい。試験用の文書の `image.png` を埋め込めたことを、この値でも確かめる

1. 試験用のフォルダーを消す。

   ```bash
   # この項の手順 1 で作った試験用のフォルダーを消す
   [ -n "${preview_dir:-}" ] && rm -r -- "$preview_dir"
   unset preview_dir
   ```

   - 何も出なければよい
   - この項の手順 1 と同じ端末で行う（別の端末では、消すフォルダーが分からない）

<details id="mdpreview-で-markdown-を-html-に書き出す-の補足と注意点">
  <summary>mdpreview で Markdown を HTML に書き出す の補足と注意点</summary>

**[mdpreview で Markdown を HTML に書き出す](#mdpreview-で-markdown-を-html-に書き出す)の手順 1**

- 自分の文書を使う形は `mdpreview render -o preview.html README.md`。`-o` を省くと標準出力に HTML を書く。書き出し先のフォルダーは先に用意する
- 知らせがあれば、標準エラーに種類ごとの件数を出す。例は `mdpreview: 参照: 2 件`、`mdpreview: 見つからないメディア: 1 件`。ほかの種類の名前は「図」「提案」「取り込み」「絵文字」と、件数が多くて省いた分の「省略した知らせ」
- `--theme system|light|dark` で配色、`--width fluid|fixed` で本文幅を選ぶ。既定は `system`（OS に従う）と `fluid`（全幅）
- `system` の暗い配色は画面だけに使い、印刷は明るい配色にする
- `--root <フォルダー>` でルートを指定できる。省略したときのルートの決め方はプレビューと同じ
- 試験用の `image.png` は、コマンドに書いたデータから作る 32×32 px の画像。`--embed-images` を付けると、ルート内の PNG・JPEG・GIF・WebP を data URL にして HTML に埋め込む。自分の文書を使う形は `mdpreview render --embed-images -o preview.html README.md`
- 埋める画像は拡張子と先頭のバイト列の両方で種類を確かめ、1 枚 8 MiB・合計 32 MiB までにする。同じ実ファイルは合計へ 1 回だけ数える。画像の内容全体をデコードして検査するものではない
- SVG・対応外の種類・拡張子と種類の食い違い・外部 URL・ルートの外・見つからない画像・読み取れない画像・上限を超えた画像は埋めず、通常の URL の扱いで残す。理由ごとの件数を `画像を埋め込みませんでした（N 件）: <理由>` の形で標準エラーへ知らせる。画像の警告だけでは終了コードを失敗にしない
- 本文にもともとある `data:` の画像はそのままにし、警告もしない。埋め込みの処理は外部 URL を取得せず、外へ通信しない。詳しい順序と上限は [画像の埋め込み](reference/readme.md#画像の埋め込み)にある
- `--embed-images` を付けないと、画像は埋め込まない。動画・音声と埋めなかった画像・リンクは、ルート内の相対パスを書き出し先から見た形に直す
- 書き出し先がルートの外のときは、相対パスを文書のフォルダーから見た形のままにし、そのことを標準エラーに知らせる（書き出し先から見た形にすると、ルートより上のフォルダーの名前が HTML に入るため）。リンクと画像を合わせるには、ルートの中へ書き出す
- 入力の Markdown と同じファイルは、書き出し先にできない
- 別の Markdown へのリンクもファイルへのリンクとして残る。リンク先の HTML をまとめて作る機能はない
- 公式スタイルを導入していても、書き出しには同梱のスタイルを使う。必要な KaTeX・mermaid と数式のフォント、コードのコピーのボタンがあるときはそのスクリプトも埋め込む。数式・mermaid・コードのコピーのどれも無ければスクリプトを入れない
- mermaid の図があると、ライブラリを埋め込むため HTML が大きくなる。数式と図を含む文書を書き出した例では約 6.2 MB

**[mdpreview で Markdown を HTML に書き出す](#mdpreview-で-markdown-を-html-に書き出す)の手順 3**

- サーバーを起こさず、`file://` から開く。埋めた画像は HTML だけで表示する。埋めなかったメディアを別の場所へ移すときは、HTML との相対パスの関係を保つ
- 画像を埋めた HTML の表示は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある

</details>

### Windows 11 の mdpreview で Markdown をプレビューする

- 試験用の小さな Markdown を作り、ブラウザで表示を確かめる
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く

1. 管理者ではない PowerShell 7 を開く。

1. 試験用の Markdown を作り、プレビューを起こす。

   ```powershell

     # 試験用の Markdown を、専用のフォルダーに作って開く
     $previewDirectory = Join-Path ([IO.Path]::GetTempPath()) ("md-preview-" + [guid]::NewGuid())

     } finally {
   ```

**[Windows 11 の mdpreview で Markdown をプレビューする](#windows-11-の-mdpreview-で-markdown-をプレビューする)の手順 2**

- `--no-open` を外すと、既定のブラウザを開く。`--browser <実行ファイル>` で別のブラウザを指定する
- 試験用の Markdown を専用のフォルダーに作るのは、そのフォルダーがルートになるため（「一覧」に出るのは、その中の Markdown だけ）。止めると、フォルダーごと消す
- 自分の文書を開くときは、試験用ファイルの代わりに Markdown のパスを渡す。保存すると描き直す。未保存の内容を見るときは Neovim から使う
- フォルダーを開く形は `mdpreview docs`。指定したフォルダーをルートにし、最初に一覧を出す。`--root` とは併用しない
- ファイルを渡したときのルートは、上へたどって最初に `.git` があるフォルダー。無ければ、そのファイルのあるフォルダー。`--root <フォルダー>` で変えられる
- 画像・動画・音声・別の文書・include で読めるのはルート内のファイルだけ。`.git` の中は読まない
- `--port <番号>` で待ち受けるポートを指定する。省略すると空いているポートを選ぶ
- `::include{file=…}` で取り込むファイルの変更・削除・作成にも合わせて描き直す
- 公式スタイルは任意。[Windows 11 で md-preview の公式スタイルを取得する](install.md#windows-11-で-md-preview-の公式スタイルを取得する)に従う

**[Windows 11 の mdpreview で Markdown をプレビューする](#windows-11-の-mdpreview-で-markdown-をプレビューする)の手順 4**

- 「GitLab との違い」は、知らせが 1 件以上あるときだけ出る。この項の試験用文書では、存在しない `missing.txt` へのリンクを「リンク切れ」に出す
- リンクは描画の約 400 ms 後に、外へ通信せずに点検する。文書の中の `#id`、ルート内の相対ファイル、別の Markdown の見出しの `#id` を調べる。外部 URL、見出しのアンカー、目次、脚注、画像そのものを開くリンク、図のリンクは対象にしない
- 別の文書は 32 件・各 10 MiB まで、点検全体は 10 秒まで。ルートの外、上限を超えた分、読み取れない・描画できない文書は「点検していないリンク」に出す。「リンク切れ」と合わせて件数に入り、行がある項目から本文へ移れる
- 「再点検」はリンクの知らせが 0 件でも出る。点検の失敗は「リンクを点検できませんでした。再点検してください。」と出るので、押し直す。対象と上限の設計は [リンク切れの点検](reference/readme.md#リンク切れの点検)にある
- リンク点検の画面の操作は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある
- 数式は KaTeX、mermaid のコードブロックは mermaid で描く。どちらも同じサーバーから配る同梱のライブラリを使う
- 見出し欄の幅は既定が 260 px、180〜480 px の間で変えられる。上限は 480 px と画面の幅から 320 px を引いた幅の小さい方（最小は 180 px）。右のコメント欄を開いているときは、画面の幅から 680 px を引く
- つまみにフォーカスして ←・→ で 10 px ずつ、Shift+←・Shift+→ で 50 px ずつ変える。Home は最小、End は上限、Enter は既定の幅に戻す。ドラッグ中の Esc は変更を取り消す
- 幅 700 px 以下の画面ではつまみを出さず、見出し欄は画面の幅の 42% になる。幅と欄の開閉は、配色・本文幅と同じ、そのタブの sessionStorage に保存する
- 見出しへのリンクは、見出し欄の項目の右クリック、フォーカス中の Shift+F10・メニューキーからコピーする。ファイル名つきは今の文書のファイル名だけを使うので、同じフォルダーの文書へ貼るときに使う。ID は描画の値を使い、同じ題の `-1` なども区別する。ファイル名と ID は符号化し、リンクの題は 1 行にまとめ、`[`・`]`・`\` はエスケープする。無名の文書ではファイル名つきは使えず、「無名の文書では、ファイル名つきのリンクを作れません」と出る
- コードのコピーは、表示された囲みの中の文字を空行・タブ・末尾の空白も含めてそのまま写す。囲みの記号と言語名は入れない。成功すると「コピーしました」、失敗すると「コピーできませんでした」と出る。提案（`suggestion`）・数式・mermaid の表示には出ない。書き出した HTML にも同じボタンが付く
- 折りたたみ（`<details>`）がなければ「すべて開く」「すべて閉じる」は出ない。1 つでも閉じていれば「すべて開く」、すべて開いていれば「すべて閉じる」になる。全幅表示の表の中も対象にし、差分更新と全置換の後も開閉を保つ。開閉は保存せず、再読み込みで Markdown に書いた状態へ戻る
- 原文の入力欄が隠れる「すべて閉じる」は止め、「原文の入力欄が隠れるため閉じられません。編集を確定するか取り消してから操作してください」と知らせる。確定か取り消しをしてから押し直す
- 画像の拡大は、利用者が書いたリンクの中の画像・PlantUML・数式・mermaid には使わない。Ctrl・Shift・Alt などを押しながらのクリックと中ボタンはブラウザーに任せる。画像をダブルクリックしても、開いた拡大は閉じない。印刷を始めると拡大は閉じる
- コードと見出しのリンクのコピー、折りたたみの一括の開閉、画像の拡大は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「コードと見出しのリンクのコピー・折りたたみ・画像の拡大・依頼文の形・要確認の一括・追加欄の定型と、版 0.19.0 の配布の検証（2026-11-14）」にある
- 印刷用の表示では、操作欄・見出し欄・幅のつまみ・知らせ・コードのコピーのボタン・画像の拡大表示を隠す。HTML への書き出しにも見出し欄とつまみを入れない
- 表の「検索」は各条件の「列」で「すべての列」か列番号と見出しの名前を選ぶ。「条件を足す」で空の欄も含めて 5 個まで足し、「条件を消す」で外す。最初の条件を消すと、その文字は空、列は「すべての列」に戻る
- 検索は NFKC で全角・半角をそろえ、小文字にし、空白をまとめた部分一致で比べる。空の条件は使わない。「一致した行だけ表示」は、文字のある条件の全部に合う同じ行（AND）を残す。縦の結合でつながる行もまとめて残すが、別の行で合う条件を組み合わせて一致にはしない
- 絞り込み中の強調・件数・「前」「次」は、全部の条件に合う行を覆う一致セルだけを対象にする。見出し・固定している行・縦の結合や区切りを保つために残した行の一致も、この条件を満たす場合だけ数える。チェックなしでは、各条件の一致セルを重複なく行・列の順にたどる
- 列は位置で選ぶ。見出しが変われば名前も変わり、列が無くなると「列 N（現在はありません）」と出る。別の列へは切り替わらないので、列を選び直す。条件と列の選択は保存せず、検索を閉じると消える。ページとブックマークレットで同じ操作を使う
- 列ごとの絞り込みは、gitlab.com の実際の画面、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある
- 表の列幅は 32〜1600 px。手で決めた幅では「折り返さない」にしても文字を折り返す。表示だけの設定で、Markdown は変えず、幅は保存しない。印刷では幅を外し、印刷後に戻す
- 本文の差分更新で本文のセルの文字だけが変わったときは列幅を保つ。見出しの文字・結合や列の位置が変わった列は自動に戻す。見出しの無い表で列数が変わると全列を戻す
- 列幅のブラウザ試験は GitLab をまねたページで行っており、gitlab.com の実際の画面での列幅は未確認
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「表の列幅の調節と、版 0.17.0 の配布の検証（2026-11-13）」にある

### Windows 11 の mdpreview のプレビューで表を編集する

- パイプの表と結合セルのある HTML の表、表の外のブロックの原文、タスクのチェックボックス、見出しと節を、プレビューの画面で直してファイルに書く。パイプの表全体の原文を直し、ブロックの上下の移動とリストの項目の段の上げ下げができる

   - 上の表の「りんご」をクリックする。そのセルに枠が付き、画面の下に操作欄が出ればよい

   - 「青りんご」をクリックし、「行」→「複製」を押す。すぐ下に同じ行が増え、「元に戻す」1 回で戻ればよい
   - 「青りんご」をクリックし、「行」→「コピー」を押す。「みかん」をクリックし、「行」→「コピーした 1 行を下に挿入」を押す。その下に「青りんご」の行が増えればよい

**[Windows 11 の mdpreview のプレビューで表を編集する](#windows-11-の-mdpreview-のプレビューで表を編集する)の手順 2**

- 自分の文書には `mdpreview --edit README.md`、フォルダーには `mdpreview --edit docs` を使う。フォルダーでは一覧から文書を選ぶ。`--edit` がなければ編集ボタンも書き込みもない
- Neovim から使うとき（LazyVimStarter の `<leader>cp`）は、`--edit` は要らない。「編集」で直した内容は Neovim のバッファへ入り、ファイルには書かない（保存は `:w`、取り消しは `u`。画面に「元に戻す」「やり直し」は出ない）。編集できるのは、Neovim で開いている文書だけ。Neovim の側でバッファを変えた直後や、変更できないバッファでは、編集を断って理由を知らせる。`vim.g.gitlab_preview_edit = false` で無効にできる
- 画面の編集は直ちにファイルへ書く。BOM とファイルの権限を保ち、隣の一時ファイルから入れ替えるため、ハードリンクは切れ、同じ実体を指していた別名には反映しない。Windows でそのファイルだけに付けたアクセス権（ACL）と、Linux の所有者・拡張属性は、引き継がれないことがある
- 取り込んだ include 先・JSON から作った表・入れ子の表・対応を確かめられない表は編集できない。UTF-8 でないファイル・単独の CR で行の対応がずれる文書・16 MiB を超える文書も対象外
- セル用 Markdown を同じ描画に書き戻せない内容、壊れた HTML の原文、表の外へはみ出す貼り付けなどは書かず、理由を知らせる。ファイルを外で変えた場合も上書きしない
- 取り消しの履歴は文書ごとに200手・全体で32 MiBまで。プレビューを終了すると失われる。外で変わったファイルには古い履歴を適用しない

- セルを選んだときの画面下の操作欄は「行」「列」「セル」「表」「原文を編集」「元に戻す」「やり直し」。HTML の表だけ「原文を編集」を使える。Neovim のバッファでは「元に戻す」「やり直し」を出さず、Neovim の `u` で戻す
- 「表」の「表全体の原文を編集」は、原文の範囲を確かめられる、いちばん外側のパイプの表だけに使える。HTML の表・引用やリストの中の表・取り込んだ表・front matter・JSON からできた表・入れ子の表などは無効で、メニューで選ぶと理由が出る
- 入力欄には見出し・区切り・本文の行が入り、行と列の数も変えられる。Ctrl+Enter（macOS は Cmd+Enter も）か入力欄の外のクリックで確定し、Esc でその対象の下書きも取り消す。編集モードを出たときなどの下書きは、同じ原文を開き直すと戻る。前後の空行は取り除き、改行（LF・CRLF）と BOM は保つ
- 確定できるのは、前後の段落を含まないパイプの表 1 個だけ。表でなくなる・2 つの表に分かれる・前後の段落を巻き込む入力は断り、入力を残す。脚注の参照を足すなど、表の外の描画が変わる場合も、「表全体の原文を変えると、表の外の描画も変わります。」と知らせて書かない
- 表の直後に空行なしで続く文の行は、GFM では表の行になるため、取得する原文にも含まれる。入力欄でも、表の行に空行なしで続けて書いた文は表の行として扱う。別の段落は表全体の入力欄には含めず、ブロックの追加などで表の外に空行で区切って書く
- 表全体の原文の変更は「元に戻す」で 1 手として戻せる。Neovim にはバッファの 1 個の行の置き換えとして届き、保存は `:w`、取り消しは `u` で行う
- 「表」の「HTML の表にする」「パイプの表にする」は、セルの文字・見出し・揃えを保って種類を変える。`[ ]`・`[x]`・`[X]`・`[~]` だけのセルがあると、チェックボックスの描画が変わるので断る。内容の続く先頭の `<br>`、3 つ以上続く `<br>`、HTML のブロックを含むセル、リンクの参照の定義など、変換で解釈が変わる場合も理由を出して断る。HTML のブロックは、唯一のブロックが 1 行で、タグの外に Markdown の字句や記号が無い場合だけ変えられる

- ボタンは外側の種類に合わせて「リスト全体を編集」「引用全体を編集」「説明リスト全体を編集」「注記全体を編集」「項目全体を編集」「説明全体を編集」「HTML のブロック全体を編集」、ほかは「外側のブロックを編集」と出る
- 「内側に戻る」か Alt+↓ で、移る前の内側のブロックへ戻る。移るときは入力途中の文字を確定せずに残し、戻ると入力欄に出す。IME の変換中は移らない
- ブロックの原文を開くと、入力欄のそばの操作欄に「前に追加」「後ろに追加」が出る。押すと、編集中の入力は確定せず下書きに残り、空の入力欄が開く。右下の札は「追加」になる
- 追加の入力欄は、いちばん外側のブロックの上か下に出る。リストの項目ならリスト全体、引用の中の段落なら引用全体の前後に追加する
- 生の HTML のブロック全体を開いているときは、その全体の前後に追加する。中の段落などを開いているときは、生の HTML の中で、その対象の前後に追加する
- 追加は Ctrl+Enter（macOS は Cmd+Enter も）で確定し、Esc で取り消す。入力欄の外をクリックすると、文字があれば確定し、無ければ取り消す。追加中は、外側・内側へ移るボタンと Alt+↑・Alt+↓ は使えない
- 追加する文の前後の空行は除き、前後のブロックとの間に空行を 1 行ずつ置く。既に空行があれば足さず、文書の先頭・末尾の側にも足さない。改行（LF・CRLF）はその場所に合わせる
- 追加した文が前後のブロックに取り込まれたり、前後を巻き込んだりする場合は、「追加した文が前後のブロックに取り込まれます。」と知らせ、書き込まず入力を残す
- 後ろに内容がある所へ閉じていないコードの囲み（` ``` ` だけ）・`>>>`・`<details>` を足すと断られる。リストのすぐ後ろへの字下げした文や項目（`- b`）の追加も断られる。リストに項目を足すときは、リスト全体を開いて書き足す
- 文書の最後の生の HTML のブロックの前に、閉じない要素（`<div>` だけ、など）を足して既存のブロックを取り込む場合も断られる
- 空白だけの追加は、「追加する文を入力してください。」と知らせて断る
- 操作欄の「追加」から、文書の先頭・末尾にも追加できる。先頭は front matter の後ろになる。空白と空行だけの文書では「追加」の代わりに「最初のブロックを書く」が出て、入力した文で全体を置き換える。参照の定義やコメントだけの文書は空とは扱わない
- 文書の末尾が閉じていない `<!--`・`<details>`・コードの囲みなどで、追加した文がその中に取り込まれる場合は断る
- 表のセルを選び、画面の下の「表」か右クリックの「表 ▸」から、表の前後への追加を選べる。表の操作ができる最上位の表だけが対象。リスト・引用の中、入れ子、HTML の表の最初と最後の行に表以外の文字がある場合などは、理由を出して断る
- 追加の入力欄の「注記…」で「メモ（note）」「ヒント（tip）」「重要（important）」「警告（warning）」「注意（caution）」を選んで「入れる」を押す。`> [!note]` などの種類の行と、本文用の `> ` が入る
- 「コード…」で `sh`・`bash`・`powershell` を選んで「入れる」を押す。言語名の付いたバッククォート 3 つの囲みと空の本文の行が入る。「折りたたみ」は `<details>`・`<summary>題</summary>`・本文・閉じタグの定型をすぐに入れる
- 注記・コード・折りたたみの定型は、入力欄のカーソルの位置（文字を選んでいればその範囲）へ入れ、前後に必要な空行を補う。入力欄で直してから Ctrl+Enter で追加を確定する。「閉じる」か Esc は種類や言語を選ぶ欄だけを閉じる。確定では通常の追加と同じ検査を通し、周りの表示が変わる場合などは書かず理由を知らせる
- 追加欄の定型は、実際の IME、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「コードと見出しのリンクのコピー・折りたたみ・画像の拡大・依頼文の形・要確認の一括・追加欄の定型と、版 0.19.0 の配布の検証（2026-11-14）」にある
- 追加の入力欄の「表を入れる…」で、列を 1〜20、本文の行を 1〜100 から選び、「入れる」を押す。見出しが「列1」・「列2」…の空のパイプの表が、入力欄のカーソルの位置（文字を選んでいればその範囲）に入る。入力欄で内容を直してから、Ctrl+Enter で追加を確定する。「閉じる」か Esc は大きさを選ぶ欄だけを閉じる
- セルの原文の入力欄と脚注の定義には「前に追加」「後ろに追加」のボタンが出ない。include 先・front matter、範囲を確かめられないいちばん外側のブロック、生の HTML に `data-sourcepos` を書いた要素からも追加できない
- ファイルを編集しているときは、追加も「元に戻す」「やり直し」で 1 手として戻せる。Neovim にはバッファの 1 個の行の置き換えとして届き、`u` で戻せる
- 空行なしの説明リストの用語は、描画エンジンの位置を編集の側で正して開く
- `>>>` の引用の中の最後の項目など、範囲を確かめられないブロックを押すと、開ける外側のブロックを開いて知らせる。外側もなければ、理由を知らせて開かない
- 生の HTML に `data-sourcepos`・`data-checkbox-sourcepos` を書いた要素は、描画エンジンが付けた位置と区別できないので編集できない。同じ要素名・同じ位置を持つ本物の要素も編集できなくなる
- 脚注の定義の中を押すと、ラベル `[^1]:` を含む定義全体を開き、「ラベルを変えると、本文の参照と対応しなくなります」と知らせる
- 脚注のラベルを変えて確定すると、置き換えた上で「脚注のラベルが変わりました。本文の参照を確かめてください。」と知らせる。脚注の中の段落だけは編集できない
- 編集モードの間は、原文を直せる所のリンクを押しても移動しない。PlantUML の図のクリックで SVG を開く操作と、Neovim のエディタの行へ移る操作も止め、図のダブルクリックで原文を開く。リンクで移るときは、「編集」をもう一度押して編集モードを出る
- Ctrl などを押しながらのリンクのクリックは止めないので、新しいタブで開ける
- 目次・include 先・front matter は画面から編集できない。リスト・引用などの中の生の HTML だけを開くこともできない
- 表の操作ができる表のセル（生の HTML の表と、パイプの表の `| [ ] |`）と脚注の定義の中も、タスクをクリックかフォーカス中の Space で切り替えられる。JSON の表・入れ子の表・対応できない表・include で取り込んだ表の中は無効のまま。「表を固定」の「セルを選んで固定」の最中は、チェックを切り替えず固定の境界を選ぶ
- 表と脚注の中の数式と図は、それだけを開いて編集できない。脚注の定義は、ラベルを含む全体を開く
- 原文の取得や書き込みを断ったときは、理由を知らせる。Ctrl・Shift・Alt を押しながらのダブルクリックでは、編集を始めない

### Windows 11 の mdpreview のプレビューでコメントを付けて、VS Code の Agents Window へ送る

- 本文にコメントをため、計画か直接の修正を頼む形を選んだ依頼文をコピーして、文書のルートで開いた VS Code の Agents Window に貼って送る
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある。Agents Window を開くには、VS Code の `code` コマンドも PATH にあること。Copilot のセッションを使うときは、VS Code で Copilot にサインインしておく
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く

1. 管理者ではない PowerShell 7 を開く。

   - スタートメニューで「PowerShell」を探し、クリックして開く（「Windows PowerShell」ではない。「管理者として実行」にはしない）
   - 「PowerShell」が無ければ、[PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)を入れる

1. コメントを付ける Markdown のパスを入力し、プレビューを起こす。パスは引用符を付けずに入力する。

   ```powershell
   & {
     # コメントを付ける文書を選び、コメントを有効にして開く
     $reviewFile = Read-Host 'Markdown のパス'
     "`n$([char]27)[7m 確認 $([char]27)[0m"
     mdpreview --review $reviewFile
   }
   ```

   - ブラウザで文書が開き、操作欄に「コメント」が出ればよい
   - エラーが出たら、中断して文書のパスと [導入の手順](install.md#windows-11-で-md-preview-を導入更新する)で導入状態を確かめる

1. 操作欄の「コメント」を押す。

   - 右にコメントの欄が出ればよい。狭い画面では下に出る

1. 本文のブロックか表のセルを押す。文字を引用したいときは、1 つの対象の中で文字を選ぶ。

   - 欄に選んだ対象が出ればよい。文字も選んだ場合は「選んだ文字」に出る
   - 節全体に付けるときは、本文のいちばん外側の見出しを選び、「節全体へのコメントにする」にチェックを入れる。「節: …」と出ればよい。チェックを外すと見出しだけが対象になる
   - コメントを付けられない所は、理由の知らせを確かめ、対象を選び直す

1. 欄にコメントを書き、「追加」を押す。Ctrl+Enter でも追加できる。

   - コメントのカードが「未コピー」で出ればよい。節全体を選んだ場合は、カードの題が「節: …」になる
   - この項の手順 4〜5 を、必要なコメントの数だけ繰り返す
   - コメントを持ち出すときは「書き出す」を押し、「コメントを書き出してコピーしました。」が出ることを確かめる。このページの外の文字を入力できる所に Ctrl+V で貼り、コメントの JSON が出ることを確かめる
   - 書き出したコメントを足すときは、JSON をコピーしてから、同じ文書のコメント欄で「読み込む」を押す。「書き出したコメントの JSON を貼り付けてください」の欄に Ctrl+V で貼り、「足す」を押す。追加した件数と、重なりで足さなかった件数の知らせを読む。同じカードがある文書へそのまま読み込むと、追加は 0 件で重なりになる。足したカードがあれば「未コピー」で出ることを確かめる

1. 「依頼文の形」で「/plan で計画」「日本語で計画」「直接直す」を選び、「依頼文を作る」を押す。対象のファイル・行・原文と、コメントを確かめる。

   - ページを開いたときは「/plan で計画」が選ばれている。その形では先頭が `/plan` で、まず計画だけを示す依頼文が出ればよい。ほかの形の先頭は、この項の補足で確かめる
   - 「要確認」の件数が出たら、該当するカードの「直す」を押し、本文で対象を選び直して「保存（対象を変える）」を押す。同じ位置の内容を確かめ直す場合は「保存」と出る。今回の依頼に含めないときは「今回は送らない」を押す。「今回は送る」で戻せる
   - 要確認をまとめて今回の依頼から外すときは「要確認をまとめて送らない」を押す。「まとめて送らないを戻す」で、そのボタンで付けた印だけを戻せる
   - 「誤り」のカードがあれば、それぞれの理由を読み、対象やコメントを直して作り直す。表の情報を読み込んでいる知らせが出たら、少し待って押し直す

1. 「コピーして Agents Window を開く」を押す。

   - 依頼文がコピーされ、文書のルートで VS Code の Agents Window が開けばよい
   - Agents Window が前のフォルダーのまま開くことがある。新しいフォルダーの信頼の確認が出たら、フォルダーと内容を確かめて「Trust Folder & Continue」を押す。確認を進めた後に文書のフォルダーへ切り替わるので、開いたフォルダーを確かめる

1. Agents Window の「Show Session Options」を開き、セッションの種類を Copilot か Claude、作業場所を Branch にする。

   - セッションの種類は、既定が Codex のことがある。Copilot へ送るときは Copilot を選ぶ（Claude のセッションへの送付は未検証）
   - 開いたフォルダーがプレビューのルートであることを確かめる
   - Git の文書では、Branch は今のフォルダーを直接直す。New Worktree は別の worktree で直す

1. Agents Window の入力欄に Ctrl+V で依頼文を貼り、内容を確かめて Enter で送る。

   - 選んだ形の依頼文をそのまま貼る。「/plan で計画」では `/plan` を含める。Agents Window のエージェントの一覧から Plan を探す操作は要らない
   - 「/plan で計画」を選んだ場合、Copilot では `/plan` がスラッシュコマンドとして扱われ、「Review Plan」と「Implement / Reject」が出ることを確かめる。承認するまでファイルを変えないことも確かめる

1. 「/plan で計画」「日本語で計画」では、返ってきた計画を確かめ、直す範囲と内容がよければ実装を承認する。「直接直す」では、計画の承認を待たずに直す依頼になる。

   - 実装後に、直した内容と差分を確かめる
   - Branch でプレビューと同じファイルが保存されると、直した結果がプレビューに出ることを確かめる

1. 終わったら、プレビューを起こした端末で Ctrl+C を押して止める。

   - コマンドの入力に戻ればよい

- ファイルを渡したときのルートは、上へたどって最初に `.git` があるフォルダー。無ければ、そのファイルのあるフォルダー。`--root <フォルダー>` で変えられる。Agents Window もこのルートで開く。Neovim では、名前のあるファイルで依頼文を作ったときのルート（その文書を含む Git のリポジトリのルート、無ければ文書のフォルダー）で開く

- 段落・見出し・リスト・引用・コード・数式のブロック・図・水平線・注記・脚注の定義と、最上位の生の HTML の連なり、表のセルが対象になる。「表を固定」で固定・全幅表示にした表のセルにも付けられる

- 「節全体へのコメントにする」は、本文のいちばん外側の見出しを選んだときだけ出る。既定はチェックなしで、本文で対象を選び直すと外れる。節は選んだ見出しから、子の節を含め、次の同じか上のレベルの見出しの手前まで（無ければ文書の末尾まで）。依頼文の種類は「節」で、行と原文も節全体になる
- 節の先頭にできるのは、原文と対応づけた最上位の Markdown の見出しだけ。include の指定や取り込んだ行を含む節、front matter の中の見出し、引用・リスト・HTML の中などの見出しによって境があいまいになる節は送れない。カードを追加できても依頼文の作成で断る場合があるので、「誤り」の理由を確かめる

- カードの「直す」でコメントや対象を直し、「消す」でそのカードを消し、「本文へ移る」で対象を表示する。「未コピー」はまだ依頼文をコピーしていないコメント、「コピー済み」はコピーしたコメント。「誤り」は依頼文を作るときに断られた対象それぞれの理由を示す
- 「要確認」は対象が消えた・内容が変わった・対応を一つに決められない・表を確かめられなくなったもの。位置が同じでも内容が違えば要確認にし、元に戻して同じ対象の内容が戻れば外す
- `--edit --review` の画面での編集と「元に戻す」「やり直し」の後は、位置と内容を確かめて、内容の変わらないブロック・生の HTML の連なり・表のセル・節へコメントを追従させる。表の開始位置や同じ内容の候補を一つに決められない場合は要確認にする。外のエディターやファイルの変更では、別の位置へ移さない
- 節へのコメントは、画面の節の移動や節ごとの見出しのレベル変更でも、節全体の内容が一致し、候補が一つなら付いてくる。子の見出しだけのレベル変更や本文の変更は要確認になる。脚注の定義は、表示される場所ではなく原文の開始行がある節に含める。コードの外の空白はまとめて比べるが、コードの中の改行と字下げは区別する
- 今回送るコメントに要確認があると依頼文を作らず、件数を知らせる。「直す」で対象を選び直すか、「今回は送らない」で外す。「今回は送る」で戻せ、コメント自体は消えない。除外の印は依頼文をコピーすると外れる。表の情報の読み込みが揃う前も依頼文を作らず、待つよう知らせる
- 「要確認をまとめて送らない」は、未コピーで今回送る対象になっている要確認だけに「今回は送らない」の印を付ける。「まとめて送らないを戻す」はその操作で付けた分だけを戻し、もともと付いていた印と、手で付け直した印は戻さない
- 一括で戻す記録は保存しない。依頼文のコピー成功で記録を全部捨て、カードを直して保存・削除したときはそのカードの記録を外す。文書の切り替えと再読み込みでも記録は失われる
- 「依頼文を作る」は「今回は送らない」を除く未コピーのコメントをまとめる。「コピー済みを消す」はコピー済みのカードを消す。コピー済みは、エージェントへ送ったことや実装が済んだことを示さない
- コメントは文書ごとに、そのタブの sessionStorage に版 2 の形で保存する。Neovim ではバッファの文書ごとに分け、バッファを移ると前の文書のコメントを保存して次の文書の分を読み戻す。対象の位置・内容の指紋・文書の版と、コメント・コピーの状態・要確認・今回送らない印などを保存する。同じタブの再読み込みでは読み戻すが、編集の前後を追う記録は消え、保存した位置と内容で確かめ直す。永続的な保存や別のタブとの自動の共有には使わない
- 「書き出す」は、今の文書のコメントをコピー済み・要確認・今回送らない分も含めて JSON にしてクリップボードへコピーする。コメントのコピーの状態は変えず、ファイルへは書かない。JSON には形式の名前と版・文書の相対パス、対象・題・コメント・選んだ文字・内容の指紋・セルの照合用の鍵を入れる。サーバーの token・端末の絶対パス・URL を自動で入れず、依頼文・起動ごとの版・コピーや要確認などの状態も持ち出さない。コメントなどに自分で書いた文字はそのまま入る
- 文書は描画のルートからの相対パスで見分け、別の文書のコメントは足さない。今あるカードを残して足し、同じ対象で同じコメントの文は、選んだ文字が違っていても重なりとして足さない。読み込んだカードはすべて未コピーになり、今回送らない印を外し、今の位置と内容の指紋を確かめ直す。対象が無い・内容が合わない場合は要確認になる。別の位置は探さない
- 読み込む JSON は UTF-8 で 4 MiB、項目は 200 件まで。足した後の合計も保存 200 件・未コピー 50 件までにする。型・値・余分な項目名など、1 つでも形が違う場合や上限を超える場合は何も足さない。「読み込む」の貼る欄は「やめる」か Esc で閉じ、貼った文字を捨てる。描画が届く前や依頼文の作成中・コピー中・停止後は持ち出しを使えない
- 節へのコメントと持ち出しは、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、実際の IME、タッチの端末では未検証。書き出した JSON を別の PC やブラウザーへ移す操作も未検証

- 行は 1 から数え、終わりの行も含む。include の展開前の原文を、front matter の行も含めて数える。ファイルが外で変わったときは、最新の表示と要確認のカードを確かめて依頼文を作り直す

### Windows 11 の mdpreview で Markdown を HTML に書き出す

- 試験用の Markdown を HTML に書き出し、ブラウザで開く
- 前提: [Windows 11 で md-preview を導入・更新する](install.md#windows-11-で-md-preview-を導入更新する)を通し、`mdpreview` が PATH にある
- 実行場所: この PC のデスクトップの管理者ではない PowerShell 7。この項の手順 1 で開く
- PowerShell のリダイレクトで HTML を保存せず、`-o` で書き出し先を指定する

1. 管理者ではない PowerShell 7 を開く。

   - スタートメニューで「PowerShell」を探し、クリックして開く（「Windows PowerShell」ではない。「管理者として実行」にはしない）
   - 「PowerShell」が無ければ、[PowerShell 7](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)を入れる

1. 試験用の Markdown を作り、HTML に書き出す。

   ```powershell
   # 試験用の Markdown を HTML に書き出す
   $previewDirectory = Join-Path ([IO.Path]::GetTempPath()) ("md-preview-" + [guid]::NewGuid())
   & {
     New-Item -ItemType Directory -Path $previewDirectory -ErrorAction Stop | Out-Null
     [IO.File]::WriteAllBytes("$previewDirectory\image.png", [Convert]::FromBase64String('iVBORw0KGgoAAAANSUhEUgAAACAAAAAgCAIAAAD8GO2jAAAAK0lEQVR4nGNQLd1AU8QwasGoBaMWjFowasGoBaMWjFowasGoBaMWlA4RCwA0/ihM7D1ZAgAAAABJRU5ErkJggg=='))
     Set-Content -LiteralPath "$previewDirectory\preview.md" -Value "# 書き出しの確認`n`n本文です。`n`n![埋め込みの確認](image.png)" -Encoding utf8 -ErrorAction Stop
     mdpreview render --embed-images -o "$previewDirectory\preview.html" "$previewDirectory\preview.md"
     if ($LASTEXITCODE -ne 0) { return }
     "`n$([char]27)[7m 確認 $([char]27)[0m"
     Get-Item -LiteralPath "$previewDirectory\preview.html" | Format-List FullName, Length
   }
   ```

   - `preview.html` のパスと、0 より大きい大きさが出ればよい
   - 表示されたファイルのパスを、この項の手順 3 で使う
   - エラーが出たら、中断して入力ファイルと書き出し先を確かめる

1. ブラウザで、書き出した HTML を開く。

   - Ctrl+O を押し、この項の手順 2 で確かめたファイルを開く
   - 本文に「書き出しの確認」と「本文です。」、青い四角の画像が出ればよい
   - ブラウザでページのソースを表示し、本文の画像の `src` が `data:image/png;base64,` で始まればよい。試験用の文書の `image.png` を埋め込めたことを、この値でも確かめる

1. 試験用のフォルダーを消す。

   ```powershell
   # この項の手順 2 で作った試験用のフォルダーを消す
   if ($previewDirectory) { Remove-Item -LiteralPath $previewDirectory -Recurse; $previewDirectory = $null }
   ```

   - 何も出なければよい
   - この項の手順 2 と同じ PowerShell 7 の窓で行う（別の窓では、消すフォルダーが分からない）

<details id="windows-11-の-mdpreview-で-markdown-を-html-に書き出す-の補足と注意点">
  <summary>Windows 11 の mdpreview で Markdown を HTML に書き出す の補足と注意点</summary>

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)のリード**

- PowerShell の版によっては、パイプやリダイレクトが文字コードや改行を変える。`-o` ならアプリが UTF-8 の HTML を直接書く

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)の手順 2**

- 自分の文書を使う形は `mdpreview render -o preview.html README.md`。`-o` を省くと標準出力に HTML を書く。書き出し先のフォルダーは先に用意する
- 知らせがあれば、標準エラーに種類ごとの件数を出す。例は `mdpreview: 参照: 2 件`、`mdpreview: 見つからないメディア: 1 件`。ほかの種類の名前は「図」「提案」「取り込み」「絵文字」と、件数が多くて省いた分の「省略した知らせ」
- `--theme system|light|dark` で配色、`--width fluid|fixed` で本文幅を選ぶ。既定は `system`（OS に従う）と `fluid`（全幅）
- `system` の暗い配色は画面だけに使い、印刷は明るい配色にする
- `--root <フォルダー>` でルートを指定できる。省略したときのルートの決め方はプレビューと同じ
- 試験用の `image.png` は、コマンドに書いたデータから作る 32×32 px の画像。`--embed-images` を付けると、ルート内の PNG・JPEG・GIF・WebP を data URL にして HTML に埋め込む。自分の文書を使う形は `mdpreview render --embed-images -o preview.html README.md`
- 埋める画像は拡張子と先頭のバイト列の両方で種類を確かめ、1 枚 8 MiB・合計 32 MiB までにする。同じ実ファイルは合計へ 1 回だけ数える。画像の内容全体をデコードして検査するものではない
- SVG・対応外の種類・拡張子と種類の食い違い・外部 URL・ルートの外・見つからない画像・読み取れない画像・上限を超えた画像は埋めず、通常の URL の扱いで残す。理由ごとの件数を `画像を埋め込みませんでした（N 件）: <理由>` の形で標準エラーへ知らせる。画像の警告だけでは終了コードを失敗にしない
- 本文にもともとある `data:` の画像はそのままにし、警告もしない。埋め込みの処理は外部 URL を取得せず、外へ通信しない。詳しい順序と上限は [画像の埋め込み](reference/readme.md#画像の埋め込み)にある
- `--embed-images` を付けないと、画像は埋め込まない。動画・音声と埋めなかった画像・リンクは、ルート内の相対パスを書き出し先から見た形に直す
- 書き出し先がルートの外のときは、相対パスを文書のフォルダーから見た形のままにし、そのことを標準エラーに知らせる（書き出し先から見た形にすると、ルートより上のフォルダーの名前が HTML に入るため）。リンクと画像を合わせるには、ルートの中へ書き出す
- 入力の Markdown と同じファイルは、書き出し先にできない
- 別の Markdown へのリンクもファイルへのリンクとして残る。リンク先の HTML をまとめて作る機能はない
- 公式スタイルを導入していても、書き出しには同梱のスタイルを使う。必要な KaTeX・mermaid と数式のフォント、コードのコピーのボタンがあるときはそのスクリプトも埋め込む。数式・mermaid・コードのコピーのどれも無ければスクリプトを入れない
- mermaid の図があると、ライブラリを埋め込むため HTML が大きくなる。数式と図を含む文書を書き出した例では約 6.2 MB

**[Windows 11 の mdpreview で Markdown を HTML に書き出す](#windows-11-の-mdpreview-で-markdown-を-html-に書き出す)の手順 3**

- サーバーを起こさず、`file://` から開く。埋めた画像は HTML だけで表示する。埋めなかったメディアを別の場所へ移すときは、HTML との相対パスの関係を保つ
- 画像を埋めた HTML の表示は、AlmaLinux 10 の実機、Edge 以外のブラウザー、スクリーンリーダー、タッチの端末では未検証
- この版の検証記録は、`repos/md-tools/docs/verification/readme.md` の「リンク切れの点検・書き出しの画像の埋め込み・表の列ごとの絞り込みと、版 0.21.0 の配布の検証（2026-11-14）」にある
